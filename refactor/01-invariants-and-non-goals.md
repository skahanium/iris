# 01. 不变量与非目标

本文只定义长期不变量与明确非目标，不表达当前实现状态。代码事实和完成证据分别见附录 A、B；任何实现方案如果违反这些不变量，即使局部更“先进”，也不能进入主干。

## 1. 产品与数据边界

- Iris 仍是本地优先的 Markdown 笔记应用，不建设通用 Agent 平台、插件市场或任意代码执行环境。
- 用户的 `.md` 文件仍是笔记知识的最权威来源；SQLite 中的索引数据必须可由 Markdown 重建。
- AI 会话、网页缓存和收件箱等运行时状态可以保存在 SQLite，但不得反向成为笔记内容的隐式权威来源。
- 未经用户明确确认，不修改笔记正文，不把模型推断写成用户事实。
- `ROADMAP.md` 是版本排期和产品范围的唯一来源，本目录不承诺版本号或交付日期。

## 2. Run 生命周期与内容所有权不变量

- `client_request_id` 是 Run 幂等键：同 ID、同请求指纹的重放必须返回原 Run 且不得再次取得执行权；同 ID、不同指纹必须返回幂等冲突。新的 ID 即使文本相同也属于新请求。
- 普通会话同一时刻最多存在一个活动中的顶层 Run；子任务由父 Run 管理，不另造顶层竞争者。
- `Completed` 必须在最终助手消息和必要元数据成功持久化后才能成立。
- `AnswerComplete` 是持久化终态的外部投影，不能先于最终化成功发出。
- 用户拒绝有副作用的确认后，Run 终止为 `Cancelled(reason=user_rejected_change)`；本次不新增 `Rejected` 状态。
- 事件下发失败不能改写已经持久化的事实；前端通过快照或事件重放恢复。
- 助手正文、流式 reveal、过程事件和引用绑定必须带有同一个 Run 身份；任何正文都不能仅凭“当前消息行”归属。
- 接受新 Run 时必须立即建立空的本轮助手投影。上一 Run 的 reveal 缓冲、动画帧、消息正文或迟到事件不得成为新 Run 的回退值。
- 终态恢复只能读取该 Run 自己的持久化消息和事件，不得借用同会话上一条助手消息填充空内容。

## 3. 权限与隐私不变量

- Web 开关是受管 `web.search`、`web.fetch` 与 `web.domain.read` 检索的唯一用户授权来源；通用 `external.read` 仍需逐 Run 显式授权，路由器、领域分类或模型建议不能扩大任一权限。
- 工具必须经过统一、确定性的执行前门禁；目录展示、模型选择和运行时执行使用同一能力事实。
- 自动检索到的本地笔记内容不得进入 Web 搜索词、URL、日志或错误消息。
- API Key、Token、用户笔记正文和解密密码不得进入日志、遥测、模型可见错误或调试事件。
- 被标记为隔离或不可信的内容只能作为数据使用，不能取得更高优先级的指令地位。
- 领域服务商只允许复用经过审核的只读 MCP/联网边界；启用领域分类不等于自动信任任意第三方工具。

## 4. 当前事实与研究预算不变量

- 本机日期、时间、星期和时区优先来自可信运行时，不为证明本机事实而搜索网页。
- 日期、天气、新闻、金融、影视和体育等会变化的事实必须携带绝对时间语境；不得只把“近期”“现在”“今天”等相对词原样交给搜索或模型。
- 外部当前事实只能来自本 Run 的可用证据或已验证结构化工具输出；模型训练记忆、历史助手回答和旧 Run 来源不能补足缺口。
- 简单问题必须使用有界预算。证据充分后立即停止；达到搜索、抓取或修复上限后失败关闭，不允许继续无界思索。
- 多步研究只允许针对已识别的证据缺口继续搜索。后续查询不得扩大用户授权、泄露本地材料或无关改写问题。
- “搜索成功”不等于“证据充分”；结果数量、来源组存在和模型声称已联网都不能单独满足完成条件。
- 进入领域能力增强后，六类领域规则以附录 D 为准。规则无法验证所需字段、时效、地域、单位或来源时，只能说明不足，不得用语言润色掩盖缺失。

## 5. 证据不变量

- `session_evidence` 是 Web 证据事实的现有存储，不新增平行证据仓库。
- 精确引用只能绑定到当前 Run 实际使用且可定位的证据；历史缓存或同会话旧证据不能冒充本次依据。
- `SourceGroupFallback` 表示“本次检索得到的一组来源”，不证明某个句子得到其中某条来源支持。
- Direct、ToolLoop、恢复和降级路径必须遵守相同的绑定语义；fallback 不能作为严格当前事实的成功依据。
- 所有 Web 最终答案都必须显式携带引用绑定模式。缺失或不可解析时，UI 必须按来源组/未逐段核验处理，不能默认显示成精确来源。
- 严格当前事实的实体、数字、日期、地域、渠道、单位和数据时点必须绑定到结构化结果或可确定定位的本 Run 证据。
- 天气、金融等结构化工具应做确定性的字段、单位、时效和来源校验；自由文本的通用语义判断仍是远期实验，不能成为默认完成标准。

## 6. 上下文与最小记忆不变量

- 当前 Run 的决策上下文由已提交消息、Run 事件、证据和冻结的 intake 结果投影得到，不新增 `session_situation` 一类第二真相表。
- 已有 `conversation_summaries` 用于上下文超限后的会话压缩；摘要是派生数据，必须可失效、可重建，且不能覆盖原始消息。
- 允许的跨会话记忆仅限用户明确确认的少量偏好，例如常用地点；必须可查看、可修改、可清除并带作用域。
- 常用地点只能来自本轮用户明确输入或经确认记忆；不得通过 IP、网络端点、笔记正文或模型猜测推断。
- 未确认的模型推断、Web 内容和本地检索片段不得自动晋升为长期记忆。

## 7. 明确非目标

以下内容不进入当前增量主干：

- 跨会话向量化“语义记忆管理中心”；
- 依赖 LLM judge 的默认自由文本事实校验；
- 通用浏览器自动化、登录态网页操作和表单提交 Agent；
- 六类当前事实之外的购物、旅行、医疗诊断、法律判断等大规模垂直扩展；
- 个性化投资买卖建议、自动交易或将描述性金融分析包装成投资结论；
- 第三方工具市场、动态插件协议或任意代码执行；
- 为未来设想预建新的路由状态机、长期任务系统或多 Agent 编排平台。

时间、天气、新闻、金融、影视和体育的最小只读能力属于核心缺陷收口后的能力增强，不是修复旧时效链路或跨 Run 投影的前置条件。每个领域只能通过附录 D 已定义的稳定操作和验证规则进入主干，不得借此演变成“万能数据层”。
