# 03. 可靠性契约

本文把重构要求写成可实现、可测试的契约。具体类型名可以调整，但不得削弱行为约束。

## 1. Run 接受与幂等契约

### 接受

对 `(conversation_id, client_request_id)` 的接受必须是原子的，并返回：

```text
accepted: 已存在或新建的 Run 标识
is_new: 本次调用是否首次取得执行权
```

- `is_new=true`：调用方可以启动执行器。
- `is_new=false`：调用方只能返回已有 Run，不得再次 spawn。
- 两个并发请求只能有一个取得 `is_new=true`。
- 普通会话已有活动顶层 Run 时，新请求返回 `agent_run_active_run_exists`；不能静默并行。

### 重试

- 对同一 retry token / request id 的重复重试保持幂等。
- 重试必须记录与原 Run 的关系，但不能复制旧 Run 的未提交副作用。
- 崩溃恢复后再次提交同一请求，仍服从相同的唯一执行权判断。

## 2. 最终化与事件契约

成功路径严格遵循以下顺序：

1. 收集并校验本次输出、工具结果和证据绑定；
2. 在同一可恢复边界内持久化最终助手消息及引用元数据；
3. 持久化 Run 的 `Completed` 终态；
4. 发出 `AnswerComplete` 和最终 UI 投影。

任一步失败时：

- 不得发出虚假的完成事件；
- 已持久化的事实不得因事件 sink 失败而回滚成另一种语义；
- 前端重连后可从 Run 快照、消息和事件序列恢复到相同结果；
- 重放事件不得再次触发工具调用、写笔记或其他副作用。

用户拒绝变更确认时，终态为 `Cancelled`，reason 使用稳定机器码 `user_rejected_change`，展示文案由前端本地化。

## 3. Intake 与工具表面契约

Run 被接受时冻结以下输入：

- 用户请求和会话标识；
- Web 授权等用户设置快照；
- 模型能力与可用性；
- 确定性的请求分类结果；
- 本次可见工具表面及目录版本。

执行过程中设置变化默认只影响下一次 Run，除非属于立即撤销权限的安全操作。Executor 不重新推导一套不同路由结果。

现有 `ToolSurfacePlan` 及其已解析工具列表是本次 Run 关于“模型可见且可能执行”的唯一事实，并随 Run 冻结：

- `Planned` 工具不可见、不可 dispatch；
- `HarnessOnly` 只在明确的内部路径可见；
- `Dispatchable` 仍需通过用户授权、参数和确认门禁；
- `capabilities_read` 只能报告当前计划解析出的工具，不得把完整目录宣传成当前能力。

## 4. 工具执行门禁契约

所有工具调用在 dispatch 前依次经过同一门禁：

1. 工具存在且属于当前 surface；
2. 参数符合目录 schema，未知或无消费方的字段拒绝；
3. 当前用户授权允许所需能力；
4. 输入数据流满足隐私规则；
5. 需要用户确认的副作用已取得与参数摘要匹配的确认；
6. 运行时实现状态确实可 dispatch。

任何旁路调用也必须复用该门禁。目录元数据用于描述约束，门禁负责最终裁决；模型提示词不是安全边界。

错误必须返回稳定错误码与脱敏摘要，不包含密钥、笔记正文、完整网页正文或未经处理的工具参数。

## 5. Web 证据绑定契约

### 绑定模式

- `Exact`：回答片段可定位到当前 Run 的具体证据片段。
- `Normalized`：经确定性规范化后仍能建立具体证据对应关系，并记录规范化类型。
- `SourceGroupFallback`：只声明这些来源在本次检索中被获取，不声明逐句支持关系。

所有启用 Web 且产出来源的最终答案必须具有显式绑定模式。Direct、ToolLoop、恢复和降级路径遵守同一规则。

### Direct 路径

Direct 严格 Web 路径如果没有可证明的精确绑定，必须从当前 Run 的 `session_evidence` 生成 `SourceGroupFallback`。不得用 `None` 表示“可能有来源”。

### UI fail-safe

- `Exact`/`Normalized` 才能采用精确引用样式。
- `SourceGroupFallback` 显示“本次检索来源组”，并明确“不表示已逐段核验”。
- 绑定缺失、未知版本、反序列化失败或证据已失效时，也按 fallback/未逐段核验展示，并记录可诊断但不含正文的错误。
- 没有当前 Run 证据时，不显示来源列表，也不能回退到历史来源冒充本次依据。

### 校验

- 结构化工具的 VERIFIED 必须来自确定性规则，例如字段存在、单位一致、数据时间、来源标识和数值格式。
- 没有适用规则或规则失败时保持 `uncalibrated`，不得静默晋升。
- 自由文本语义支持判断只可作为影子实验，不参与默认成功条件、用户标签或合并门禁。

## 6. 上下文投影契约

`RunSituation` 是每次执行开始时构造的只读投影，至少包含：

- 当前请求与已提交的近期消息；
- 当前 Run 的冻结权限和工具表面；
- 当前 Run 已产生的事件、工具结果和证据摘要；
- 仅在超出上下文预算时使用的有效会话摘要。

投影不得把以下内容当成当前事实：未提交的 UI 草稿、旧 Run 的临时工具输出、过期摘要、第一条用户消息推断出的永久目标、未确认的长期记忆。

摘要必须带覆盖消息范围、生成时间/版本和失效判断。读取时必须重新核对覆盖范围内消息的顺序、内容哈希和数量；范围后的新消息不使旧摘要失效。摘要错误不能破坏原始消息；重新生成或在低于阈值时删除旧摘要是恢复手段。

## 7. 最小记忆契约

允许持久化的长期记忆仅限：

- 用户明确要求记住的偏好；
- 用户在确认界面接受的候选偏好；
- 有明确 scope、来源、更新时间和删除方式的短值。

数据库沿用 071 的 `(scope, key)` 唯一性；清除某 scope 不影响其他 scope。读取时只合并 global 与当前 vault，精确 key 和列表去重都以 vault 优先；没有活动 vault 时只读取 global，并设置严格数量和长度预算。

禁止自动写入 Web 内容、模型推断、敏感凭据、整段笔记或检索片段。本次不引入向量召回、冲突自动合并或跨会话人格建模。

## 8. 前端恢复契约

- UI 状态是持久化 Run/消息事实与可重放过程事件的投影，不是独立真相源。
- 重载或重连后，完成、失败、取消、等待确认和 capability degraded 均应恢复一致。
- 未知事件类型必须安全忽略或降级，不能导致整个会话无法打开。
- 诊断展示默认只包含工具名、阶段、稳定错误码和脱敏摘要。
