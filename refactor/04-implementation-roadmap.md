# 04. 实施路线图

本路线图按风险和依赖排序，不绑定版本号或日期。版本安排仍由 `ROADMAP.md` 决定。每个阶段都应单独可合并、可回滚，不等待“大重构”一次落地。

## 阶段 0：基线复核与测试钉住

目标：避免根据过期审计修复已经不存在的问题。

- 逐项复核附录 A 中的 Confirmed/Partial 问题。
- 为 P0/P1 问题先添加能在当前实现上失败的聚焦测试。
- 记录现有 48-case Agent capacity eval 结果，冻结场景 ID，不另造重复评测框架。
- 明确本阶段涉及的公共 IPC、数据库 migration 和 UI 兼容边界。

退出条件：每个进入施工的问题都有当前代码证据、稳定 ID 和至少一个目标测试。

### 阶段 0 兼容边界

- **公共 IPC**：本阶段只允许新增内部 `pub(crate)` 契约（如 `AcceptRunOutcome.is_new`、sink 的 terminal presentation 钩子），不改变既有 Tauri command 的参数名、类型或返回值；若后续必须改动 `assistant_run_*`，必须同步 `src/types/ipc.ts`、`src/lib/ipc.ts`、`src/types/ai.ts` 和 `docs/ipc-api-reference.md`。
- **数据库 migration**：本阶段不引入 schema 变更；若阶段 4 的 `(scope, key)` 唯一性或阶段 2/3 需要新列，必须走 `src-tauri/migrations/` 增量 up/down，禁止直接改表。
- **UI 兼容**：本阶段只增加 fail-safe 投影测试与现有组件的行为约束；不新增第二套来源/状态组件。`SourceGroupFallback` 文案必须与现有 `AssistantCitationFooter` 一致，未知事件类型继续安全忽略。
- **评测兼容**：继续使用 `docs/eval/agent-answer-capacity.md` 定义的 48-case 与 24-case smoke 场景 ID；不另建评测框架，不把 live pilot 未执行声明为已通过。

## 阶段 1：Run 与来源展示止血

目标：先消除重复执行、假完成和误导性来源展示。

- 保留 retry 的 `is_new` 信息，仅首次接受时 spawn 执行器。
- 增加普通会话顶层 Run 单航班测试。
- 调整最终化顺序，使 `AnswerComplete` 晚于消息和终态持久化。
- 为 Direct 严格 Web 路径生成 `SourceGroupFallback`。
- UI 对缺失/未知 binding 采用“本次检索来源、未逐段核验”的 fail-safe。
- 将已有 `capability_degraded` 展示接入生产事件流。

退出条件：并发 retry 只执行一次；最终持久化失败不出现完成；Direct 和 ToolLoop 的未校准来源展示一致；刷新后状态可恢复。

## 阶段 2：工具事实与授权收敛

目标：让模型可见能力、目录声明和实际执行一致。

- 完成现有 `ToolSurfacePlan` 的生产接入，并随每个 Run 冻结其已解析工具列表。
- 让 `capabilities_read` 只返回当前 surface。
- 把目录校验、权限、确认和 dispatch 收敛到单一执行前门禁。
- 修正 reasoning/subagent 等工具的错误权限映射。
- 删除没有生产用途的工具及参数，或明确保持内部不可见。
- 为目录补充确有执行用途的成本、输出和证据策略，不新增平行成熟度体系。
- 对工具输出做确定性尺寸限制和安全截断，保留可诊断摘要。

退出条件：模型无法调用未暴露工具；关闭 Web 后所有外部检索旁路都被拒绝；确认与实际参数摘要匹配；目录和执行器不存在同名不同义。

## 阶段 3：证据闭环与隐私门禁

目标：使“有来源”“精确引用”“已验证”三种说法各自有可复核含义。

- 统一 Direct、ToolLoop、降级和恢复路径的 citation binding 生成。
- 精确绑定只接受当前 Run、未失效且可定位的证据。
- 为已支持的结构化工具实现确定性 VERIFIED 规则；其他输出保持 uncalibrated。
- 将来源时间、原 Run、失效状态和安全摘录纳入绑定检查。
- 确保自动本地检索内容不会流入 Web 查询、URL、日志和错误。
- 来源排序没有可靠信号时不展示名次。

退出条件：所有 Web 最终答案都能解释其绑定模式；历史/失效证据不能晋升；结构化校验可复现；隐私负例全部通过。

## 阶段 4：上下文压缩与最小记忆

目标：在不建设语义记忆平台的前提下，稳定长会话和少量用户偏好。

- 将现有运行时上下文构造接入生产调用链，形成只读 `RunSituation`。
- 短会话直接使用已提交消息，超预算后才使用 `conversation_summaries`。
- 为摘要增加覆盖范围、失效和重建测试。
- 移除“首条用户消息永久作为目标”的兜底。
- 将 `ai_memories` 唯一性调整为 `(scope, key)`，补 migration、回滚和 scope 清理。
- 仅通过显式确认写入少量偏好，并限制注入数量和长度。

退出条件：摘要失效后不会污染新请求；原始消息始终可恢复；相同 key 可在不同 scope 共存；Web/模型推断不会自动成为长期记忆。

## 阶段停线规则

任一阶段出现以下情况时暂停后续扩展，先修复或回退：

- 同一请求出现重复副作用；
- UI 成功状态无法由数据库事实恢复；
- Web 关闭后仍发生外部请求；
- 来源组被展示为逐段精确引用；
- 新增状态表、目录或缓存成为第二真相源；
- 为通过测试而放宽隐私、确认或证据约束。

未来能力提案不与上述阶段并行进入主干，详见附录 C。
