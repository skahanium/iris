# 05. 评测与验收

本次重构的验收重点是确定性契约，而不是“回答看起来更聪明”。现有 Agent capacity eval 继续作为端到端能力基线；新增测试优先贴近具体缺口。

## 1. 测试分层

### 单元测试

覆盖纯规则与边界：

- Run 接受、retry 的 `is_new` 判定与状态转换；
- Tool surface 裁剪和目录 schema 校验；
- 权限、确认、数据流和实现状态门禁；
- citation binding 模式选择、失效判断和 UI 映射；
- 无已注册结构化规则时 VERIFIED 的 fail-closed 门；
- 摘要失效、记忆 scope 合并和注入预算。

### 组件/仓储集成测试

覆盖事务和持久化：

- 并发接受只创建一个执行权；
- 最终助手消息、绑定和 Run 终态的失败注入；
- 事件 sink 断开后的恢复与重放；
- 当前 Run 证据与历史、失效证据隔离；
- 既有 071 `(scope, key)` 唯一性上的作用域读取、删除与清理。

### 前后端契约测试

覆盖 IPC 和事件投影：

- `AnswerComplete` 不早于持久化完成；
- `capability_degraded`、等待确认、取消和失败可恢复；
- binding 缺失、未知和 fallback 的 UI 文案与样式；
- 未知事件类型不破坏会话加载；
- 公共 IPC 若保持不变，应有兼容性测试证明。

### Agent capacity eval

复用现有 48-case 基线，不另建重复套件。它用于发现整体能力回退，不能替代上述确定性契约测试。场景失败必须定位到稳定问题 ID；新增场景只有在现有层级无法覆盖真实风险时才加入。

## 2. 必验场景

### Run 与恢复

1. 两个并发 retry 使用同一请求标识，只启动一次工具执行。
2. 最终消息写入失败，不发出 `AnswerComplete`，Run 不显示成功。
3. 终态写入后事件 sink 断开，刷新可恢复完成结果且不重做副作用。
4. 用户拒绝写入确认，Run 为 `Cancelled(user_rejected_change)`，不会写笔记。

### 工具与授权

1. `Planned` 工具不出现在 surface、capabilities 或 dispatch 中。
2. Web 关闭时，Direct、ToolLoop、恢复和旁路调用均不能外发请求。
3. 模型伪造工具名或额外参数时，门禁确定性拒绝。
4. 确认后参数发生变化时，旧确认不可复用。
5. `capabilities_read` 只报告本次 Run 可用能力。

### 证据与 UI

1. ToolLoop 未校准回答显示 `SourceGroupFallback`。
2. Direct 严格 Web 未形成精确绑定时同样生成 fallback。
3. binding 缺失或版本未知时，UI 显示“本次检索来源组/不表示已逐段核验”。
4. 历史 Run、失效证据或无定位信息的证据不能成为 Exact。
5. 无结构化验证规则的输出不会显示 VERIFIED。
6. 没有本次 Run 证据时不借用旧来源。

### 隐私与上下文

1. 恶意笔记文本不能进入 Web 查询、URL、日志或工具错误。
2. 网页中的提示注入只作为不可信内容，不改变系统权限。
3. 第一条用户消息不会在后续无关请求中被固定为当前目标。
4. 摘要覆盖范围内消息变化后立即失效；范围外新增消息不使旧摘要失效，并进入近期窗口。
5. 相同 memory key 在不同 scope 共存；清除一个 scope 不影响另一个。
6. Web 内容和模型猜测不能未经确认写入长期记忆。

## 3. 完成证据

每个已修复问题至少保留以下证据：

- 对应问题 ID；
- 修复前可失败、修复后通过的测试；
- 若涉及状态或 UI，包含恢复/刷新路径测试；
- 若涉及安全或隐私，包含一个拒绝型负例；
- 必要时更新 IPC 类型、migration up/down 或用户可见文案。

开发中只运行与当前改动相关的测试。阶段合并前运行受影响模块的 lint、格式、类型和测试；发布门禁再按项目规范运行完整检查。不得用手工体验替代可自动验证的核心契约。

## 4. 不作为默认完成条件的内容

- LLM 对自由文本“是否被来源支持”的主观评分；
- 跨模型输出风格一致或回答质量的笼统偏好；
- 跨会话语义记忆的召回率；
- 尚未进入产品范围的浏览器、垂直数据或第三方工具能力。

这些可做影子实验或人工评估，但不能阻塞本次可靠性重构，也不能给用户展示确定性 VERIFIED 标签。

## 5. 人工试用边界

真实 API、真实网页或真实用户笔记的试用只有在用户明确授权后执行。默认评测使用脱敏夹具、固定响应和故障注入，避免产生费用、隐私外发和不可复现结果。
