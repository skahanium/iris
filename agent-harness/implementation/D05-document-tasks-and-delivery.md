# D05 贯通文档任务与最终交付

本工作包依据 [Agent 架构定义](../../docs/agent-architecture.md) §10.3 的 **D4 贯通文档任务与最终交付** 依赖单元建立，主要承接对象是 `C05`／`C06`、`C23`–`C25`，责任对象登记为 `C23`。它登记施工依据、证据要求与回退条件，**不是工期、版本或发布承诺**，也不沿用已归档体系的阶段完成度。

| `D03` 收清会话、权限与上下文   | 完成并留下选区绑定、冻结确认与上下文覆盖证据（`D03` 的定义见 [D03](./D03-session-permission-context.md)） |

**本波执行事实（2026-09-21 第一波，不关闭）**

- **已落地（本波接线，不造轮子）**：`WebDecisionReason::LocalTransformation` 与 `is_local_transformation_request` 原先只用于 vault 工具面；现已接到 `ExclusionClassifier::resolve`。`instruction：body` 剥离后仍用未剥离全文判定显式核实／高风险，避免「翻译：请核实 https://…」被当成纯变换。`web.search` 仍只在 `web_enabled && freshness != Offline` 时进入信封。Durable Apply 派发前把 checkpoint 写成 `Dispatching`。
- **本波做**：纯润色／格式整理在联网开关打开时也不进入 `web.search`（Q14 触发面；词表含「格式整理」等同义，不含裸「规范化」以免误伤知识问句）；「Summarize the latest breaking news」这类时效题仍给 `web.search`。`Dispatching` 先核验磁盘哈希：已是 `expected_post` 则跳过写入、仍是 base 则派发一次、两者都不是则失败关闭且不重放后缀。前缀已落地时跳过并只派发后缀。恢复把 `Dispatching` 前缀已写入判为可续跑，不得把 `Dispatching` 直接加成 `Applied`；磁盘不再匹配计划终点则该 Run 手动检查，不中断整批恢复。机械 `V03` 与生产入口 `V04`（`execute_confirmed_frozen_change_set`）绑 `d05_document_task_tests.rs`。不把 D05／Q14／C05／C06／C24 标 closed 或 `verification.passed`。
- **本波明确不做**：N04 正文／顺序／链接目标程序化核对器；把 `doc_normalize_markdown` 升格为内容保持；K15 `completed|partial|blocked` 新持久字段；C24 独立候选类型／UI；N23 撤回≠重规划扩 scope；D06、HR-7 live、Gemini 适配器、V05。不回头做 D04／G02／G03／Q17。
- **不能当作关闭证据**：斜杠命令 `useInlineAi.ts` 的 `webEnabled: false` 只是入口钉，不能单独关闭 Q14。

**本波执行事实（2026-09-21 第二波，不关闭）**

**修复复核（2026-09-22，不变更验收登记）**

- 格式保持门按「参数／权限 → 整文 hash → 虚拟整文候选 → 整文保持 → 冻结」执行，局部数字、链接显示文字、锚点与代码正文不能被结构归一化掩盖。中英文格式意图与 Intake 复用判据，显式核实／时效需求仍优先。
- 变更集拒绝使用带类型的 `Frozen`／`Rejected` 结果；每个原调用收到对应失败反馈，全批在冻结前拒绝，允许有界纠偏且不计实际工具执行。资源不足交付限制说明。

- 选区仅精确映射已执行编辑；范围重叠歧义或无映射依据时不猜测。写后整文 `read_note` 复核仅限已显式授权整文的目标，否则 Host 保留真实写入报告并说明未复核。

## 二、改动范围

本工作包依赖 `D02`、`D03`，验证候选差异、内容保持、确认版本、写入回执与最终表达：

- 生成候选不等于写文件；候选文本、差异与适用范围在统一合同中交接（`C24`）。
- 内容保持可核对：正文信息、顺序与链接目标的差异可复验，允许变化集合明确列出（`C23`、`N04`）。
- 应用绑定确认身份与版本：`C05` 冻结确认、`C06` 写入回执，hash 漂移与部分失败如实报告。
- 交付表达与来源区投影按 `K15` 区分任务结果与 Run 生命周期（`N11`）。
- 触发范围收清：纯编辑不因联网开关打开而自动检索（`Q14`）。

纯编辑不等待 `D04`；需要联网材料的组合任务再依赖 `D04`。

**迁移与旧路径退役**：本工作包负责的被替换路径是**编辑候选生成与应用的交接**（`C24`）、**终局发布**（`C25`）与**写入执行边界**（`C06` 及其复用的业务原语）。迁移与旧路径退役由这些组件的实现任务承担，主责对象登记为 `C23`；跨组件变更必须指定一个主责组件，不能由「评测平面」代替执行责任。迁移以可验证的完整交接为单位，保留可读取的历史会话与明确的配置版本：**不得同时运行两套权威状态**（候选流程与自动写入不得并存为两条写入路径，任务结果不得由 Run 生命周期代替）；**不得重放未知副作用**（写入回执未知时不重复执行，部分失败保留已执行前缀）；**回退不得重新开放已拒绝的权限**——无法保证版本复验与确认绑定时保留候选流程并停止自动应用。只有新路径的输入、执行、结果与诊断合同都有证据后，才能移除被替代的判断，不能只增加一层包装就宣布已经迁移。

## 三、回归证据

**进入下一步的证据：**

1. **候选与差异**：`C24` 的统一候选合同（生成候选不等于写文件）。
2. **内容保持**：`C23` 对正文信息、顺序、链接目标的核对与允许变化集合。
3. **应用**：`C05` 冻结确认与 `C06` 写入回执，hash 漂移与部分失败。
4. **交付**：`K15` 的 `completed`／`partial`／`blocked` 表达与来源区投影。
5. **触发范围**：纯编辑不因联网开关打开而自动检索（`Q14`）。

**回归证据要求：**

1. 格式整理：正文信息与顺序保持，仅允许的变化发生；无法证明保持时提供差异与不确定项，不写「内容完全未改」。
2. 应用：确认目标、范围、版本与真实写入一致；写入回执未知时不重复执行。
3. 交付：限制说明只说明影响交付的具体原因，不使用「模型能力降级」。
4. 纯编辑任务零检索的负例证据。

证据用途、组合与验收要求见 [evidence.md](../testing/evidence.md)；`V03`、`V04` 的判据不在本文件重复定义。

## 四、回退条件

内容保持无法证明时只交付差异与不确定项，不自动写入。写入路径若无法保证版本复验与确认绑定，**保留候选流程并停止自动应用**。回退不重放未知副作用，也不重新开放已拒绝的权限。

## 五、不作出的承诺

- 不承诺文本润色与风格满意度可由确定性检查保证：语义质量仍需判据、来源、不确定性表达与人工校准。
- 不承诺现有规范化转换即可保证任意粘贴文章的内容保持；纯正则空白整理器不等于内容保持合同已经实现。
- 不把生成候选扩张为文件写入授权：新内容通常由用户插入，实际写入继续经确认边界。
- 不设发布分数、数值门槛与版本排期承诺；版本排期唯一来源是 [ROADMAP.md](../../ROADMAP.md)。
- 不因本文件存在而声明 `N04`、`Q14` 已达成或已验证：本工作包第一波与第二波均已开工，仍未关闭。
- 用户撤回已发布答案不等于 Host 在循环内替模型重规划（`N23`）。

### D05 正式定义

## 合同要点

- **前置**：`D02`、`D03`，以及 `K05`、`K15`、`K16`、`L03`、`L04`。纯编辑不等待 `D04`。
