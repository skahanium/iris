# D03 收清会话、权限与上下文

本工作包依据 [Agent 架构定义](../../docs/agent-architecture.md) §10.3 的 **D2 收清会话、权限与上下文** 依赖单元建立，主要承接对象是 `C01`–`C09`、`C16`、`C24`，责任对象登记为 `C07`。它登记施工依据、证据要求与回退条件，**不是工期、版本或发布承诺**，也不沿用已归档体系的阶段完成度。

## 一、前置条件

本工作包的作用域与登记表一致：`N05`、`N12`、`N13`、`N14`、`N22`、`Q02`、`Q08`、`Q15`、`Q16`、`G01`、`G05`；前置 `D01`、`K01`、`K03`、`K05`、`K07`、`K08`；关闭 `Q08`、`G05`。

| 前置                         | 状态要求                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------- |
| `D01` 建立可信基线与最小诊断 | 完成并留下基线身份、评分口径与最小诊断证据（`D01` 的定义见 [D01](./D01-trustworthy-baseline.md)） |
| `K01` 请求身份与引用绑定     | 提供会话、Vault、文档版本与选区绑定的身份合同                                                     |

| `K05` 授权范围与冻结确认     | 提供授权范围、冻结确认与继承／收窄规则                                                            |
| `K07` 上下文装配与裁剪边界   | 提供采用／裁剪／过期的覆盖清单表达                                                                |
| `K08` 压缩覆盖与长期记忆条目 | 提供摘要覆盖与记忆条目的状态、来源与失效表达                                                      |

可施工与可验收**由计算得出**，不读历史标签：见 [治理规则](../rules/governance.md) §2.5。本轮该工作包状态是 `planned`，登记不等于已施工。

## 二、改动范围

本工作包依赖 `D01`，其可与 `D02` 独立的部分并行推进。范围是**证明最新输入、选区版本、摘要覆盖、权限与取消不失真**，为长对话和编辑应用提供可信材料及授权：

- 输入修订在安全点被吸收，旧修订产生的未发布答案不覆盖新要求，取消后不启动新副作用（`K03`、`Q16`）：`Q16` 的**交互形态**未确定，本工作包负责的是修订不会让旧答案覆盖新要求、取消不会启动新副作用这两条可验证性质。
- 上下文装配说明哪些内容被采用、裁剪或过期（`K07`）。
- 摘要覆盖与真实裁剪边界一致，或留下显式缺口（`K08`、`Q08`）。
- 权限判定与冻结确认只继承或收窄，子任务与重试不能增权（`K05`）。
- 工具目录的权限分类与参数消费收清（`G01`）。

**迁移与旧路径退役**：本工作包负责的被替换路径是**会话与运行状态投影**（`C01`–`C03`）、**上下文装配与压缩覆盖**（`C07`／`C08`）、**权限判定入口**（`C04`）与**工具目录分类**（`C16`）。迁移与旧路径退役由这些组件的实现任务承担，主责对象登记为 `C07`；跨组件变更必须指定一个主责组件，不能由「评测平面」代替执行责任。迁移以可验证的完整交接为单位，保留可读取的历史会话与明确的配置版本：**不得同时运行两套权威状态**（运行生命周期与任务结果不得各自成为第二权威，两个设置入口不得各自维护实际路线）；**不得重放未知副作用**（修订、重试与取消后的恢复都不能重复执行已发生的变更）；**回退不得重新开放已拒绝的权限**——权限判定变化若扩大范围，回退到原授权语义。只有新路径的输入、执行、结果与诊断合同都有证据后，才能移除被替代的判断，不能只增加一层包装就宣布已经迁移。

## 三、回归证据

**进入下一步的证据：**

1. **输入修订**：`K03` 的安全点吸收、旧修订答案不覆盖新要求、取消后不启动新副作用。
2. **上下文**：`K07` 的采用／裁剪／过期覆盖清单。
3. **压缩**：`K08` 覆盖与裁剪边界一致，或有显式缺口（`Q08`）。
4. **权限**：`K05` 的授权范围与冻结确认。
5. **工具目录差异**：`G01` 的目录分类与参数消费。

**回归证据要求：**

1. 长对话场景：最新纠正、重要约束与任务进展在压缩后仍被承接，被裁剪区间可解释。
2. 编辑场景：选区与目标绑定、版本与范围可复验。
3. 权限场景：子任务与重试只继承或收窄，不能增权。
4. 两个设置入口交替保存的往返结果（与 `D04` 共用的 `Q02` 证据）。

跨组件交接与生产入口证据、证据记录与适用性要求见 [evidence.md](../testing/evidence.md)；`V02`、`V04`、`V08` 的判据不在本文件重复定义。

## 四、回退条件

摘要覆盖无法与裁剪边界对齐时，保留**显式缺口标记**并禁止把缺口当作已覆盖。权限判定变化若扩大授权范围，回退到原授权语义。回退不重放未知副作用，也不重新开放已拒绝的权限。

## 五、不作出的承诺

- 不承诺运行中追加／修改指令的具体交互形态：该事项未确定；本工作包只承诺「旧修订不覆盖新要求、取消不启动新副作用」两条性质（`Q16`，2026-09-16 由 `D02` 迁入）。
- 不承诺长期记忆的写入时机、有效期、冲突处理与用户管理界面（`Q15` 未确定）：当前只确定确认合同与作用域，默认不把任意聊天内容自动写成长期事实。
- 不承诺普通研究 Run 在进程重启后从任意中间点续跑（`N22`）；不要把「有记忆」写成续跑。
- 不新增 Skill 执行器：技能是提示方法包。`request_tools` 只绑定已有 `G01`，不新开缺口号。
- 不设新的数值门槛与版本排期承诺；版本排期唯一来源是 [ROADMAP.md](../../ROADMAP.md)。
- 不因本文件存在而声明 `Q08`、`Q15`、`Q16`、`G01`、`G05` 已修复或已验证：本工作包尚未施工。

### D03 正式定义

## 合同要点

- **前置**：`D01`，以及 `K01`、`K03`、`K05`、`K07`、`K08`。
- **改动范围**：输入修订、上下文覆盖清单、压缩边界一致性、授权与取消、工具目录差异。
- **证据**：长对话承接、编辑绑定、权限不增权、两个设置入口往返。
- **回退**：覆盖无法与裁剪边界对齐时保留显式缺口；授权语义扩大即回退。
- **关闭**：`Q08`、`G05`；同时为 `Q02`、`Q15`、`G01` 提供证据。
- **不得发生**：把缺口当作已覆盖；子任务或重试自行增权。
