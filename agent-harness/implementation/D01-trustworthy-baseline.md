# D01 建立可信基线与最小诊断

本工作包依据 [Agent 架构定义](../../docs/agent-architecture.md) §10.3 的 **D0 建立可信基线与最小诊断** 依赖单元建立，主要承接对象是 `E01`／`E03` 与 `C26`／`C27`，责任对象登记为 `M09`。它登记施工依据、证据要求与回退条件，**不是工期、版本或发布承诺**，也不沿用已归档体系的阶段完成度。

<!-- iris:object D01 kind=rules owner=M09 file=true -->

## 一、前置条件

本工作包的作用域与登记表一致：`N01`、`N15`、`N18`、`Q01`、`Q03`、`Q09`、`Q11`、`Q12`、`Q18`、`G04`；前置 `P01`、`P02`、`P03`、`P06`、`K17`、`V01`、`V08`；关闭 `G04`、`Q18`。

| 前置                         | 状态要求                                           |
| ---------------------------- | -------------------------------------------------- |
| `P01` 体系入口               | 已登记，能据其进入规则、需求与工作包               |
| `P02` 对象与标记规则         | 提供对象身份、标记与指纹规则                       |
| `P03` 治理规则               | 提供状态四维、关系模型与就绪计算规则               |
| `P06` 需求与边界             | 提供需求条目 `N01`–`N20`，本工作包作用域的需求依据 |
| `K17` 审计事件与诊断查询     | 提供事件关联、记录完整性与诊断查询合同             |
| `V01` 证据用途分类与组合要求 | 提供证据分类与组合判据                             |
| `V08` 证据记录、绑定与适用性 | 提供证据绑定字段与当前适用性表达                   |

可施工与可验收**由计算得出**，不读历史标签：见 [治理规则](../rules/governance.md) §2.5。本轮该工作包状态是 `planned`，登记不等于已施工。

## 二、改动范围

- **固定基线身份**：代码提交、配置版本、场景集合与评测夹具身份必须可复现，使同期比较有可比对象。
- **处理 `F02`（空分母适用性表达）**：区分适用／未覆盖／通过，显示实际分母；**保留原评分基线**，零分母不得被记为满分通过（`Q03`）。
- **建立最小诊断**：能够追踪模型、工具及恢复交接；完整诊断界面可后续扩展，但**不能先以不可定位的结果评价迁移成功**（`Q09`、`Q18`、`G04`）。

以上范围不新增模块，也不建立第二套运行状态。

**迁移与旧路径退役**：本工作包负责的被替换路径是**现有评分口径与诊断记录口径**（`E01`／`E03` 与 `C26`／`C27` 的当前记录方式）。迁移与旧路径退役由上述组件的实现任务承担，主责对象登记为 `M09`；跨组件变更必须指定一个主责组件，不能由「评测平面」代替执行责任。迁移以可验证的完整交接为单位，保留可读取的历史会话与明确的配置版本：**不得同时运行两套权威状态**（新旧口径并存时按显式版本标识读取，不双算、不双写）；评测与诊断**不得重放未知副作用**，写入回执未知时必须先核实；**回退不得重新开放已拒绝的权限**。只有新路径的输入、执行、结果与诊断合同都有证据后，才能移除被替代的判断，不能只增加一层包装就宣布已经迁移。

## 三、回归证据

**进入下一步的证据：**

1. **基线身份**：代码提交、配置版本、场景集合与评测夹具哈希齐备。
2. **评分口径**：区分适用／未覆盖／通过的判据与分母显示可用（`Q03`）。
3. **最小诊断**：Run／输入修订／父子任务／模型回合／调用与尝试身份齐备，出站结构证据可用（`Q09`、`Q18`、`K17`）。
4. **证据记录**：`V08` 的绑定与适用性字段可用。

**回归证据要求：**

1. 同期基线的评测记录：保留原口径与版本标识，**不得把零分母改为 0 分冒充模型质量下降**。
2. 一次已知故障的诊断演练：能指出发现位置、直接失败、恢复结果与待证根因。
3. 负例：注册表损坏、文件读取失败、检查器异常均返回失败，不出现伪通过。

证据用途、组合与验收要求见 [evidence.md](../testing/evidence.md)；`V01`、`V08` 的判据不在本文件重复定义。

## 四、回退条件

诊断实现无法在评审周期内定位已知故障时，**保留原评分基线**并退回评测口径修正；不以「界面未完成」为由放行迁移评价。回退不重放未知副作用，也不重新开放已拒绝的权限，已取得的真实结论不因回退被改写。

## 五、不作出的承诺

- 不承诺完整诊断界面在本工作包内完成：界面可后续扩展，进入下一单元的条件是最小诊断的可定位性。
- 不设新的评分门槛、发布分数、容错百分比或费用上限；版本排期唯一来源是 [ROADMAP.md](../../ROADMAP.md)。
- 不因本文件存在而声明 `F02`、`Q03`、`Q09`、`Q18`、`G04` 已修复或已验证：本工作包尚未施工。
- 不承诺自动评分可以替代人工校准：语义质量仍需判据、抽样规则与人工记录。

### D01 正式定义

## 合同要点

- **前置**：本体系入口与规则（`P01`–`P03`、`P06`）、`K17`（审计事件与诊断查询）、`V01`、`V08`。
- **改动范围**：只做基线身份、评分口径与最小诊断，不改产品行为、不扩大预算。
- **证据**：同期基线评测记录、一次已知故障的诊断演练、检查器负例。
- **回退**：诊断无法定位已知故障时保留原评分基线，不以界面未完成放行迁移评价。
- **关闭**：`G04`、`Q18`。
- **不得发生**：把零分母改为 0 分冒充模型质量下降；用未绑定指纹的旧证据评价迁移成功。
