本工作包依据 [Agent 架构定义](../../docs/agent-architecture.md) §10.3 的 **D1 修正协议与有界纠偏** 依赖单元建立，主要承接对象是 `C11`／`C12`、`C13`／`C14`、`C17`／`C23`，责任对象登记为 `C14`。它登记施工依据、证据要求与回退条件，**不是工期、版本或发布承诺**，也不沿用已归档体系的阶段完成度。

## 二、改动范围

- **先覆盖 `F03`（流式终止原因）**：正常结束、长度截断、工具结束、尾事件与缺失终止事件都必须保留供应商事实并到达验证边界，不能把截断的工具调用当作完整动作执行（`Q04`）。
- **未知工具纠正、参数修正与工具后续轮**：无效提议不当作执行；返回具体反馈（准确工具名、字段级校验问题与合法取值）后由模型重新提议或修正参数并继续。
- **证明停止原因与错误反馈到达正确边界**，再把新循环路径作为默认；在此之前不以新循环取代现有路径的行为。
- **停止判定从配方启发式改为信封**（`R11`、`R12`、`G06`、`N15`、`N21`）：任务未完成且信封仍允许时，Host 不得因无进展身份或两轮拒绝强制综合。完成额度预留触达后不提供业务工具、把 remaining 留给表达，属信封（`R12`）；禁止的是因此注入关面指令。

以上范围不改变协议本身，也不新设第二个执行循环。

**迁移与旧路径退役**：本工作包负责的被替换路径是**现有停止判定与恢复反馈交接**（`C14`）以及**协议续轮与调用结果适配**（`C11`／`C12`）。迁移与旧路径退役由这些组件的实现任务承担，主责对象登记为 `C14`；跨组件变更必须指定一个主责组件，不能由「评测平面」代替执行责任。迁移以可验证的完整交接为单位，保留可读取的历史会话与明确的配置版本：**不得同时运行两套权威状态**（旧停止判定不得与新终止原因判定并存双写，预算只有一个账本）；恢复与重试**不得重放未知副作用**，已执行或可能已执行的写入必须先核实回执；**回退不得重新开放已拒绝的权限**，取消与明确拒绝不因回退恢复为可重试状态。只有新路径的输入、执行、结果与诊断合同都有证据后，才能移除被替代的判断，不能只增加一层包装就宣布已经迁移。

## 三、回归证据

**进入下一步的证据：**

1. **协议保真**：Chat Completions／Responses／Messages 各自的续轮字段、工具增量与出站结构不丢失（`Q10`）。**本包只覆盖下文「本包关闭证据」列出的部分**；服务端搜索事件与引用不在本包，见 [G03](../requirements/open-items.md)。
2. **终止原因**：正常结束、长度截断、工具结束、尾事件与缺失终止事件都能到达验证边界（`Q04`）。本包的关闭证据是 **Chat Completions 的机械记录**（`V03`），不是逐端点 `V05`；`V05` 见下文外移清单。
3. **纠偏**：可恢复错误按 `K16` 的默认处理反馈并继续，机械重试／重新提议／语义改查分开计数。
4. **预算**：`K06` 单一账本仍是前置。同版本数值差异目前不可读，属 `Q13` 已知限制；改默认值必须先升 `schema_version`（已采用的 `R13`）。本包不关闭 `Q13`，也不因 `R13` 采用而可验收。
5. **过早收束负例**：下列六项已实现并由 `agent_tool_loop_host_authority_tests.rs` 的独立 `verify` 命令绑定（`G06`）。

   2. 换查询的第二次搜索撞同一 URL／同一段正文 ≠ 无进展；验收钉 `safe_progress_identities`（`src-tauri/src/ai_runtime/agent_tool_loop/observations.rs`），不钉循环 if（`G06`）。
   3. 两轮 `unknown_tool` 已给字段级反馈且预算未尽 → 不得因 `rejected_rounds >= 2` 强制综合。
   4. Host 不得在任务未完成且信封仍允许时仅因 `no_progress_rounds`／`failed_service_rounds` 注入关面指令或关闭业务工具。
   5. 完成额度预留触达后可不提供业务工具并把 remaining 留给表达（`R12`）；不得因此注入 `tool_surface_closed_instruction`。
   6. 8／24／每回合 2 个发现的数值变化不要求改架构正文。

**回归证据要求：**

1. 每个协议分支的字段保真测试与出站结构证据。

## 四、回退条件

终止原因无法在不改协议的前提下定界时，**保留原停止判定**并只上线纠偏与反馈部分。预算调整破坏旧 Run 读取时回退到受控配置并保留原策略版本（`Q13`）；不得靠放宽「完整但不规范必须失败关闭」这条不变量来换取可读性。回退不重放未知副作用，也不重新开放已拒绝的权限。

## 五、不作出的承诺

- 不宣布 MiniMax、DeepSeek 或 Gemini 任一端点已通过：协议与端点适配仍需逐个验证（`Q17`／`G03`）。
- 不新设容错百分比门槛、重试次数或时限：具体次数与时限由受控恢复策略配置和评测校准决定。
- 不把自动切换模型作为未知工具或普通参数错误的默认纠偏手段。
- 不读取或保存模型私有思维链：恢复轨迹只记录可观察的动作、错误、反馈与修正，无推理内容返回的模型具备同样能力。
- 不承诺运行中追加／修改指令的就地通道；该事项的交互形态已于 2026-09-19 确定并关闭（`Q16`：运行中拒绝新指令），作用域在 [D03](./D03-session-permission-context.md)，本工作包不因它被阻断验收。不设版本排期承诺，版本排期唯一来源是 [ROADMAP.md](../../ROADMAP.md)。
- 本包已按 §三「关闭门槛」表收口：`D02`、`Q04`、`Q10`、`G06` 均已关闭，`work.state=done`、`verification.state=passed`。关闭只表示表中列明的证据已绑定，**不表示** `Q13` 已关闭、任一端点已 live 通过、或 `C11`／`C14` 组件自身已 `passed`。`F03` 不是登记对象：`Q04` 关闭表示架构定义 §10.2 所描述的 Chat Completions 流式终止缺陷已有机械覆盖；该节仍是发现当时的快照，不表示 live／Anthropic／Responses 已过。字段级纠偏属 `K16`／`C14`，Anthropic 五类负例属 `C11`／`K04`，均不作为 `G06` 关闭条件。

     **禁止只补转引而不补所需证据**；收口前不满足时 `work.state` 保持 `planned`、`verification.state` 保持 `none`，不得写成 `done` 或 `ready`。
- 不把 8／24／每回合 2 个发现写成架构真理。

### D02 正式定义

## 合同要点

- **前置**：`D01` 的证据口径，以及 `K04`、`K06`、`K10`、`K15`、`K16`、`R11`、`R12`。
- **改动范围**：协议保真、流式终止原因、纠偏反馈与工具后续轮；停止判定从配方启发式改为信封（完成额度预留按 `R12`）；新循环路径取得证据后才作为默认。
- **证据**：各协议分支的字段保真测试与出站结构证据；本包恢复案例（未知工具纠正后派发、参数按字段级原因修正后派发、网络工具暂失败后再提议成功、取消后不再开轮，`V04`）；过早收束负例（进展身份、观察后再提议、已反馈的未知工具不得强制综合、预留触达不注入关面指令，`V03`）。
- **回退**：终止原因无法定界时只上线纠偏与反馈；预算调整破坏旧 Run 读取时回退受控配置。
- **关闭**：`Q04`、`Q10`、`G06`——关闭证据以 §三「关闭门槛」表为准（`Q04`／`Q10` 用现有 `V03`，`G06` 用独立 `host_authority` 绑定）；逐端点 `V05` 外移 `G03`／`Q17`／`D04`，不是本包关闭条件；`Q13` 不关。
- **不得发生**：把截断工具调用当作完整动作执行；因一次未知工具即终止 Run；向用户提示模型能力降级；只补转引而不补所需证据就写 `work.state=done`。
