# D04 接通双路搜索完整链路

本工作包依据 [Agent 架构定义](../../docs/agent-architecture.md) §10.3 的 **D3 接通双路搜索完整链路** 依赖单元建立，主要承接对象是 `C10`／`C18`、`C20`–`C22`、`C25`，责任对象登记为 `C20`。它登记施工依据、证据要求与回退条件，**不是工期、版本或发布承诺**，也不沿用已归档体系的阶段完成度。

## 二、改动范围

本工作包依赖 `D02` 的续轮与恢复，以及 `D03` 涉及的外发授权和取消边界。范围是处理 `F01`、`F04`，并把**设置、配置、原生能力、搜索、抓取与诊断**贯通：

- 一个 Iris 搜索接口、两条内部执行路线、共同的按需正文读取；原生不支持时正常单 MCP，不显示能力降级。两路都搜到是**证据**不是配方：模型不必按固定步骤搜索。
- 两个设置入口的写入语义一致：主服务入口走 `web_search_route_promote`（服务端读当前路线后提前），不得用 `set([id])` 或过期内存拼数组覆盖备用项；面板调序仍用整表 `set`。查询路径保持只读，配置升级移到明确的保存边界（`F01`、`F04`、`Q05`）。`Q02` 保持 closed。
- 必须证明**真实生产入口**的两路执行与无原生时的正常单路，不能只用后端替身被调用来代替。

**迁移与旧路径退役**：本工作包负责的被替换路径是**搜索与抓取的生产执行路径**（`C20`–`C22`）、**原生搜索接入**（`C10`／`C18`）与**设置写入路径**（`C16`／`C25` 的当前投影）。迁移与旧路径退役由这些组件的实现任务承担，主责对象登记为 `C20`；跨组件变更必须指定一个主责组件，不能由「评测平面」代替执行责任。迁移以可验证的完整交接为单位，保留可读取的历史会话与明确的配置版本：**不得同时运行两套权威状态**（实际路线不得由不同前端局部状态各自决定，配置、快照与冻结顺序只有一个权威来源）；**不得重放未知副作用**（配置升级与重新抓取都不得重复提交未知结果的写入或计费动作）；**回退不得重新开放已拒绝的权限**——原生凭据不可核实或端点不可用时不得借回退扩大外发范围。只有新路径的输入、执行、结果与诊断合同都有证据后，才能移除被替代的判断，不能只增加一层包装就宣布已经迁移。

## 三、回归证据

**进入下一步的证据：**

1. **双路协调**：`K11` 的两路状态、执行证据与合并线索。
2. **原生子请求**：`K12` 的受控接入与凭据判定。
3. **抓取**：`K13` 的批量读取、窗口续读与部分失败保留。
4. **证据**：`K14` 的来源身份与 `Wn` 登记规则。
5. **设置**：F01 写入协议——主服务变更走 `promote`、不丢备用项。`Q02` 已 closed，不是本包再关项。
6. **只读查询**：`Q05` 的读取路径不写库、配置升级移到明确保存边界。

**回归证据要求：**

1. 生产入口证据：「原生＋单 MCP」「原生不支持＋单 MCP」「MCP 主备切换」「两个设置入口交替保存」「运行中关闭联网」。
2. 执行证据只用供应商定义的实际搜索事件或可证明检索发生的结构化 grounding 元数据。
3. 分路故障：原生失败保留 MCP 结果、MCP 失败保留原生结果、两路都失败如实说明。
4. 与端点的真实调用记录（`Q17`），不得仅凭厂商名或 OpenAI-compatible 标签判定。

协议兼容与真实端点证据、跨组件交接与生产入口证据见 [evidence.md](../testing/evidence.md)；`V04`、`V05`、`V08` 的判据不在本文件重复定义。

## 四、回退条件

原生凭据不可核实或端点无法稳定实现时，**保留 MCP 单路**并如实记录协议／结果不足，不得伪造成功或归为「模型不支持」。双路证据不足时**不宣称双路已接通**。回退不重放未知副作用，也不重新开放已拒绝的权限。

## 五、不作出的承诺

- 不宣布 MiniMax、DeepSeek 或 Gemini 任一端点已通过：端点、混合续轮、费用与权限适配仍需逐个验证（`Q17`／`G03`）。
- 不承诺两路一定取得两个成功结果，也不承诺固定程度的召回提升；渠道数量、转载数量与独立证据数量不能混算。
- 不新设费用上限与延迟目标：时间上是否并行是执行策略，两路实际执行才是功能合同。
- 不把「OpenAI-compatible」标签或首轮文本成功当作能力证明；原生返回无可核实的检索凭据时只记录协议／结果不足。
- 不设版本排期承诺；版本排期唯一来源是 [ROADMAP.md](../../ROADMAP.md)。
- 不因本文件存在、也不因 `Q05` 源码 list 只读（落点 `058366ea`），而声明 `F01`、`F04` 已关闭、`Q05` 已关闭、或双路已接通：该提交与 list 写库的机械覆盖都不是本包验收；`F01` 架构项、双路、`G02`、`G03` 与逐端点 `V05` 仍待施工。不因 `web_search_route_promote` 落地而把架构 `F01` 写成已关闭。
- 不因 `C20` 协调器接入生产 `web_search`、也不因机械 `V03` 双倍覆盖，而声明 `G02` 已关闭或双路已接通：生产入口录制回放 `V04` 已有，**不是** `V05` live；未登记模型仍 MCP 单路；不得把机械双替身写成 `V04`。
- 不因 `K12` 适配器登记，而声明 `G03` 已关闭或任一端点已通过：生产子请求仍不经 `streaming.rs`；主对话 SSE 夹带进入处理路径为凭据，不是逐端点 `V05`。现行执行事实见 [K12](../contracts/K12-native-search-subrequest.md)。
- 不因 `D02` 验收而声明任一端点已 live 通过：`D02` 的关闭证据是机械记录，逐端点 `V05` 仍由本工作包与 `G03`／`Q17` 承接。

### D04 正式定义

## 合同要点

- **前置**：`D02`（续轮与恢复）、`D03`（外发授权与取消），以及 `K09`、`K11`–`K14`、`K18`。
- **改动范围**：设置写入语义、原生能力配置、双路协调、原生受控子请求、抓取与窗口、证据登记、只读查询。
- **证据**：生产入口五组场景；供应商实际搜索事件或结构化 grounding 元数据；分路故障处理；端点真实调用记录。
- **回退**：原生凭据不可核实或端点不稳定时保留 MCP 单路并如实记录协议／结果不足。
- **关闭**：`Q05`、`Q17`、`G02`、`G03`。`Q02` 已 closed，不由本包再关。
- **不得发生**：伪造原生成功；把不支持悄悄归成失败或把失败归成不支持；以单路结果冒充双路完成。
