# web_search

<!-- iris:object T11 kind=rules file=true -->

`web_search` 是 Iris 的内置业务工具之一（通用能力目录，共 39 个）。它是能力接口，不是权限：能否调用由 `C04` 授权决定，实际派发由 `C17` 负责。

## 用途与语义归属

一次动作保证原生与 MCP 可用路线均实际搜索（设计目标为此，当前实现见「当前状态」）。语义归属「工具」，责任模块 `M07`；目录身份由 [catalog.mjs](../catalog.mjs) 登记，语义归属与目标合同见 [docs/agent-architecture.md](../../docs/agent-architecture.md) §5、§6.2。

它是**发现**动作，不是正文读取：返回本次 Run 的候选线索（标题、域名、URL、有界片段），候选只标记为搜索片段，不登记为可引用证据；只有 `web_fetch` 取得正文的选中页面才登记为可引用证据。这与 `N07`、`N08` 的分工一致。

它同时是"唯一联网检索入口"的落点：原生检索（`M04` 的受控子请求）与 MCP 检索（`C18`）是同一接口内部的两条执行路线，不新增第二个让主模型任选的搜索工具（`K11`、`K12`）。

## 参数与消费

| 参数    | 类型   | 必填 | 消费事实                                                                     |
| ------- | ------ | ---- | ---------------------------------------------------------------------------- |
| `query` | string | 是   | 作为本次搜索动作的查询；空串或纯空白在派发前拒绝（`tool_arguments_invalid`） |

`input_schema` 声明 `additionalProperties: false`，未知字段被拒绝，不是静默忽略。目标合同之下，查询语义只由模型提出：宿主不得用关键词规则替模型改写查询（`C14` 的可恢复错误表）。

被消费的声明性元数据：`access_level = Network`、`max_results = Some(8)`（每次派发允许的候选面）、`execution_metadata.cost_class = "network"`、`evidence_policy = "current_run_web"`。其中**实际生效的候选上限**来自执行侧的有界常量（见「预算」），目录的 `max_results` 不单独决定返回条数。

## 授权

- `C04` 是唯一授权决定者；联网开关是 `web.search` 的唯一授权源：关闭时原生与 MCP 两条路线都不可达，选项、Skill、子 Run 与提示词都不能增权。
- 运行期准入门槛是能力 `web.search`；目录声明的 `access_level = Network` 只是展示元数据，不得扩大 Run 授权。
- 权限原子映射为 `WebSearch`，风险级别 `Low`；不需要确认（`requires_confirmation = false`）。
- 外发边界优先于双路：查询外发受 `K09` 约束。当前实现还带一条拒绝规则——若查询文本与自动装入的本地材料重合，本次派发被拒绝（`web_query_local_material_blocked`），不把私有材料带出（`N13`）。

## 副作用

对外发起网络请求，向内写入两类记录：

1. 本次动作的候选线索与来源身份（`C22` 的线索身份）；
2. 审计与诊断事件中脱敏后的查询哈希与 URL 计数，不记录查询原文与笔记正文（`K17`）。

它不写 `.md`、不写长期记忆、不登记可引用证据（候选只算片段）。上游影响与传播关系按 `K17` 记录，本工具不自行作出归因结论。

## 预算

- 单一预算分类 `Network`，受 `max_network_tool_calls` 约束；Standard／Delegated／DurableApply 三类预设当前均为 6，且 `web_search` 与 `web_fetch` **共用**该类别额度（`K06`、`Q19`）。
- 一次搜索动作记一次网络类派发（内部两条路线不各记一次）；未派发的提议不增加实际派发计数，但它已经消耗的模型回合、token 与时间照实计入（`N16` 的容错预算口径）。
- 需要联网观察的 Run 会先由宿主完成一次有界的最小观察（搜索加抓取），它在启动前就预留网络类额度；这次观察不伪造助手工具调用，也不隐藏后续 Web 工具。
- 发现类动作另有每模型回合上限：catalog 标记的发现调用每回合最多 2 次，超出的独立发现动作返回 `deferred_for_feedback`，不消耗额度。
- 原生与 MCP 两条路线都在同一 Run 的额度内申领（`C13`）；预算不足以启动两条已承诺路线时，如实说明本次限制，不以单路结果冒充双路完成。
- 时间边界：单次网页派发有界（当前 20 秒，重试需保留最小剩余预算）。数值属于受控配置，不在本卡片新设。

## 幂等

搜索本身不产生持久变更，但**不保证可复用**：同一查询的候选集合随时间与供应商状态变化。目标合同允许在同修订内复用同一搜索动作的真实观察，但复用必须指向真实观察与其时间，不能算作一次新的联网执行，也不能据此伪造第二次搜索成功。

## 取消

派发边界在开始前检查 Run 取消标志；进行中的外部调用可请求取消，其迟到结果保留为旧修订观察，不自动成为新答案（`C03`）。双路搜索的每一路都受同一取消与所有者额度约束。

## 失败反馈

按可恢复错误反馈，一次失败不终止任务（`C14`、`N16`）：

| 情形                     | 反馈                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 联网未授权（关闭状态）   | 明确拒绝 `web search not enabled for this request`，不静默转为本地检索                                                 |
| 参数无效                 | 派发前拒绝（`tool_arguments_invalid`），不派发                                                                         |
| 查询含自动装入的本地材料 | 拒绝 `web_query_local_material_blocked`，并记录一条受控的 Web 失败类别                                                 |
| 全部候选失败             | 返回失败工具结果并说明「没有可核验的网页证据」；不得凭记忆或猜测给结论                                                 |
| 返回结构不可解析         | 明确回报「联网搜索链路返回不可解析结果」，并说明这是链路问题、不代表外部没有相关信息，也不改写成「搜索服务暂时不可用」 |
| 超时／网络类错误         | 可重试，带退避与剩余预算约束；不紧密无限重试                                                                           |
| 一条路线失败             | 保留另一条真实结果；修复失败路线或按证据充足性继续，不因一侧失败丢弃另一侧结果                                         |
| 原生返回无检索凭据       | 记录协议／结果不足，在预算内有依据地恢复；不伪造「原生已成功」，也不悄悄归成「模型不支持」                             |

判据与执行证据要求见 `V04`、`V05`；不得仅凭厂商名或 `OpenAI-compatible` 标签判定能力（`Q17`）。

## 暴露规则

通用能力目录项（`surface=general`），位于目录的 `web` 组；只在联网获准时进入工具面，并记录工具面版本（`C16`、`K10`）。发现类动作受每模型回合的发现上限约束（见「预算」）。

在受限子任务中，本工具属于 `CHILD_SAFE_TOOLS`（只读白名单），子 Run 不绕过父级的原生／MCP 策略（`N12`）。子任务目前不含标准 `web_fetch`（`Q07`）。

目录行不含任何原生搜索的旁路入口：供应商原生工具声明是协议能力，不作为第二个可任选的 Iris 搜索工具暴露。

## 当前状态

- 文档成熟度 `draft`（见「维护规则」：[README.md](../README.md) §八）。
- 实现状态 `implementation.state = partial`：目录项为 `Dispatchable`，主链路与备用派发入口都能执行一次检索，但**双路协调是明确缺失、需新增的行为**——搜索候选只解析 MCP 路线，原生搜索事件尚未接入网关处理路径。源码事实：`collect_search_provider_fetches` 只把候选枚举为 MCP provider；网关侧未见服务端搜索事件／引用的接入。
- 因此：**一个 `web_search` 动作当前不能保证原生与 MCP 两路都实际搜索**；目标合同（`N07`）与实现之间是已知缺口 `G02`（双路搜索协调的真实执行）、`G03`（原生搜索事件的接入与端点适配），阻断门槛均为 `at=acceptance`，主要工作包 `D03`。
- 端点、混合续轮、费用与权限适配待验证（`Q17`）；本卡片**不宣布** MiniMax、DeepSeek 或 Gemini 任一端点已通过。
- 所需证据：生产入口的两路执行证据（`V04`），以供应商定义的实际搜索事件或可证明检索发生的结构化 grounding 元数据为执行证据；单纯发出带工具声明的请求、模型自行生成 URL 都不算已搜。
- 验证结果：本卡片不声明任何验证结论；本轮为基线 `2670739f` 的静态核对，未执行新实验、未运行付费实网评测。
