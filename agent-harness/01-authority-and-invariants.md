# 01. 权威边界与长期不变量

本文只定义任何 Harness 实现都必须遵守的长期合同，不表示目标已经实现。当前事实和测试证据分别见文档 02 与附录 A。

## 1. 产品、数据与权威边界

- Iris 仍是本地优先的 Markdown 笔记应用，不建设通用 Agent 平台、工具市场或任意代码执行环境。
- 用户 `.md` 文件仍是笔记知识的最权威来源；未经明确确认不得修改笔记正文，也不得把模型推断写成用户事实。
- SQLite 中的笔记索引必须可由 Markdown 重建；AI 会话、Web 缓存和外部补充事实属于应用状态，不得反向成为笔记权威。
- `ROADMAP.md` 是版本排期唯一来源；本目录不得新增版本号、发布日期或与根路线图冲突的承诺。
- `ARCHITECTURE.md` 只记录已部署事实；目标合同只有落地并验证后才能同步进去。

## 2. Run 生命周期与内容所有权

- `client_request_id` 是持久化 Run 幂等键：同 ID、同请求指纹必须重放原 Run；同 ID、不同指纹必须冲突。
- 同一普通会话同时最多有一个活动顶层 Run；子任务不得建立竞争的顶层真相源。
- 最终助手消息和必要绑定持久化成功后才能写入 `Completed`，随后才能投影 `AnswerComplete`。
- 事件 sink 故障不得改写已提交事实；恢复从 Run、消息和可重放事件完成，不重新执行副作用。
- 助手正文、reveal、过程事件、工具结果和引用必须携带同一 Run 身份；新 Run 不得回退显示上一 Run 内容。
- 写操作继续执行确认门；拒绝后不得执行变更或生成伪成功结果。

## 3. 权限、隐私与网络安全

- Web 开关、classified/local-only 状态和当前 Run 冻结权限是外部读取授权的唯一来源；模型、领域分类和 provider 状态均不能扩大权限。
- 工具展示、`capabilities_read` 和执行门禁必须消费同一冻结工具表面。
- 自动检索出的本地笔记内容不得进入 Web 查询、URL、日志、错误或 provider 参数。
- API Key、Token、笔记正文、解密密码和 provider 原始输出不得进入日志、遥测或模型可见诊断。
- 网络 URL 必须为 HTTPS，并通过 SSRF、重定向、大小、类型、超时和 current-Run provenance 校验。
- 网页和工具结果始终作为不可信数据处理，不得提升为系统指令。

## 4. 当前事实与研究循环

- 本机日期、时间、星期和时区优先来自可信 runtime，不为证明本机事实联网。
- 会变化的外部事实必须带绝对时间语境；地域、单位、渠道和标的歧义必须在回答前解决或明确披露。
- 外部当前事实只能来自本 Run 的可用 Web 证据或已验证结构化结果；模型记忆、旧 Run 来源和历史回答不能补缺。
- 研究循环必须有搜索、抓取、模型轮次、证据量、总时限和 token 上限；不得以无界思考替代回答。
- 第一次调用后，继续研究必须对应未解决的 `EvidenceGap`；重复规范化查询和无新增证据循环必须停止。
- 搜索成功、来源数量或模型声称联网都不等于证据充分。
- 达到预算仍不能满足事实合同时，必须说明缺口或失败关闭，不能通过语言润色制造确定性。

## 5. 证据与最终化

- 继续复用现有 evidence ledger，不新增平行证据表。
- 精确引用只能绑定当前 Run 实际使用、未失效、可定位的证据。
- 最终答案来源协议只有一种解释：`Wn` 是当前 Run 的 Web 顺序号，`E{id}` 是当前 Run 的外部工具 evidence ledger ID，`L{id}` 是当前 Run 的本地 evidence ledger ID，`Mn` 是本轮授权材料顺序号；会话展示标签 `[Cn]` 和裸数据库 ID 永远不是模型可提交的来源引用。
- `ProvenancePolicy` 是来源语法、当前 Run 所有权与逐块覆盖校验的唯一事实源；当前事实、Host renderer 和 UI 不得各自实现另一套 ID 匹配规则。
- `SourceGroupFallback` 只表示本次检索来源组，不能冒充逐段引用或严格事实支持。
- 实体、数值、日期、地域、单位和状态必须能追溯到结构化字段或可定位证据；provider 自带 evidence ID 不可信。
- 当前生产门禁校验引用归属、时效字段与事实块覆盖，不宣称已经实现自由文本语义蕴含或 NLI VERIFIED judge。
- Direct、ToolLoop、恢复、降级和结构化快路径遵守相同的证据所有权和最终化语义。

## 6. 上下文与最小记忆

- 当前决策上下文从已提交消息、Run 事件、冻结 intake、证据和必要摘要投影，不新增持久化的第二会话真相。
- 会话摘要是可失效、可重建的派生数据，不能覆盖原始消息。
- 跨会话记忆只保存用户确认的少量偏好，必须可查看、可修改、可删除并带作用域。
- 地点不得从 IP、网络端点、笔记正文或模型猜测中推断。

## 7. 技术债与性能不变量

- 全系统只保留一套 Run engine、prompt compiler、tool catalog、provider registry、evidence ledger 和网络研究循环。
- 继续只暴露一个模型可见网络工具 `web_search`；不得通过新增 fetch 工具绕过统一预算和安全边界。
- 新抽象只有在同一阶段删除对应旧分支、旧测试和旧文档时才能进入主干。
- 不允许长期双写、兼容 facade、第二套路由状态机或只为未来假设建立持久化模型能力库。
- 单轮抓取并发必须有上限；Deep 只能由用户明确触发；性能优化不得放宽质量和安全门禁。
- 活跃研究模块不得依赖模块级 `allow(dead_code)` 掩盖不可达实现。

## 8. 明确非目标

- 近期实现 11/11 结构化 Provider 覆盖；
- readiness 管理中心、通用 REST adapter 和多 Provider 自动 failover；
- 自动交易、个性化投资买卖建议和高风险外部写操作；
- 通用浏览器自动化、登录态页面操作和表单提交 Agent；
- 第三方工具市场、任意代码执行和通用多 Agent 平台；
- 依赖 LLM judge 的默认自由文本 VERIFIED 标签；
- 为模型“强弱”建立新的长期评分和持久化路由系统。
