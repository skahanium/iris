# L04 格式保持链路

<!-- iris:object L04 kind=rules file=true -->

本链路说明**交接顺序**：谁在什么时候把什么交给谁。它**不重复定义**合同（K*）、组件（C*）或工具（T\*）的正式定义，只引用它们。对象身份与标记规则见 [objects.md](../rules/objects.md)，权威边界与状态语义见 [governance.md](../rules/governance.md)；上位依据是 [Agent 架构定义](../../docs/agent-architecture.md) §7.3 与 M8 的内容保持说明，当前实现事实以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 的 Markdown document boundary 一节为准。

本链路只写交接顺序，不把内容保持写成已经实现：**检查不能确定时交付差异和不确定项，不自动写入，也不声称「内容完全未改」**；纯正则空白整理器不等于这个合同已经实现。

## 步骤与交接

| #   | 触发者 → 组件                      | 交付物                                                                           | 引用合同 |
| --- | ---------------------------------- | -------------------------------------------------------------------------------- | -------- |
| 1   | 用户格式整理请求与目标文档 → `C01` | 请求身份与材料引用：目标文档版本、选区与「允许变化集合」的显式要求               | `K01`    |
| 2   | `C01` → `C24`                      | **先保存原始文本**与目标版本，再进入变换；原文与允许变化集合是本链路的第一交付物 | `K16`    |
| 3   | `C24` → 模型或辅助转换器           | 原始文本与允许变化集合；由模型或辅助转换器给出候选                               | `K16`    |
| 4   | 候选 → `C24`                       | 候选文本、差异与适用范围；允许的变化必须明确列出                                 | `K16`    |
| 5   | `C24` → `C23`                      | 原文与候选、允许变化集合，供核对正文信息、顺序、链接等                           | `K16`    |
| 6   | `C23` → `C24`／`C14`               | 逐项报告与实际分母：通过、失败、未知或对本任务无要求分别表达；不确定时给出缺口   | `K16`    |
| 7   | `C24` → `C25`                      | 可证明保持时呈现候选；**不能证明时交付差异和不确定项，不自动写入**               | `K15`    |
| 8   | 用户选择应用 → `C05` → `C06`       | 冻结确认与实际写入；写入路径与普通编辑相同                                       | `K05`    |

**内容保持的核对边界**：`C23` 比较**保留的文本内容、顺序及链接目标**等信息；仅序号和表示结构所需的语法变化可以在**已约定范围内**发生。「不能机械忽略所有空白、标点或数字」是本链路的硬性要求——机械忽略会漏过实质改动。这一类核对属任务验证，不由模型的完成声明代替。

**与相邻链路的分界**：候选的应用与写入回执在 `L03`；本链路只增加「原文与允许变化集合 → 候选 → 内容保持核对」的交接。Markdown 的持久化边界与序列化失败语义属实现事实（[ARCHITECTURE.md](../../ARCHITECTURE.md)：不支持的语法成为保留原源码的节点，序列化失败可恢复且不回退到 HTML／Turndown），本文件不重复其正文。

| [`K05`](../contracts/K05-authorization-and-confirmation.md) | 第 8 步：候选应用需要冻结确认，确认绑定目标、内容、范围与版本                              |
| [`K14`](../contracts/K14-evidence-and-provenance.md)        | 候选与草稿不得被登记为已核实来源；格式整理的候选同样受此边界约束                           |

工具卡的正式定义只写在各自卡片中，本链路不复制：`T25` `doc_normalize_markdown` 的语义归属是 `M8`，其目标标为**无文件写入的变换**，不能替代内容保持验证（架构 §6.3、`G01` 已登记其目录权限分类与真实效果不符）。`T25` 的工具卡本轮尚未建立，登记位置见 [catalog.mjs](../catalog.mjs) 与缺口 `G01`。

## 状态与失败

**状态事实**：`C23`、`C24` 当前 `implementation.state=partial`，`verification.state=none`（[catalog.mjs](../catalog.mjs)）。架构将内容保持验证列为**仍需补齐的验证合同**：文本润色与风格满意度不能由确定性检查保证，格式整理则不同，`C23` 应比较保留的文本内容、顺序及链接目标等信息。

| 情形                                     | 交接处理                                                               | 依据         |
| ---------------------------------------- | ---------------------------------------------------------------------- | ------------ |
| 检查通过                                 | 报告可证明的项；允许变化集合内的变化逐项列出                           | `K16`        |
| 检查不能确定                             | 交付差异与不确定项，**不自动写入**，也不声称「内容完全未改」           | `K16`、`K15` |
| 检查失败（正文信息、顺序或链接目标改变） | 返回具体缺口，让模型修改候选或缩小结论；旧候选的验证结果不沿用到新候选 | `K16`        |
| 候选失效（目标版本漂移）                 | 要求重新生成或重新确认                                                 | `K05`        |
| 转换器只做空白规范化                     | 不能作为内容保持的证据；不得据此标记「未改内容」                       | `K16`        |

**诊断归属**：格式整理改变内容按 `C24` → `C23` 检查原文与候选的信息差异、允许变换与验证结果（§8.5）。相关未决问题：部分确定性测试与实现可能共享同一错误假设（`Q11`），因此「有测试」不等于内容保持合同成立。

## 证据要求

本链路不新增判据；判据的正式定义在 [testing/evidence.md](../testing/evidence.md) 与 [acceptance-matrix.md](../testing/acceptance-matrix.md)。

| 判据  | 本链路需要它覆盖什么                                                                                           |
| ----- | -------------------------------------------------------------------------------------------------------------- |
| `V03` | 内容保持的**程序化差异检查**：正文信息、顺序、链接目标与允许变化集合的逐项核对（`N04` 的主要覆盖方式）         |
| `V02` | 登记关联：不变量必须在登记表中找到同一口径的条目，且违例案例能在错误实现中被发现；**未补齐即表示该项尚无证据** |
| `V04` | 跨组件交接：原文保存 → 候选 → 核对 → 差异交付 → 确认 → 写入，含版本漂移路径                                    |
| `V06` | 语义质量：需要人类判断的部分（例如结构是否真的改善）与机械核对分列，不互相冒充                                 |
| `V07` | 用户可见表达：不确定项与限制说明如实呈现，不显示为「已完全保持」                                               |

判据登记中与本链路相关的任务判据是「格式整理不改实际内容（序号按允许处理）」；该判据**还没有组成最终发布门槛**（讨论十五）。本体系本轮没有执行任何新实验。

## 不做的事

- 不重复定义 `K01`、`K05`、`K14`、`K15`、`K16` 的合同正文，也不为 `C23`／`C24` 写第二份组件定义。
- 不声称内容保持已经实现或有验证结论：本文件只固定交接顺序与不确定时的交接要求。
- **不机械忽略所有空白、标点或数字**；也不把「忽略空白后一致」当作内容保持的证据。
- 不在检查不能确定时自动写入，也不用流畅文字代替未满足的要求。
- 不设定新的数值门槛（差异比例、允许变化条数等），也不承载版本排期；排期见 [ROADMAP.md](../../ROADMAP.md)。
- 不引用 [archive/](../archive/2026-09-15-pre-reform/MANIFEST.md) 中的归档材料作为依据。
