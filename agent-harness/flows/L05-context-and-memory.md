# L05 上下文与记忆链路

<!-- iris:object L05 kind=rules file=true -->

本链路说明**交接顺序**：谁在什么时候把什么交给谁。它**不重复定义**合同（K*）、组件（C*）或工具（T\*）的正式定义，只引用它们。对象身份与标记规则见 [objects.md](../rules/objects.md)，权威边界与状态语义见 [governance.md](../rules/governance.md)；上位依据是 [Agent 架构定义](../../docs/agent-architecture.md) §7.4 与讨论纪要第十二节，当前实现事实以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 的 Agent Run 一节为准。

本链路只写交接顺序，不把长对话连续性写成已经保证：**摘要覆盖与真实裁剪边界不同源**是已登记的待证事项（`Q08`／`G05`），长期记忆的写入时机、有效期、冲突与用户管理**尚未确定**（`Q15`）。

## 步骤与交接

| #   | 触发者 → 组件                  | 交付物                                                                                       | 引用合同            |
| --- | ------------------------------ | -------------------------------------------------------------------------------------------- | ------------------- |
| 1   | 运行身份与修订号 → `C07`       | 当前指令、授权材料、观察、技能方法与稳定指令的装配输入；进入上下文的事实必须带来源与时间身份 | `K01`、`K03`、`K07` |
| 2   | `C07` → `C08`                  | **实际裁剪边界**：本轮因规模约束真正被排除在上下文之外的区间                                 | `K07`               |
| 3   | `C08` → 摘要与工作状态         | 使用实际裁剪边界压缩历史，输出覆盖终点、缺口标记与任务状态（待办／撤回／已完成）             | `K07`、`K08`        |
| 4   | `C08` → `C07`                  | 摘要覆盖与任务状态回装本轮上下文；`C07` 为稳定指令和最新纠正保留空间                         | `K07`、`K08`        |
| 5   | 材料需要复用时 → `C22` → `C21` | 会话摘要**不复制完整网页证据**；需要时按来源身份重新加载获准内容并检查时效                   | `K08`               |
| 6   | `C09` → `C07`                  | 获准作用域的长期条目（偏好／事实）与变更回执；已保存偏好可在获准作用域自动取用               | `K08`               |
| 7   | 后续用户指令 → `C03`           | 输入修订；`C03` 在**模型／工具交接安全点**协调模型与工具，`C07` 把纠正置于当前约束           | `K03`               |
| 8   | `C03` → `C25`                  | 修订号与失效事实：`C25` **不发布已失效版本的最终答案**                                       | `K03`               |

**必须保留的语义**：`C08` 压缩时至少保留**当前目标、用户最新纠正、执行回执及未决项**（架构 §7.4；讨论十二还列出已撤回信息、已经执行的动作与证据时效）。失败不能压成成功，旧纠正不能覆盖新纠正；摘要与当前任务状态可由系统维护，但**不能修改真实动作结果**。

**旧观察不得升级**：被裁剪或被摘要覆盖的旧观察仍是旧观察。需要重新使用时按来源身份重新加载获准内容并检查时效（第 5 步），不把摘要改称新证据，也不把长期事实自动当作当前网页证据。

**长期记忆的边界**：`C09` 与聊天摘要分离，同作用域保留更新关系；持久修改沿用户确认合同，**默认不把任意聊天内容自动写成长期事实**；写入副作用由 `C06` 授权执行。读写工具 `T13` `memory_read` 与 `T14` `memory_write` 的正式定义只在各自卡片中（见 [tools/memory_read.md](../tools/memory_read.md)、[tools/memory_write.md](../tools/memory_write.md)）。

## 状态与失败

**状态事实**：`M03` 与 `C08` 当前 `implementation.state=partial`，`C07`、`C09` 为 `present`，全部 `verification.state=none`（[catalog.mjs](../catalog.mjs)）。这只描述源码事实。

| 情形                     | 交接处理                                                   | 依据         |
| ------------------------ | ---------------------------------------------------------- | ------------ |
| 覆盖不完整               | 如实标注缺口，不静默丢失；**发现缺口与补齐缺口是不同能力** | `Q08`、`K08` |
| 裁剪边界与覆盖终点不同源 | 少量长消息可能先被裁剪但尚未进入摘要覆盖范围；如实报告缺口 | `Q08`、`G05` |
| 压缩请求失败             | 保留原历史区间与既有摘要，不静默丢弃                       | `K08`        |
| 修订在运行中到达         | 在模型／工具交接安全点吸收；迟到结果保留为旧修订观察       | `K03`、`Q16` |
| 长期条目作用域冲突或失效 | 报告冲突事实与当前作用域，不自动合并或覆盖                 | `K08`、`Q15` |
| 材料已删除或授权已撤回   | 如实说明不可核验，不默认成功，也不删除历史事实             | `K14`        |

**进程级恢复的边界**：本链路**不承诺普通研究 Run 在进程重启后从任意中间点续跑**；只保留已有安全会话恢复与受限变更检查点语义。只有 Durable Run 具有暂停与检查点语义，重启只恢复未执行后缀。未来扩大执行恢复能力需单独明确，不隐藏在「有记忆」这一名称里。

**诊断归属**：追问遗漏最新纠正按 `C03` → `C07` → `C11` 检查（§8.5）；上下文进入网关前后缺少边界证据是缺口（`G04`、`Q09`）。纪要第十二节的「收紧联网次数会加速裁剪」是**已撤回的推论**，不得作为因果方向使用。

## 证据要求

本链路不新增判据；判据的正式定义在 [testing/evidence.md](../testing/evidence.md) 与 [acceptance-matrix.md](../testing/acceptance-matrix.md)。

| 判据  | 本链路需要它覆盖什么                                                                                                         |
| ----- | ---------------------------------------------------------------------------------------------------------------------------- |
| `V04` | 跨组件交接：装配 → 裁剪 → 压缩 → 回装 → 长期条目 → 修订吸收，以及材料按来源身份重新加载                                      |
| `V02` | 登记要求「被裁剪区间必须有可解释的覆盖或缺口」与「摘要不得覆盖用户后来的纠正」与本链路同一口径；**未补齐即表示该项尚无证据** |
| `V06` | 语义质量：追问能否承接最新约束；**用户自然表达的追问案例，不能用「请联网核实」类显式指令代替**                               |
| `V07` | 用户可见表达与状态投影：失效版本不被发布，恢复过程不堆进正文                                                                 |
| `V08` | 诊断可定位性：覆盖终点、实际裁剪边界与上下文进入网关前后的关联可查（`Q18`、`G04`）                                           |

本体系本轮没有执行任何新实验；引用判据不表示本链路已通过验收。

## 不做的事

- 不重复定义 `K02`、`K03`、`K07`、`K08`、`K14`、`K15` 与 `T10`／`T13`／`T14` 的合同正文，也不为 `C07`–`C09` 写第二份组件定义。
- 不把「保存了聊天记录」当作「模型本轮实际收到了什么」；后者是覆盖事实。
- 不把摘要、长期条目或压缩结果当作真实动作结果的改写权。
- 不承诺普通 Run 的进程级续跑，也不把任务状态写成模型私有推理。
- 不设定新的数值门槛（历史条数、token 预算、有效期数值），也不承载版本排期；排期见 [ROADMAP.md](../../ROADMAP.md)。
- 不替尚未确定的交互定案：长期记忆的写入时机、有效期、冲突处理与用户管理（`Q15`）、运行中补充要求的具体交互（`Q16`）不在本链路内确定。
- 不引用 [archive/](../archive/2026-09-15-pre-reform/MANIFEST.md) 中的归档材料作为依据。
