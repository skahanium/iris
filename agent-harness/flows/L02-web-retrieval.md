# L02 联网检索与核实链路

<!-- iris:object L02 kind=rules file=true -->

本链路说明**交接顺序**：谁在什么时候把什么交给谁。它**不重复定义**合同（K*）、组件（C*）或工具（T\*）的正式定义，只引用它们。对象身份与标记规则见 [objects.md](../rules/objects.md)，权威边界与状态语义见 [governance.md](../rules/governance.md)；上位依据是 [Agent 架构定义](../../docs/agent-architecture.md) §5 的八步与 §5.1 的配置合同，当前实现事实以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 的「搜索、联网与 Skills」一节为准。

**先说明本链路的事实边界**：`C20` 协调器已接入生产 `web_search`（`implementation.state=partial`）。原生可达性与适配器登记见 [K12](../contracts/K12-native-search-subrequest.md) 执行事实；未登记模型 MCP 单路是正常配置。**双路尚未接通**（`G02` 仍 open，见 [open-items.md](../requirements/open-items.md)）；服务端搜索事件与引用尚未完整进入网关处理路径（`G03`）；原生端点、混合续轮、费用与权限适配**待验证**（`Q17`）。本体系**不宣布** MiniMax、DeepSeek 或 Gemini 任一端点已通过。本文件定义交接顺序，不代表双路已经接通。机械 `V03` 不是 `V04`。

## 步骤与交接

下面八步对应架构 §5 的目标顺序；每一步的交出方、接收组件与交付物如下。

**1. 主模型提出查询 → `C16` 工具面 → `T11`**

主模型理解问题后提出 `web_search(query)`。纯润色、提供材料内的格式整理等**不因联网开关打开就自动搜索**；一旦执行新的网页搜索，双路合同生效。查询语义只由模型提出，Host 不得用关键词规则替模型编造或改写查询（可恢复错误表见 `K16`，语义判断边界见 `K14`）。明确需要当前核实但没有实际观察的答案，由 `C23` 返回缺口，`C14` 让模型继续行动。

**2. `C04` 授权 → `C20` 冻结路线 → `C13` 申领额度**

`C04` 检查联网开关与查询外发权限，输出 allow／deny／need-confirmation 与原因；联网开关是 `web.search` 的唯一授权源，关闭时原生搜索、MCP 搜索、抓取及其重试都不可达。`C20` 根据 `C10` 给出的具体模型／端点能力**冻结路线**，并从 `C13` 申领资源。外发资料边界与双路要求冲突时，**先满足已授权的数据边界**（`N13`）。

**3. 两路分别执行**

MCP 路线经 `C18`（`K18`）调用选定搜索服务；原生路线经 `C11` 的协议与续轮适配发起**仅携带获准查询和必要公共范围**的独立原生搜索请求（`K12`），不转发整段私有笔记上下文。原生路线向 `C13` 申领额度，纳入顶层总消耗，不形成第二本账。

**4. 并发与执行证据**

两路独立时默认并发；供应商或执行约束需要串行时仍执行两路，并记录实际时间。执行证据只接受**供应商定义的实际搜索事件**或**能证明检索发生的结构化 grounding 元数据**：单纯发出带工具声明的请求、模型自行生成 URL，都不算已搜。

**5. 原生凭据不足的表达**

原生返回只有生成文字、没有可核实的检索凭据时，记录**协议／结果不足**；在预算内允许有依据的恢复，不能伪造「原生已成功」，也不能悄悄归成「模型不支持」。原生不支持时 MCP 单路是正常配置。

**6. `C20` 合并线索 → `C22` 登记 → 主模型判断相关性**

`C20` 合并 URL、保留渠道来源与各自状态；**相同 URL 不算两个独立信源**。`C22` 保存线索与来源身份。主模型判断相关性、矛盾与阅读需求，调用 `web_fetch(urls, startChar)`；两路发现的 URL 都可直接读取，不要求先出现在本 Run 的候选集中，也无需先重搜（`N08`）。

**7. `C21` 读取与窗口**

`C21` 默认使用已配置 MCP 提取，并保留当前获准的安全抓取回退；可批量抓取，URL 安全校验不可绕过，部分失败保留成功页面。搜索与抓取故障**分别记录**；正文不足时返回阅读窗口与完整性，不能把摘要包装成完整抓取。

**8. `C23` 核实条件 → 主模型综合 → `C25` 发布**

`C23` 检查引用身份与应满足的核实条件；主模型综合事实，`C25` 发布答案与必要限制说明。所有可用路径失败或证据不足时如实说明无法完成当前核实（`N11`），不用流畅文字掩盖证据不足，也不用「模型能力降级」概括工具调用错误（`N17`）。

**路线状态与动作身份**：`C20` 的逻辑结果包含请求身份、各路线的 `supported`／`attempted`／`succeeded`／`failed`、候选来源、用量与不足说明。查询修改形成**新的搜索动作**；同修订内成功的同一动作可以复用，但复用必须指向真实观察与时间，不能算作新的联网执行。

## 状态与失败

| 情形                    | 合法表达与交接                                                                     | 依据                |
| ----------------------- | ---------------------------------------------------------------------------------- | ------------------- |
| 原生不支持              | MCP 单路是**正常配置**，不显示能力降级；真实证据不足仍须说明（状态表第一行）       | `K11`、`N09`、`K15` |
| 原生临时失败而 MCP 足够 | 保留 MCP 真实结果；诊断保留真实失败，不强行警告（状态表第二行）                    | `K11`、`N10`        |
| MCP 失败                | 保留原生真实结果；抓取是否可用单独判断，不能由搜索失败推断抓取失败（状态表第三行） | `K11`、`N10`        |
| 两路均失败或证据不足    | 如实说明无法完成当前核实，不用单路结果冒充双路完成（状态表第四行）                 | `K11`、`N11`        |
| 预算不足以启动两条路线  | 说明本次限制；`supported=true` 而 `attempted=false` 是允许表达但**不构成合规执行** | `K06`、`K11`        |
| 联网关闭                | 预期限制与控制结果，不是程序错误：不重试、不降级提示，也不以替代路径执行           | `K09`               |
| 抓取部分失败            | 保留成功页面，失败项按原因重试或用获准回退；不重新抓取已成功页面                   | `K13`、`K16`        |

**当前实现状态**：`C20` 为 `partial`；`C21`、`C22`、`C19` 为 `present`；`M07` 为 `partial`；相关对象 `verification.state=none`。`T11` 为 `partial`、`T12` 为 `present`（[catalog.mjs](../catalog.mjs)）。这些只描述源码事实，不代表合同正确或用户任务可用。`G02` 仍 open。

**诊断归属**：两路只执行了一路检查 `C10` → `C20` → `C12`／`C18`；抓取成功但没有正文检查 `C18` → `C21` → `C22`（§8.5）。诊断关联不完整（记录动作不等于还原因果）仍是缺口（`G04`、`Q09`）。配置侧：两个设置入口的 MCP 候选写入语义（`Q02`／`F01`）已关闭；主服务入口走 `web_search_route_promote`（[`mcp_runtime_registry.rs`](../../src-tauri/src/ai_runtime/mcp_runtime_registry.rs)）。`Q05`／`F04` 的 list 写库落点见 `Q05`（`058366ea`），关闭仍在 `D04`。本链路不替它们下结论。

**触发范围未单独确认**：双路合同对纯编辑任务的触发范围尚未单独确认（`Q14`），且不得据此把双路要求退回「两路可选」。

## 证据要求

本链路不新增判据；判据的正式定义在 [testing/evidence.md](../testing/evidence.md) 与 [acceptance-matrix.md](../testing/acceptance-matrix.md)。

| 判据  | 本链路需要它覆盖什么                                                                                                 |
| ----- | -------------------------------------------------------------------------------------------------------------------- |
| `V04` | 生产入口的两路执行证据（`G02` 所需证据）、无原生时正常单路、以及搜索 → 抓取 → 登记 → 终局引用的来源绑定              |
| `V05` | 逐端点的协议测试加对应端点真实调用（`Q17`、`G03`）；该证据只能证明检索发生与结果接入，不能证明来源彼此独立或内容正确 |
| `V03` | 局部机械不变量：片段不得升级为证据、`Wn` 生成条件、同 URL 去重、`evidence_refs_json` 的显式空数组语义                |
| `V06` | 语义质量：来源是否真正支持结论、来源冲突是否被如实呈现（自动评价只作辅助并须人工抽检）                               |
| `V07` | 诊断可定位性：路线的失败与不足说明可见，且不显示成「能力降级」                                                       |
| `V02` | 登记关联：已登记条目「搜索片段不能升级为正文证据」（检测位置 `C22`）与本链路同一口径；**未补齐即表示该项尚无证据**   |

**仅验证后端两个替身都被调用，不足以声明双路能力已接通**（§5.1）。live 探针不是 `V05`，也不关闭 `G02`／`G03`。
