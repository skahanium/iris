# L03 编辑与候选应用链路

<!-- iris:object L03 kind=rules file=true -->

本链路说明**交接顺序**：谁在什么时候把什么交给谁。它**不重复定义**合同（K*）、组件（C*）或工具（T\*）的正式定义，只引用它们。对象身份与标记规则见 [objects.md](../rules/objects.md)，权威边界与状态语义见 [governance.md](../rules/governance.md)；上位依据是 [Agent 架构定义](../../docs/agent-architecture.md) §7.2 与 §6.2，当前实现事实以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 的 Agent Run 与数据原则两节为准。

本链路只写交接顺序，不把任一环节写成已经可用：`implementation.state` 只描述源码事实，不代表合同正确或用户任务可用。

## 步骤与交接

| #   | 触发者 → 组件              | 交付物                                                                     | 引用合同     |
| --- | -------------------------- | -------------------------------------------------------------------------- | ------------ |
| 1   | 用户选区与目标文档 → `C01` | 绑定会话、Vault、文档版本与选区的材料引用；显式授权事实不由模型推断        | `K01`        |
| 2   | `C01` → `C07`              | 当前指令与目标版本；`C07` 决定哪些内容被采用、裁剪、过期                   | `K07`        |
| 3   | `C07` → 模型网关           | **只补必要文风材料的**本轮上下文：已给出的选区与被授权材料足够时不额外装载 | `K07`        |
| 4   | 模型 → `C24`               | 候选文本与差异；生成候选**不等于**写文件                                   | `K16`        |
| 5   | `C24` → `C25`              | 候选、差异、适用范围与目标版本绑定，作为用户可见的候选呈现                 | `K14`、`K15` |
| 6   | 用户选择应用 → `C05`       | 冻结待确认的变更集：目标、内容、范围、版本与有效期                         | `K05`        |
| 7   | `C05` → `C06`              | 通过确认与版本复验的操作；只有此边界可提交 Agent 引起的副作用              | `K05`        |
| 8   | `C06` → `C25`              | 实际执行回执与部分失败；`C25` 依据回执呈现，不把模型声明当作回执           | `K15`、`K16` |

**交接顺序的两个关键点**：

- **已有授权文本足够时无需检索、也无需子 agent**（架构 §7.2）。本链路不因联网开关打开就自动触发 `L02`；需要联网材料的组合任务才交接给联网链路。
- **生成候选与实际写文件分离**（`N03`）。候选由 `C24` 产出，用户选择应用后才进入冻结与执行；按目标文件格式与文风生成的、原本不存在的内容**由用户插入**，模型不能自主落盘。

**执行边界的落点**：实际写入由 `C06` 调用已有笔记原语完成（`T15` `insert_text_at_cursor`、`T16` `replace_selection` 的语义归属是 `M2`／`M8`，实际执行由 `C06` 完成）。目标工具绑定插入点或原文范围与版本，`Apply` 类 Run 才取得 `note.apply_patch` 能力，`Draft` 效果只能提议补丁。读取目标正文与内容哈希由 `T06` `read_note` 提供。

**格式整理**：候选内容保持的核对属 `L04`；本链路只交接候选与差异，不重复 `L04` 的核对步骤。

| [`K07`](../contracts/K07-context-assembly.md)               | 第 2、3 步：只装入必要文风材料，并显式表达哪些内容被采用／裁剪／过期                               |
| [`K10`](../contracts/K10-tool-surface.md)                   | 第 3–5 步的工具可见面与派发状态：候选生成阶段的派发状态不得与写入回执混同                          |
| [`K14`](../contracts/K14-evidence-and-provenance.md)        | 第 4、5 步：草稿／候选不被登记为已核实来源；候选的适用范围可追溯                                   |
| [`K05`](../contracts/K05-authorization-and-confirmation.md) | 第 6、7 步的冻结确认与副作用提交：确认绑定目标、内容、范围、版本，已有有效授权不反复索要           |
| [`K15`](../contracts/K15-delivery-result.md)                | 第 5、8 步：候选与澄清的呈现、任务结果与 Run 生命周期分离、限制说明的门槛                          |
| [`K16`](../contracts/K16-verification-report.md)            | 第 4、8 步：候选未通过验证时返回具体缺口让模型修改候选，旧候选的验证结果不沿用到新候选             |

## 状态与失败

**状态事实**：`C05`／`C06` 属 `M02`，`C24`、`C25` 属 `M08`；`M08` 与 `C24`／`C25` 当前 `implementation.state=partial`，相关对象 `verification.state=none`（[catalog.mjs](../catalog.mjs)）。这只描述源码事实。

| 情形                   | 交接处理                                                 | 依据         |
| ---------------------- | -------------------------------------------------------- | ------------ |
| 目标版本漂移           | 候选失效，要求重新生成或重新确认；`C05` 使旧确认失效     | `K05`、`K16` |
| 差异无法确定           | 交付差异与不确定项，不自动写入                           | `K16`、`K15` |
| 写入部分失败           | 保留已执行前缀，只报告事实；不可撤销的动作不假装回滚     | `K05`、`K15` |
| 写入回执未知           | 先核实回执，不因重试造成重复变更                         | `K16`、`K05` |
| 候选未通过验证         | 返回具体缺口让模型补查或修改候选；不立即改称模型能力降级 | `K16`        |
| 无选区或目标版本取不到 | 无法完成绑定，如实说明缺什么；不私自读取缺失文档         | `K01`        |

**诊断归属**：文件发生意外修改时按 `C24` → `C05` → `C06` 检查候选、冻结范围、确认身份、版本与实际写入回执（§8.5）；「答偏了但调用都成功」不能因请求都成功就展示为质量通过。相关未决问题：运行中追加／修改指令的交互（`Q16`）会影响发布期间的交接，本文件不推定其实现。

## 证据要求

本链路不新增判据；判据的正式定义在 [testing/evidence.md](../testing/evidence.md) 与 [acceptance-matrix.md](../testing/acceptance-matrix.md)。

| 判据  | 本链路需要它覆盖什么                                                                                                        |
| ----- | --------------------------------------------------------------------------------------------------------------------------- |
| `V04` | 跨组件交接：绑定 → 候选 → 呈现 → 确认 → 冻结 → 写入回执，含版本漂移与取消路径                                               |
| `V02` | 已登记不变量「冻结确认绑定目标与版本」（检测位置 `C05`／`C06`）以本链路的候选与版本绑定为输入；**未补齐即表示该项尚无证据** |
| `V06` | 语义质量：润色是否符合对象、长度与明确偏好；生成内容是否适合目标位置与文风（这类质量不能由确定性检查保证）                  |
| `V07` | 用户可见表达：候选、澄清与限制说明的分类，以及不出现不应有的降级提示                                                        |
| `V03` | 局部机械不变量：参数与范围的拒绝条件（例如插入点必须为空范围、替换必须给出范围内完全一致的原文）                            |

本体系本轮没有执行任何新实验；引用判据不表示本链路已通过验收。

## 需求覆盖

| 需求                                                           | 本链路的承接内容                                                            | 主要组件            |
| -------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------- |
| `N02` 字词／句段润色、扩写、缩写；对象可能是字词、单句或一段   | 第 1–5 步：范围以字节区间精确表达，候选作为用户可见结果呈现                 | `C24`、`C05`、`C06` |
| `N03` 按目标文件格式与文风生成原本不存在的内容，**由用户插入** | 第 4–8 步：候选生成与文件执行分离，应用是用户动作，`C06` 只执行已确认的操作 | `C24`、`T15`、`T16` |

需求条目的正式定义在 [requirements.md](../requirements/requirements.md)，本文件不复制其正文。

## 不做的事

- 不重复定义 `K01`、`K05`、`K07`、`K10`、`K14`、`K15`、`K16` 与 `T15`／`T16` 的合同正文，也不新增「润色」「扩写」「缩写」「写入候选」等独立工具。
- 不把生成候选写成写文件；也不把模型的完成声明落为文件回执。
- 不设定新的数值门槛（候选数量、差异大小、确认有效期数值），也不承载版本排期。
- 不宣称编辑路径「已修复」或「已验证通过」；差异确认与独立撤销的集成状态以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 与 [open-items.md](../requirements/open-items.md) 为准。
- 不在本链路的范围之外触发检索或子 agent：已有授权文本足够时无需检索（架构 §7.2）。
- 不引用 [archive/](../archive/2026-09-15-pre-reform/MANIFEST.md) 中的归档材料作为依据。
