# L06 委派链路

<!-- iris:object L06 kind=rules file=true -->

本链路说明**交接顺序**：谁在什么时候把什么交给谁。它**不重复定义**合同（K*）、组件（C*）或工具（T\*）的正式定义，只引用它们。对象身份与标记规则见 [objects.md](../rules/objects.md)，权威边界与状态语义见 [governance.md](../rules/governance.md)；上位依据是 [Agent 架构定义](../../docs/agent-architecture.md) §7.5、§6.3 与讨论纪要第十六节。

本链路只写交接顺序。子 agent 在当前实现中是**受限可选能力**：`spawn_subagent`（`T31`）的 `context_hint` 与 `max_rounds` 存在声明与执行不一致（`Q06`），子工具缺少标准网页正文抓取（`Q07`），委派收益尚未通过对照验证。这些是已知缺口，不是本文件能解决的结论。

## 步骤与交接

| #   | 触发者 → 组件                | 交付物                                                                                     | 引用合同            |
| --- | ---------------------------- | ------------------------------------------------------------------------------------------ | ------------------- |
| 1   | 主模型提议 → `C15`           | 独立任务描述、上下文引用与父级授权、额度；`C15` 判定该任务是否属于「独立阅读或分析」类委派 | `K10`               |
| 2   | `C13` → `C15`                | **从父级总资源中显式分配的额度**；父子层级明细与顶层总消耗同时保留                         | `K06`               |
| 3   | `C15` → 子运行               | 上下文引用、工具面与额度：使用 `M3`–`M8` 同样的合同，不复制一套内核                        | `K10`、`K06`        |
| 4   | 子运行内需要检索时 → `C20`   | 父级获准联网且子任务需要搜索时，**同样经过 `C20`**；子任务不能绕过原生／MCP 策略           | `K09`、`K11`、`K12` |
| 5   | 子运行 → `C16`／`C17`        | 子工具面的可见集合与派发状态；子工具缺失项按 `Q07` 登记，不由本链路放宽                    | `K10`               |
| 6   | 子运行 → `C15`               | 带来源的报告：实际来源、未解决问题与用量                                                   | `K14`               |
| 7   | `C15` → 父级（`C14`／`C25`） | 报告与用量；**父级综合前检查报告来源、缺口与用量**                                         | `K14`、`K15`        |
| 8   | 父级 → `C23` → `C25`         | 综合后的候选结论进入验证与发布；不因「由另一个 agent 得出」就视作独立事实                  | `K16`、`K15`        |

**四条硬性边界**（架构 §3 `C15` 的不变量）：

- **一层委派**：子运行不再向下委派；`C15` 不复制一套内核。
- **只读**：委派不带来写入能力，方法指导不增加权限，委派不绕过联网或文件限制。
- **授权交集**：子任务的授权是父级授权的交集；子任务不能自行增权，`max_rounds` 只能收窄 `C13` 分配的上限。
- **预算显式分配**：子运行按子策略运行，不能自行扩大；额度只有一个权威账本，不存在每层各算一套总账。

**报告不是最终事实**：子报告必须返回实际来源、未解决问题与用量；父级综合前检查这三项。子运行失败或被取消时报告事实与已取得材料，不把子报告升级为最终事实。

## 状态与失败

**状态事实**：`C15` 当前 `implementation.state=partial`、`verification.state=none`（[catalog.mjs](../catalog.mjs)）。这只是源码事实，不代表委派可用或有收益。

| 情形                                         | 交接处理                                                                       | 依据                             |
| -------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------- |
| 子运行失败或被取消                           | 报告事实与已取得材料；不把子报告升级为最终事实，不因失败立即改称模型能力降级   | `K16`、`K15`                     |
| 报告无法绑定来源或无法回溯用量               | 停止扩大委派范围，回到既有证据口径                                             | `K14`、`K16`（`D06` 的回退条件） |
| 参数未被消费（`context_hint`、`max_rounds`） | 已知接口合同缺陷；收清合同可能意味着实现这些参数，或明确移除／限制不支持的参数 | `Q06`、`K10`                     |
| 子工具缺少标准 `web_fetch`                   | 限制标准网页正文核验；本地读取工具仍存在，不能据此否定本地阅读与独立分析的价值 | `Q07`、`K13`                     |
| 报告置信度固定填 50／75                      | 不是校准后的准确概率；应取消固定伪置信概率并按真实来源与用量表达               | `Q06`                            |
| 预算调整破坏旧 Run 存档读取                  | 回退到受控配置并保留原策略版本                                                 | `Q13`、`D06` 的回退条件          |

**诊断归属**：父子任务在诊断中分别可见（§8.3）；父子预算归属需做到父级总消耗、子级分配、重叠与遗漏均为 0。诊断关联不完整（重试与父子任务关联不完整）仍是缺口（`G04`、`Q09`）。

## 证据要求

本链路不新增判据；判据的正式定义在 [testing/evidence.md](../testing/evidence.md) 与 [acceptance-matrix.md](../testing/acceptance-matrix.md)。

| 判据  | 本链路需要它覆盖什么                                                                                  |
| ----- | ----------------------------------------------------------------------------------------------------- |
| `V04` | 跨组件交接：委派分配 → 子运行工具面与额度 → 带来源报告 → 父级综合，含取消失败路径                     |
| `V06` | 语义质量与对照：单 agent／子 agent 对照须说明模型、任务、总成本、耗时与上下文条件，不能只比较回答长度 |
| `V05` | 部分适用：子任务内原生搜索的端点适配证据（`Q17`、`G03`），不能凭厂商名判定                            |
| `V07` | 用户可见表达：委派失败与受限的说明，且不出现不应有的降级提示                                          |
| `V08` | 诊断可定位性：父子任务、重试分支与预算归属可关联（`Q09`）                                             |
| `V02` | 登记关联：本链路涉及的不变量须与登记表同一口径；**未补齐即表示该项尚无证据**                          |

`Q06` 所需证据是「参数消费或明确拒绝的合同实现，以及子任务报告的真实来源、未解决问题与用量」；`Q07` 所需证据是「子任务获准使用 `web_fetch` 后的对照结果与总成本、耗时记录」（架构 §8.6 要求对照报告分开呈现首试成功率、最终完成率、额外耗时与调用成本、错误提示误报、越权或重复副作用）。本体系本轮没有执行任何新实验；模型与预算对照、子 agent 对照都**没有实验设计，也没有实验入口**。

## 不做的事

- 不重复定义 `K06`、`K09`–`K16` 与 `spawn_subagent` 的合同正文，也不为 `C15` 写第二份组件定义。
- 不把多 agent 设为默认架构，也不因受限实现的失败否定整个思路；委派保留为受限可选能力，不扩展到普通任务。
- 不声称委派有收益：收益需通过说明模型、任务、总成本与上下文条件的对照验证。
- 不把「由另一个 agent 得出」当作独立事实或独立性证据。
- 不新增数值门槛（子任务数、轮次、额度、置信度百分比），也不承载版本排期；排期见 [ROADMAP.md](../../ROADMAP.md)。
- 不把未执行的对照实验写成施工安排：换模型可能同时改变协议适配、工具调用习惯与输出结构。
- 不引用 [archive/](../archive/2026-09-15-pre-reform/MANIFEST.md) 中的归档材料作为依据。
