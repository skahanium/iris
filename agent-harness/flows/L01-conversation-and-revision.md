# L01 对话与修订链路

<!-- iris:object L01 kind=rules file=true -->

本链路说明**交接顺序**：谁在什么时候把什么交给谁。它**不重复定义**合同（K*）、组件（C*）或工具（T\*）的正式定义，只引用它们。链路的对象身份与标记规则见 [objects.md](../rules/objects.md)，权威边界与状态语义见 [governance.md](../rules/governance.md)；上位依据是 [Agent 架构定义](../../docs/agent-architecture.md) §7.1 与 §7.4，当前实现事实以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 的 Agent Run 一节为准，版本排期唯一来源是 [ROADMAP.md](../../ROADMAP.md)。

本文件只写交接顺序与失败归属，不把任一环节写成已经可用：`implementation.state` 只描述源码事实，不代表合同正确或用户任务可用。

## 步骤与交接

下表是对话与修订链路的交接顺序。触发者 → 接收组件的每一行都对应一条既有合同；本文件不复制这些合同的正文。

| #   | 触发者 → 组件                           | 交付物                                                                                                   | 引用合同            |
| --- | --------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------- |
| 1   | 用户消息／选区／目标文档 → `C01`        | 请求身份与材料引用（会话、Vault、文档版本、选区、明确操作、幂等键）                                      | `K01`               |
| 2   | `C01` → `C02`                           | 接受事件；Run 在 accepted 后持久化，再进入策略、上下文与路由调度                                         | `K02`               |
| 3   | `C02` → `C07`                           | 运行身份、修订号与已接受的输入                                                                           | `K01`、`K03`、`K07` |
| 4   | `C07` → 模型网关                        | 本轮上下文：当前日期、地区约束与前文的采用／裁剪／过期清单                                               | `K07`               |
| 5   | `C01`／`C07` → `C16`                    | 任务类型与场景；由 `C16` 组装版本化工具面，`C17` 只申领并回报派发状态                                    | `K10`               |
| 6a  | 团队寒暄等无外部事实需求的轮次          | **可零工具回答**：纯寒暄可以在有工具的路由中零调用完成，不要求先调用工具，也不把自然对话误锁进无工具模式 | `K15`               |
| 6b  | 时间类问题 → `T01` `system_time_now`    | 本机当前日期、时间、星期与时区；单位是时钟读取，不需要联网                                               | `K10`               |
| 6c  | 需要外部事实或当前核实 → 联网链路       | 交接给 `L02` 的搜索与抓取步骤；检索结果仍由主模型判断相关性                                              | `K10`               |
| 7   | `C25` ← 验证报告、结束原因、执行回执    | 回答、候选、澄清或限制说明；任务结果与 Run 生命周期分别表达                                              | `K02`、`K15`        |
| 8   | 后续用户指令（追问、纠正、取消）→ `C03` | 带修订号的待处理输入或停止信号；修订挂在同一 Run 上，不新建请求身份                                      | `K03`               |
| 9   | `C03` → `C07`                           | 在当前约束中把最新纠正置于优先位置；迟到结果保留为旧修订观察                                             | `K03`、`K07`        |

**纠正与旧观察的分界**：用户纠正地区或片名时，`C03` 只增加输入修订（在模型／工具交接安全点吸收），`C07` 把纠正置于当前约束，旧地区材料仍是**旧观察**。摘要覆盖与覆盖清单（`K08`、`K07`）记录「被采用／被裁剪／已过期」，不把旧观察改称新地区的证据，也不改写真实工具状态。需求侧依据见 `N01`、`N05`（[requirements.md](../requirements/requirements.md)）。

**长对话的相邻交接**：压缩覆盖、任务状态与长期条目属 `L05`，本链路只交接修订与纠正；本节不重复 `L05` 的步骤。

## 引用合同

| 合同                                               | 为什么本链路需要它                                                                                 |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| [`K01`](../contracts/K01-request-identity.md)      | 请求身份与材料引用的字段构成：会话、Vault、文档版本、选区、幂等键与既有授权事实，第 1 步全部依赖它 |
| [`K02`](../contracts/K02-run-lifecycle.md)         | 决定「运行结束了」与「用户任务完成了」是两个维度，第 2、7 步不得把执行结束当作任务成功             |
| [`K03`](../contracts/K03-instruction-revision.md)  | 修订号、吸收点与迟到结果的归属，第 8、9 步的追问与纠正只在它之下成立                               |
| [`K07`](../contracts/K07-context-assembly.md)      | 本轮实际收到什么：当前日期、地区约束、最新纠正与稳定指令的空间，第 3、4、9 步的交付物由它定义      |
| [`K08`](../contracts/K08-compaction-and-memory.md) | 长对话中「当前目标、最新纠正、执行回执与未决项」如何被覆盖表达，避免摘要修改真实动作结果           |
| [`K15`](../contracts/K15-delivery-result.md)       | 回答、候选、澄清与限制说明的表达门槛，第 6a、7 步依据它决定能否零工具自然回答                      |
| [`K10`](../contracts/K10-tool-surface.md)          | 第 5、6b、6c 步的工具可见面与派发状态：未经派发的提议不写成已执行，时间与检索动作分别登记          |

工具卡的正式定义只写在各自卡片中，本链路不复制：`T01` `system_time_now`（见 [tools/system_time_now.md](../tools/system_time_now.md)）、`T02` `app_context_read`（见 [tools/app_context_read.md](../tools/app_context_read.md)）。`T11` `web_search` 与 `T12` `web_fetch` 的交接顺序在 `L02`，本链路只交接入口。

## 状态与失败

**状态事实**：`M01`（`C01` `present`、`C02` `present`、`C03` `partial`）、`M03`、`M05`、`M08` 当前 `implementation.state` 分别为 `partial`，全部相关对象 `verification.state=none`（见 [catalog.mjs](../catalog.mjs) 与各模块文件）。这只描述源码事实。

**明确缺口**：**运行中指令修订需补齐**，取消有基础（`G05`）；运行中追加／修改指令的具体交互**尚未确定**（`Q16`）。压缩覆盖终点与真实裁剪边界不同源（`Q08`）。本文件不假装这些交互已定，也不声称修订路径已经接通。

**断点归属**：失败时 `M09` 应能指出**查询范围、两路执行、正文阅读、协议续轮或最后发布**中的具体断点（架构 §7.1）。这些断点分别有可检查的实际交接：

| 现象                         | 直接检查的交接               | 依据                                                 |
| ---------------------------- | ---------------------------- | ---------------------------------------------------- |
| 追问遗漏最新纠正             | `C03` → `C07` → `C11`        | 修订、上下文覆盖、出站消息结构（§8.5）               |
| 两路只执行了一路             | `C10` → `C20` → `C12`／`C18` | 能力状态、资源预留、真实原生事件与 MCP 请求（§8.5）  |
| 抓取成功但没有正文           | `C18` → `C21` → `C22`        | 传输成功、正文校验与阅读窗口分开记录（§8.5）         |
| 流式终止原因丢失（协议续轮） | `C11` → `C23`／`C14`         | Chat Completions 分支未消费 `finish_reason`（`Q04`） |
| 只剩「能力降级」             | `C12`／`C18`／`C23` → `C25`  | 原始错误类别未被合并成一句降级说明（§8.5、`N17`）    |

诊断本身的可定位性仍是缺口：`C26` 已记录出站结构见证与完整循环事件，但 `C27` 查询视图与 `V07` 演练未做，不得把记录存在当成诊断可用（`G04`、`Q09`、`Q18`）。

## 证据要求

本链路不新增判据；判据的正式定义在 [testing/evidence.md](../testing/evidence.md) 与 [acceptance-matrix.md](../testing/acceptance-matrix.md)，此处只登记本链路需要哪一类证据：

| 判据  | 本链路需要它覆盖什么                                                                                                           |
| ----- | ------------------------------------------------------------------------------------------------------------------------------ |
| `V04` | 跨组件交接：用户提交 → 绑定 → 上下文 → 工具／回答 → 交付，以及修订到来后的重新交接                                             |
| `V06` | 语义质量：话题切换、指代承接、追问是否真的接住最新约束（`N05` 需要用户自然表达的追问案例，不能用「请联网核实」类显式指令代替） |
| `V07` | 用户可见表达：限制说明与任务结果分类，不因一条已恢复的工具错误提示模型能力降级（`N17`）                                        |
| `V08` | 诊断可定位性：上述断点能落到模块 → 组件 → 调用实例，且出站结构证据可关联（`Q18`、`G04`）                                       |
| `V02` | 登记关联：本链路涉及的不变量须在登记表中找到同一口径的条目；**未补齐即表示该项尚无证据**                                       |

本体系本轮没有执行任何新实验；引用判据不表示本链路已通过验收，也不表示用户任务可用。

## 不做的事

- 不重复定义 `K01`、`K02`、`K03`、`K07`、`K08`、`K15` 与 `T01`／`T02` 的合同正文，也不为 `C*` 写第二份组件定义。
- 不设定新的数值门槛（回合数、纠偏次数、容错百分比、发布分数），也不承载版本排期；排期见 [ROADMAP.md](../../ROADMAP.md)。
- 不宣称任何环节「已修复」「已验证通过」；本轮没有绑定指纹的证据记录。
- 不把未确定的交互写成设计要求：运行中补充指令的具体交互（`Q16`）、长期记忆写入时机与有效期（`Q15`）不在本链路内定案。
- 不承诺普通 Run 在进程重启后从任意中间点续跑（§7.4）；只有 Durable Run 具有暂停与检查点语义。
- 不把「保存了聊天记录」等同于「模型本轮实际收到了什么」；后者是 `K07`／`K08` 的覆盖事实。
- 不引用 [archive/](../archive/2026-09-15-pre-reform/MANIFEST.md) 中的归档材料作为依据。
