- 明确联网/核实、URL 与高利害当前事实是硬验证信号；日常时效与其他已授权联网任务为 `WebPreferred`。工具面存在时进入同一个有界循环，由模型决定是否调用。

## 4. HR-7 验收门

`agent:eval:smoke` 覆盖在线回答、20 轮连续性和关键 24/25 工具边界。`agent:eval:contract` 覆盖核心矩阵（26 个基础问题的成对变体，共 52 题）、1/20/50/100 轮连续性、查询改写、本地多跳、混合研究、来源隔离、取消/恢复及五次边界重复。矩阵规模由基础问题表派生，`CORE_MATRIX_MIN_CASES` 只设下限；覆盖只增不减。

**覆盖义务（2026-09-11 增补，属 HR-7 退出条件）**：分类器可把 Run 冻结进多个验证类，而未走到某个类的门无法对该类做出结论。实测原 48 题只落 `DefaultOnline` 与 `ExplicitWebRequest` 两类，`VolatileExternalFact`（全部日常时效问题所属类）与 `HighStakesCurrentFact`（交叉印证严格分支）零覆盖，导致生产侧严格分支 4/4 失败而确定性门全程全绿。矩阵现覆盖四类，并由 `every_gate_covers_every_verification_class` 以显式所有权表强制：每个可达验证类必须有具名门负责，`CurrentRunExternal` 由 `run_intake_tests` 承担。严格结构化终局现已端到端可驱动并作为必过用例纳入矩阵：脚本化提交正文曾带 `[W1]` 标记，而来源标记由 Run 侧校验器事后添加、提交解析器拒绝模型自填的 `[W...]`，导致提交在提取阶段即被拒；改为无标记正文后 `web_search` → `web_fetch` → `submit_final_answer` 完整走通。确定性矩阵不再暂缓任何计划进入报告门。

`agent:eval:live campaign` 在一次预检和一次成本确认后，交替执行两条独立连续会话的固定 6 Run。Campaign 的全局上限为 12 Run、96 模型轮次和 72 Web 逻辑动作；Canary 为 4 Run、32/24。最后一个额度允许执行，下一次派发必须留下 `campaign_budget_exhausted` 观察。`agent-live-pilot-v4` 仅验证终态、授权、search→fetch、Run-local 来源、引用绑定、安全、连续性和预算；每条路由生成匿名、哈希绑定的审阅包，再由人工按意图遵循、事实与来源、相关性与完整性、纠正与连续性四项逐场景评分（单项至少 4/5、总平均至少 4.2）。`agent:eval` 只有在 contract、同 Campaign 的两份 v4 轨迹和人工复核同时通过后才原子写入 `product-gate.json`；v2/v3 结果仅可诊断。

报告分别记录：合同、安全、连续性、循环轨迹、来源和真实回答质量。确定性 v2 汇总分开记录已执行、正常回答、预期安全拒绝与意外失败；预期拒绝可以通过安全合同，但不能增加正常回答或回答质量。汇总与明细不一致必须返回非零，不得留下“36/48 却成功”或“48/48”式假绿报告。

## 5. HR-8 覆盖回正与终态可见性

HR-8 不是新架构，而是**测量与终态的缺口回正**。2026-09-10 的真实会话暴露出一组相互掩盖的缺陷：严格分支 4/4 失败，而确定性门全程全绿。复核确认后者不是因为用例失败，而是**门从未走到那条分支**——原 48 题只落 `DefaultOnline` 与 `ExplicitWebRequest` 两类，`VolatileExternalFact`（全部日常时效问题所属类，也是该会话中被正常回答的全部消息）与 `HighStakesCurrentFact` 覆盖均为 0。未走到某个验证类的门无法对该类作出任何结论。

**可交付边界**

- 确定性矩阵覆盖分类器可达的每个验证类，并由显式所有权表强制：每个可达类必须有具名门负责，`CurrentRunExternal` 在确定性矩阵中结构上不可表达（请求构造冻结外部授权为空），由 `run_intake_tests` 的分类器契约门承担。
- 严格结构化终局可端到端驱动。阻塞点是脚本化提交正文带 `[W1]` 标记：来源标记由 Run 侧校验器事后添加，提交解析器拒绝模型自填标记，提交因此在提取阶段即被拒、误判为非法提交并耗尽修复轮。改为无标记提交正文后，`web_search` → `web_fetch` → `submit_final_answer` 完整走通。
- 终态一律可见。五处一次性硬错误出口（严格提交耗尽、草稿两次不完整、续写契约被违反、模型轮次被连续拒绝的提议烧尽）改为发布 Host 撰写的**有界限制说明**；严格当前证据契约的运行不发布无来源散文。真实成因保留在 `toolLoop` 诊断的 `exhausted` 事件中。
- 前端失败标记落在**用户行**。`AiMessageList` 的失败脚注只在携带 `turnState: "failed"` 的用户行下渲染；投影此前删除该 Run 的空助手槽，删掉的正是唯一能承载标记的行，使失败轮与「从未提问」无法区分。
- 地区不匹配检测。Web 观测两侧附带 `sourceDomains`（去重、小写、有序、上限 8、单域名 ≤80 字符）与常驻核对指令。Host 只陈述事实，**不携带域名到市场的映射、不携带地区词典**，市场判断仍归模型与 `## GeographicScope` 合同。
- 降级路径未登记链接处理。非严格联网运行不再发布模型自造链接：**剥离**而非拒绝整篇（拒绝会以「编造引用」换「零回复」）。自然澄清与证据受限答复排除在外，后者由 Host 撰写且刻意披露未核实线索及其 URL。
- 降级横幅文案如实：Host 按设计不约束也不包裹模型正文，文案不得声称「受约束答复」。

**同阶段删除**

暂缓计划进入报告门的 `REPORT_GATE_DEFERRED_PROMPTS` 与 `HR-8-target` 目标夹具属性随严格协议落地一并移除；`05` 不再保留任何暂缓条目。

**退出条件**

1. 一次经授权的 `agent:eval:live canary` 证明严格分支在真实模型下不再零回复，且每轮终态在转录区可见；
2. 真实检索中的地区不匹配被实际纠正，并由审阅包记录来源市场；
3. 人工四维评分达标（沿用 HR-7 门槛：单项至少 4/5、总平均至少 4.2）。

前两项之前，HR-8 只能声明「确定性层已验证」；真实层未校准前 **HR-7 继续未放行**，不得因 HR-8 的确定性回归而升级。
