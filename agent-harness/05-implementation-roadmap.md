## 1. 已收回的控制面

- `ExecutionEnvelope` 只冻结 effect、授权范围、风险、能力与预算；不冻结电影、天气、写作等解题策略。
- 明确联网、URL、强时效与高风险当前事实是硬验证信号；其他已授权联网任务为 `WebPreferred`。工具面存在时进入同一个有界循环，由模型决定是否调用。
- 旧 `conversation_meta`、创作、小说、公文、纪检等关键词不得撤销 Web 能力、改变来源终局或选择领域执行器。
- `web_prefetched` 与 Host 预取研究路径已退出新 Run；Web、本地、外部只读与 runtime 走同一 ToolLoop。

## 2. 连续对话与最终答复合同

会话仅持久化四个有界记忆字段：当前目标、约束/最新更正、已完成且经 Host/工具确认的结果、未解决事项。最近 12 对完整 user/assistant 消息保持原样；旧 assistant 文字和历史引用只能帮助指代，不能证明当前事实。

当上下文溢出时，压缩必须保留显式目标、偏好、更正、完成与待办；压缩失败不得阻断回答。当前确定性压测验证这一投影合同，不把固定 mock 当作真实模型语义能力。模型压缩、若启用，必须占用同一 Run 的冻结模型预算、至多一次、无工具，并有确定性兜底。

普通回答不走结构化终局。`WebRequired` 或已使用 Web/外部证据的自然正文必须以本 Run 的 `Wn`/`En`/`Ln`/`Mn` 来源标记归因；缺失时给同一模型一次无副作用修复机会。仍无法归因时丢弃草稿，以限制说明完成；只有持久化、权限或状态损坏才显示红色失败。`SourceGroupFallback` 仅兼容读取旧记录，不能满足新回答的事实来源要求。

INC-HR-006 只重新打开 HR-3 内的 fetch 应用合同与 HR-4 内的严格发布密封，不重开通用循环：MCP fetch 必须把应用错误、空正文和搜索包装视为失败，并在冻结 `web.fetch` 候选内切换；严格路径在来源绑定前不得发送正文或 `AnswerReset`。来源区只列最终正文实际引用且成功登记的 evidence，限制说明不得携带来源摘要。

INC-HR-007 继续在同一循环内回正真实工具闭环，不增加研究状态机：`web_search { query }` 只发现 Run-local 候选，`web_fetch { urls }` 只读取当前候选或用户明确 URL；两者共享既有授权、network 预算、Broker 与冻结 Provider 顺序。普通时效事实取得一份相关正文并精确引用即可完成；高风险、CitationCheck 或显式交叉核实才要求官方来源或两个独立域名。现代消息只按 `evidence_refs_json` 投影最终来源，显式空数组不得回挂整 Run 来源。

## 4. HR-7 验收门

`agent:eval:smoke` 覆盖在线回答、20 轮连续性和关键 24/25 工具边界。`agent:eval:contract` 覆盖 48 场景、1/20/50/100 轮连续性、查询改写、本地多跳、混合研究、来源隔离、取消/恢复及五次边界重复。

`agent:eval:live campaign` 在一次预检和一次成本确认后，交替执行两条独立连续会话的固定 6 Run。Campaign 的全局上限为 12 Run、48 模型轮次和 36 Web 业务调用；最后一个额度允许执行，下一次派发必须留下 `campaign_budget_exhausted` 观察。`agent-live-pilot-v3` 仅验证终态、授权、search→fetch、Run-local 来源、引用绑定、安全、连续性和预算；每条路由生成匿名、哈希绑定的审阅包，再由人工按意图遵循、事实与来源、相关性与完整性、纠正与连续性四项逐场景评分（单项至少 4/5、总平均至少 4.2）。`agent:eval` 只有在 contract、同 Campaign 的两份 v3 轨迹和人工复核同时通过后才原子写入 `product-gate.json`；v2 结果仅可诊断。

报告分别记录：合同、安全、连续性、循环轨迹、来源和真实回答质量。确定性 v2 汇总分开记录已执行、正常回答、预期安全拒绝与意外失败；预期拒绝可以通过安全合同，但不能增加正常回答或回答质量。汇总与明细不一致必须返回非零，不得留下“36/48 却成功”或“48/48”式假绿报告。

退出条件：所有要求回答的案例均有有效 assistant 正文；权限越界、跨 Run 来源、重复写入为零；纠正、任务切换和恢复在压缩前后保持最新约束；差工具结果能调整、选取来源并抓取正文，且在预算内停止；最终六维报告的计数与明细一致。INC-HR-007 的旧 MiniMax、MiMo 试运行不满足这些条件：MiniMax 未达到可执行态，MiMo 触发了错误的每路由预算门，旧 writer 还会在落盘前拒绝失败状态。2026-09-02 首次 INC-HR-008 v3 Campaign 又因“提议调用被误计为业务调用”和顶层预算出口未持久化报告而失败；本轮额度不重跑。修复已进入本地回归，下一次真实 Campaign 必须另行授权。因此 HR-7 仍是“实测未通过”，不得提升为已验收。
