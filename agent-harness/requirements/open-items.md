# 缺口与未决项

<!-- iris:object P05 kind=rules file=true -->

本文件登记**缺口（`G*`）**：当前实现与目标合同之间已知的差异，以及尚未确定的实现选择。缺口与未决问题（`Q*`，见 [current-baseline.md](./current-baseline.md)）的区别是：

- `Q*` 是**事实与根因尚未确定**的待证事项，需要运行证据；
- `G*` 是**已知目标未达成**的工作范围，需要工作包与验收判据。

缺口不是缺陷清单的替代品：`G*` 说明「规范要求的目标行为尚未落地」，`Q*` 说明「已观察到的现象还没有足够证据定位」。

### G01 工具目录目标与现状的差异

- **目标**：39 个内置业务工具（`T01`–`T39`），16 通用 + 23 扩展；Planned 不暴露；`conclude_reasoning` 退出目标工具面；`submit_final_answer` 保留 1 个条件式入口。
- **现状**：基线 `2670739f` 共 51 个内置目录项，其中 38 可派发、2 HarnessOnly、11 Planned。
- **差异**（2026-09-19 收口，逐项标注）：
  1. `doc_normalize_markdown` 的目录权限分类与真实效果不符——**已修**：该工具与同形状的 `doc_extract_citations` 都只返回载荷、不落盘，目录档位由写类改为 `ReadProfile`，`requires_confirmation` 由 `true` 改为 `false`（原先要求用户确认一个并不存在的副作用）。授权判定仍由按工具名的能力合同决定，`ToolAccessLevel` 只是展示元数据。
  2. `capabilities_read` 的目标合同 `request_tools` 参数需实现消费——**已实现**：参数进入 schema 并由处理器消费；命中当前 Run 工具面则回报可用，命中目录但不在本 Run 工具面则按 `capability_request_not_in_current_surface` 明确拒绝，未登记工具按 `capability_request_unknown_tool` 拒绝，非数组入参按 `capability_request_must_be_a_string_array` 拒绝；**任何情况下都不开放工具、能力或权限**。
  3. `spawn_subagent` 的 `context_hint`／`max_rounds` 未被消费——**仍 open**，归 `Q06` 与 `D06`，不随本条关闭。
- **阻断门槛**：`at=acceptance`（`D03`、`D05`）。
- **所需证据**：工具卡逐项实现状态与目录分类的一致性核对；无效参数必须明确拒绝而不是静默忽略。
- **覆盖**：`result_only_tools_do_not_declare_write_class_access`（只返回载荷的工具不得声明写类档位）、`capabilities_read_declares_the_parameters_its_dispatcher_consumes`（声明的参数必须被消费）、`capabilities_read_answers_request_tools_without_widening_the_surface`（回答询问不得扩大工具面）、`capabilities_read_rejects_a_malformed_request_tools_value`（畸形入参明确拒绝）。上述均为 `V03` 机械负例；第 3 项不在本条关闭条件内。

### G02 双路搜索协调的真实执行

- **目标**：一个 Iris 搜索接口、两条内部执行路线、共同的按需正文读取（`K11`）；原生不支持时正常单 MCP；不能伪造另一侧结果。
- **现状**：`dual_path_search.rs` 协调器已接入生产 `web_search`；生产原生按能力事实为 `unsupported`（尚无 `K12` 子请求），MCP 单路是正常配置。两路组合有机械 `V03`（注入双倍）。**这不是关闭**：生产入口两路仍缺（无真原生），不能把两个替身都被调用写成 `V04`，也不能把 MCP 主备写成双路。
- **差异**：双路尚未接通。原生搜索事件接入仍归 `G03`／`K12`。
- **阻断门槛**：`at=acceptance`（`D04`）。
- **所需证据**：生产入口的两路执行证据（`V04`）；以供应商定义的实际搜索事件或可证明检索发生的结构化 grounding 元数据作为执行证据——单纯发出带工具声明的请求、模型自行生成 URL 都不算已搜。机械覆盖不是验收。

### G03 原生搜索事件的接入与端点适配

- **目标**：原生搜索作为隔离的受控子请求接入（`K12`），结果与计费可关联；服务端搜索事件与引用完整进入网关处理路径。
- **现状**：服务端搜索事件和引用尚未完整进入现有网关处理路径；端点、混合续轮与费用适配待验证（`Q17`）。
- **差异**：原生搜索尚未作为受控子请求接入主链路。
- **阻断门槛**：`at=acceptance`（`D04`）。
- **所需证据**：逐端点的协议测试 + 对应端点真实调用（`V05`）；不得仅凭厂商名或 `OpenAI-compatible` 标签判定能力。授权前置与逐端点检查项见 [2026-09-19 V05 逐端点实网验证窗口](../../docs/eval/results/2026-09-19-v05-live-window.md)；**未获费用与端点范围批准前不运行**。
- **原生搜索的具体接入**：`K12` 要求原生搜索作为隔离的受控子请求接入。本轮**未选定**厂商侧原生搜索端点，本缺口保持 `open`；不得用「已发出带工具声明的请求」或「模型自行生成 URL」当作已接入。**本缺口是协议侧逐端点 `V05` 的承接方**（2026-09-17 关闭门槛改写：`Q04`／`Q10` 的关闭不再要求 `V05`，该证据由本缺口与 `Q17`／`D04` 承接）。`D02` 只交付机械续轮与终止原因，不关闭本缺口。

### G05 运行中输入修订与压缩覆盖一致性

- **目标**：输入修订在安全点生效（`K03`）；摘要覆盖必须与真实裁剪边界一致，被裁剪区间有可解释的覆盖或缺口（`K08`）。
- **现状**：取消有基础。运行中就地修订通道已确定不做（`Q16` 关闭：Host 在 Run 进行中拒绝新指令）；压缩覆盖终点与 token 裁剪边界不同源（`Q08` 已知限制，关闭时保留显式缺口）。
- **差异**：本缺口已关闭。关闭依据是 `Q16`「就地通道不做」加上取消后候选不得发布的证据，**不是**「运行中修订已实现」。覆盖终点与裁剪边界同源是独立改进，不在本条关闭条件内。

### G06 Host 用配方当第二规划器

- **目标**：`C14` 不再因无进展身份或两轮拒绝，在任务未完成且信封仍允许时强制 `synthesis_required`。完成额度预留触达后不提供业务工具属信封（`R12`），不得与无进展关面共用关面指令。观察之后下一步由模型提议（`R11`、`N15`、`N21`）。

### P05 正式定义

## 缺口对象要点

- **职责**：登记当前实现与目标合同之间已知的差异（`G*`），并给出阻断门槛与所需证据。
- **与 `Q*` 的分工**：`Q*` 是事实与根因待证；`G*` 是目标未达成的工作范围。
- **规则**：缺口不得被当作已完成；尚未确定的事项单独列出，不写成任务。

## 异常处理

缺口关闭必须由对应工作包的验收证据支持；只关闭一部分时保留剩余范围与门槛。
