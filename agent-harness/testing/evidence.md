# 证据体系：用途分类、不变量登记与当前适用性

本文件是证据体系的**规则与登记**：证据用途分类、不变量与反例登记、证据记录的绑定与当前适用性。它不规定某个模块怎么实现，也不替代真实验收。

核心纪律（`document.md` §4）：证据采用**用途分类及组合要求**，不采用「高级证据替代低级证据」的单一等级；未运行、空分母、不适用和失效证据不能变成必需维度的通过；模块及工作包验收由具体声明汇总，不能拿一个测试覆盖全部能力。

未绑定当前指纹的条目不得计为通过；具体状态以 `registry.json.verify` 为准。付费实网评测仍未运行。

## 一、证据用途分类

| 验收对象                         | 必需证据                               | 说明                                              |
| -------------------------------- | -------------------------------------- | ------------------------------------------------- |
| 局部机械不变量                   | 确定性正例和违例检测                   | 见 `V03`                                          |
| 跨组件交接、续轮、取消、来源绑定 | 实际组件组合或生产入口测试，含异常路径 | 见 `V04`                                          |
| 厂商端点及协议兼容               | 协议测试 + 对应端点真实调用            | 见 `V05`                                          |
| 相关性、追问承接、文风等语义质量 | 真实模型场景 + 明确判据 + 人工抽检     | 见 `V06`                                          |
| 诊断界面与交互                   | 状态投影测试 + 界面交互或人工检查      | 见 `V07`                                          |
| 完整用户任务                     | 该任务涉及的**全部**必需证据           | 见 [acceptance-matrix.md](./acceptance-matrix.md) |

跨层权限、写入等性质必须覆盖最终执行边界，不能仅凭局部校验函数通过。

### V01 正式定义

## 证据要求

证据按**用途分类**，不采用单一等级；跨层权限与写入必须覆盖最终执行边界。

| 验收对象                         | 必需证据                               |
| -------------------------------- | -------------------------------------- |
| 局部机械不变量                   | 确定性正例和违例检测                   |
| 跨组件交接、续轮、取消、来源绑定 | 实际组件组合或生产入口测试，含异常路径 |
| 厂商端点及协议兼容               | 协议测试＋对应端点真实调用             |
| 语义质量                         | 真实模型场景＋明确判据＋人工抽检       |
| 诊断界面与交互                   | 状态投影测试＋界面交互或人工检查       |
| 完整用户任务                     | 该任务涉及的全部必需证据               |

未运行、空分母、不适用和失效证据不能变成必需维度的通过。

### V08 证据记录、绑定与当前适用性

## 记录字段与适用性

每条证据记录（写入 `registry.json.verify`）必须包含：`object`（被验证对象 ID）、`kind`（`V03`–`V07`）、`testPath`、`command`、`environment`、`fingerprint`（对象当时的定义指纹）、`at`、`applicability`（`current`／`needs-review`／`obsolete`）。

绑定与适用性：

- 证据必须绑定规范、测试、源码、环境及非敏感配置版本；
- 对象指纹变化后，原记录自动降为 `needs-review`，不得据此宣称当前版本已验证；
- 未运行、空分母、不适用和失效证据不能变成必需维度的通过；
- 历史通过保留，但不足以支持变化后的当前验收；
- 模块及工作包验收由具体声明汇总，不能用一个测试覆盖全部能力。

存储位置：结论与记录在 `registry.json.verify`；执行产物沿用既有 `docs/eval/results/`，本体系不复制证据仓库。

## 消费方

`X01` 校验 `verification.state=passed` 必须有对应记录且指纹未过期；工作包验收依赖 `applicability=current` 的记录。
