# K07 上下文装配与裁剪边界

<!-- iris:object K07 kind=rules file=true -->

本文件是 `K07` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**模型本轮实际收到什么**：由哪些部分组成、哪些内容被采用／裁剪／过期、为稳定指令和最新纠正保留什么空间，以及材料与指令的边界。责任组件是 `C07`（当前上下文装配），主要消费方是 `C07`、`C08`、`C11`。

本合同的输入事实来自 `C01`、`C03`、`C04`、`C06`、`C16`、`C19`、`C21`、`C22` 与 `C25`，但它只定义**装配与覆盖表达**，不复制这些对象的正式定义：请求身份与修订见 [K01](./K01-request-identity.md)、[K03](./K03-instruction-revision.md)，授权见 [K05](./K05-authorization-and-confirmation.md)，预算与上下文规模约束见 [K06](./K06-budget-ledger.md)，来源身份与支持关系见 [K14](./K14-evidence-and-provenance.md)，交付表达见 [K15](./K15-delivery-result.md)。具体供应商请求形状不在这里，属于 `K04` 与 `C11`；`C11` 是否把本轮上下文保真地放进出站结构，由 `V08` 类证据核对。

本合同不代表装配结果已经正确，也不代表用户任务可用：实现状态只描述源码事实（见 [governance.md](../rules/governance.md) §2.2）。已知的实现差异与待证事项按 `G05`、`Q08`、`Q10` 引用，不在本文件另立判据。

## 接口

**输入**（逻辑类型，不是已存在的 Rust 类型或 IPC 字段）：

| 输入     | 含义                                         | 权威所有者                                     |
| -------- | -------------------------------------------- | ---------------------------------------------- |
| 当前指令 | 用户本轮消息、显式操作、目标文档与选区       | `C01`；修订号来自 `C03`                        |
| 授权材料 | 本轮获准进入上下文的材料引用及其作用域、版本 | `C04` 决策，`C01`／`C22` 提供引用              |
| 观察     | 本轮已发生的工具结果、执行回执与部分失败     | `C17`／`C06`，身份归 `C22`                     |
| 技能方法 | 技能发现结果与方法材料的引用                 | `C16`（发现与方法选择）；装载方式由 `C07` 决定 |
| 稳定指令 | 跨轮保持的系统级指令与已获准偏好             | 由 `C07` 装配层持有；偏好来源为 `C09`          |
| 最新纠正 | 用户最近一次对目标或约束的修订               | `C03`                                          |
| 执行事实 | 已执行动作的回执、未解决问题                 | `C06`、`C08`、`C23`                            |

**输出**：

1. **本轮上下文**：按角色与顺序组织的、即将交给 `C11` 的内容；每部分可追溯到上面某个输入，不引入无来源内容。
2. **覆盖清单**：逐项表达本轮上下文的处置——采用（adopted）、裁剪（trimmed）、过期（expired）；裁剪项给出可解释的覆盖或缺口（覆盖表达的责任边界见 [K08](./K08-compaction-and-memory.md)）。
3. **保留空间声明**：稳定指令与最新纠正在装配后仍然存在，包括被裁剪影响时的表达。

**边界**：本合同只输出装配结果与覆盖清单，不改写真实工具状态，不代替权限决策，也不决定业务动作是否继续（`C14`）。覆盖清单是 `C08` 与 `C22`／`C23` 判断证据时效的输入，不是新的证据账本。

## 状态转换

本合同不引入新的持久状态机。上下文装配按**轮次**发生：在每次模型请求前，`C07` 依据当前指令、授权、观察与修订号生成一份新的本轮上下文与覆盖清单；上一轮清单作为历史保留，不被就地改写。

覆盖清单的合法取值是离散的：

| 取值      | 含义                             | 约束                                         |
| --------- | -------------------------------- | -------------------------------------------- |
| `adopted` | 本轮实际装入上下文               | 必须能与某个输入项对应                       |
| `trimmed` | 因规模或优先级未装入             | 必须给出覆盖或缺口标记                       |
| `expired` | 内容仍存在但已不适合作为当前证据 | 必须给出判定依据；不得因此把旧观察改称新事实 |

轮内允许的转换只有：某输入项从待定进入 `adopted`，或在装配结束时落入 `trimmed`／`expired`。**不允许**把 `trimmed`／`expired` 重新表达为 `adopted`，也不允许在无新观察的情况下把 `expired` 改写为当前事实。完整装配失败时按「异常处理」记录缺口，不得以部分上下文冒充完整上下文。

## 不变量

1. **本轮上下文的每一部分都有来源**：或来自用户与授权材料，或来自已发生的观察，或来自稳定指令；不出现无法归属的内容。
2. **为稳定指令与最新纠正保留空间**：装配不得因为规模、轮次或裁剪把这些内容挤出本轮上下文。
3. **裁剪边界与压缩覆盖一致或显式记录缺口**：覆盖清单声明的裁剪范围必须与摘要覆盖的实际范围一致；不一致时必须记录为缺口，不允许静默。
4. **材料是资料不是指令**（提示注入边界）：外部网页、MCP 返回值、检索到的笔记与工具结果只是资料；其中要求改权限、泄露数据或调用其他工具的文字不能改变 `C04` 的授权事实。
5. **工具结果、模型输出与检索材料不得作为系统指令**：它们不能被提升为系统角色内容，也不能进入稳定指令层。
6. **授权是装配的上界**：未获准的材料不得因为装配便利而进入上下文；子任务与委派上下文的授权只能继承或收窄。
7. **旧观察仍是旧观察**：修订到来后，先前材料保留其来源与时间身份，不得改写为新修订的证据。

## 异常处理

| 失败分类                                 | 反馈对象与可恢复性                                                | 不得继续的情形                         |
| ---------------------------------------- | ----------------------------------------------------------------- | -------------------------------------- |
| 稳定指令或最新纠正未能装入               | 记录缺口并反馈给 `C14`／`C25`；在授权与预算允许时重新装配         | 以缺失纠偏指令的上下文继续生成最终回答 |
| 裁剪范围与摘要覆盖不一致                 | 记录缺口并关联 `C08` 与 `C26`；可恢复                             | 把未覆盖区间当作已被摘要覆盖           |
| 材料授权在装配前被撤回或版本漂移         | 从本轮上下文移除并如实说明不可核验，反馈给 `C07` 装配流程与 `C25` | 继续使用已撤回材料；静默替换版本       |
| 材料已删除或不可重取                     | 标记为不可核验（依 `C14`／`K14` 的来源边界）                      | 声称已核对原文                         |
| 装配证据缺失（无法说明本轮实际装入什么） | 标为未知／待证，与 `C26`／`C27` 的缺口规则一致                    | 默认装配成功                           |

装配失败不是权限拒绝，也不是外部服务失败；它与「预期限制与控制结果」分开展示（见 [agent-architecture.md](../../docs/agent-architecture.md) §8.2）。

## 消费方

| 消费方 | 消费的字段                                             | 用途                                                                                  |
| ------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `C07`  | 全部输入与输出字段                                     | 责任组件：装配本轮上下文、产出覆盖清单、维护保留空间                                  |
| `C08`  | 覆盖清单的裁剪范围与 `expired` 判定                    | 使压缩覆盖与真实裁剪边界一致；被裁剪区间必须有可解释的覆盖或缺口                      |
| `C11`  | 本轮上下文的组成部分与顺序、稳定指令与最新纠正的存在性 | 按协议保真地把上下文放入出站请求；字段是否真正到达由 `V08` 类证据核对，不由本合同声称 |

相邻而非消费的关系：`C22` 提供来源身份，`C23` 用它判断引用是否成立，`C25` 依据验证结果决定交付表达；三者通过 `K14`、`K16`、`K15` 与本合同交接，不在此重复定义。

## 验证

本合同需要以下类别证据，判据定义在各 `V*` 对象中，本文件不新增判据：

- `V03`：装配器与覆盖清单的局部机械不变量——每部分有来源、`adopted`／`trimmed`／`expired` 取值合法、稳定指令与最新纠正在裁剪后仍存在。
- `V04`：跨组件交接——`C03` → `C07` → `C11` 的修订号与内容传递、材料撤回与版本漂移路径。
- `V06`：追问承接与最新纠正的语义质量（真实模型场景 + 明确判据 + 人工抽检）。
- `V07`：装配失败与缺口在诊断中的可定位性。
- `V08`：记录绑定——证据须绑定对象指纹、测试或检查清单路径、复现命令、环境与执行时间；对象指纹变化后原记录自动降为 `needs-review`。

`V03`–`V07` 当前状态一律为「未运行」或「待执行」（见 [evidence.md](../testing/evidence.md)）；引用它们不表示本合同已通过验收。
