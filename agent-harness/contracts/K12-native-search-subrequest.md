# K12 原生搜索受控子请求

<!-- iris:object K12 kind=rules file=true -->

本文件是 `K12` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**原生搜索如何作为受控子请求发起**：请求里放什么、不放什么，它在语义判断中处于什么位置，结果与计费如何被关联，以及在缺少可核实检索凭据时如何表达。责任组件是 `C20`（双路网页搜索协调），主要消费方是 `C20`、`C11`、`C12`。

本合同只定义子请求本身；两条路线的协调结果与合并表达见 [K11](./K11-dual-path-search.md)，外发授权与开关见 [K09](./K09-web-authorization.md)，能力状态与路由见 [K04](./K04-provider-capability.md)，额度与费用账本见 [K06](./K06-budget-ledger.md)，来源身份见 [K14](./K14-evidence-and-provenance.md)，正文读取见 [K13](./K13-web-reading-window.md)。供应商原生工具声明不登记为业务工具（见 [objects.md](../rules/objects.md) §1.3），其协议能力经本合同管理。

**执行事实**：`K12` 构造器与凭据解析器已落地（`src-tauri/src/ai_runtime/native_search_subrequest.rs`）；生产登记 2 个适配器（MiniMax-M3 → Responses 隔离子请求；DeepSeek-Flash → Anthropic Messages 隔离子请求）。`C10` 对这两模型为 `Available`，其余模型仍为 `adapter_absent` 或 ASR／TTS `capability_absent`。生产路径会发真实 HTTPS（计费）。生产子请求仍 `stream:false`、不经 `ModelGateway`／`streaming.rs`。主对话 SSE **若夹带**搜索事件（`web_search_call`／`server_tool_use`／`url_citation`／`groundingMetadata`）则进入处理路径为 `MainStreamLeak` 凭据，不得写成 K11 原生 `succeeded`，也不得变成可执行客户端 `ToolCall`。隔离子请求凭据进入 C12 `dualPath` 与 C26 见证（不含 URL 正文、不含密钥）。关闭仍等 `V05`／`D04`。本体系**不宣布**任一端点已通过本合同（不是 `V05`）。`Available` 不是「支持且已适配」。

## 接口

**输入**：

| 输入           | 含义                                                                 | 来源                        |
| -------------- | -------------------------------------------------------------------- | --------------------------- |
| 获准查询       | 经 `C04` 判定允许外发的查询内容                                      | 主模型提议 + `C04`（`K09`） |
| 必要公共范围   | 完成本次检索所必需的公共参数（时间、地域、语言等），不含私有笔记内容 | `C20` 从本次动作构造        |
| 目标端点与协议 | 当前所选模型／端点及其协议适配版本                                   | `C10`、`C11`                |
| 额度租约       | 本次子请求可用的资源                                                 | `C13`（`K06`）              |
| 请求身份       | Run ID、输入修订号、父调用 ID、尝试 ID                               | `C01`／`C03`                |

**输出**：

1. **子请求结果**：供应商返回的文本、结构化检索事件或 grounding 元数据，附可核实的检索凭据（若有）。
2. **关联信息**：查询、关联结果与计费挂到同一请求身份。
3. **不足说明**：缺少可核实检索凭据时，明确标为**协议／结果不足**，而不是「未搜索」或「不支持」。

**明确不放的内容**：整段私有笔记上下文、未获准外发的材料、与本次检索无关的会话内容。子请求不是第二个主对话，也不携带未获准进入本次请求的私有材料。

输入修订沿用 Run 冻结的修订标识，查询 hash 只作查询指纹。子请求继承真实父调用、child scope、发起模型请求与工具面版本，每次 HTTP 尝试单独向 K06 申领并结算。部分已报告用量与未知尝试同时保留，未知费用不得记为免费。

检索凭据按协议位置验证：Anthropic 的 `web_search_tool_result.tool_use_id` 必须关联本响应实际 `server_tool_use.id`，仅接受成功的结构化结果；错误结果及旁支引用不构成成功。Responses 先检查整体状态，再核验已完成搜索及消息 `output_text.annotations` 中的引用，不能通过全树扫描拼接不相关字段。

首请求、重试与服务切换复用同一动作的绝对截止时间和撤权代次；每次派发前复验冻结授权、实时联网与取消，传输及响应读取同时监听取消／撤网通知。重新打开联网不会复活已撤销动作。结果未知的已申领尝试不自动退款；原生超时保留已取得的 MCP 观察，普通 Run 取消仍禁止发布最终答案。

## 状态转换

本合同不引入新的运行时状态机；它约束原生路线在**每个端点**上的可表达状态与其来源：

| 表达           | 含义                                 | 依据                    |
| -------------- | ------------------------------------ | ----------------------- |
| 端点未验证     | 尚未做过该端点的协议与真实调用核对   | `Q17`／`G03` 的初始状态 |
| 支持且已适配   | 该端点按协议发出并返回可核实检索凭据 | `V05` 类证据            |
| 不支持原生搜索 | 正常能力配置                         | `C10` 的能力状态        |
| 临时不可用     | 运行故障，与「不支持」分开           | `C12` 的调用结果        |
| 协议／结果不足 | 请求已发出但缺少可核实检索凭据       | 本合同的异常分类        |

合法转换：某端点从「未验证」进入「支持且已适配」或维持「未验证」；运行期在「支持且已适配」与「临时不可用」之间浮动。「不支持」只能由能力事实产生，不能由一次失败推断。`temporarily-failed` 不写成 `unsupported`，`unsupported` 也不因为一次成功就假定稳定支持。

## 不变量

1. **仅携带获准查询和必要公共范围**：不转发整段私有笔记上下文。
2. **不是子 agent**：它不拥有独立任务与工具面，也不产生独立报告；委派语义见 [K16](./K16-verification-report.md) 与 `C15` 的正式定义。
3. **不代替主模型的语义判断**：相关性、矛盾判断、阅读需求与补查仍由主模型决定；子请求只产出检索材料。
4. **受控可追踪**：查询、关联结果与计费挂在同一请求身份上，可关联到本次动作。
5. **额度纳入共同边界**：原生搜索请求向 `C13` 申领额度，纳入顶层总消耗，不形成第二本账。
6. **授权是前提**：联网关闭时不可达；外发范围仍受 `C04` 约束（`K09`）。
7. **不伪造成功**：缺少可核实检索凭据时记录协议／结果不足。
8. **不静默归因**：不能把缺少凭据悄悄归成「模型不支持」。
9. **端点适配逐个进行**：供应商能否稳定实现本合同仍需逐个适配测试，任何端点都不因厂商名或 `OpenAI-compatible` 标签而被视为已通过。

## 异常处理

| 失败分类                           | 反馈与可恢复性                                                                | 不得发生的行为                                       |
| ---------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------- |
| 缺少可核实检索凭据（只有生成文字） | 记录协议／结果不足；在预算内允许**有依据的恢复**（如重新发起、改用 MCP 路线） | 伪造「原生已成功」；悄悄归成「模型不支持」           |
| 端点尚未适配或适配失败             | 反馈 `C10`／`C20`：走 MCP 单路或如实说明限制；可恢复                          | 把未适配端点算作已支持                               |
| 请求已发出但结果为空               | 如实保留空结果，反馈模型修改查询或改查来源                                    | 把空结果当传输故障重复同一请求                       |
| 额度不足                           | 说明本次限制（`K06`）                                                         | 以未计入账本的请求补齐额度                           |
| 授权在运行中撤回                   | 停止新的子请求，保留已有真实观察                                              | 继续已撤回授权的重试                                 |
| 取消信号到达                       | 请求取消；迟到结果保留为旧修订观察（`C03`）                                   | 把迟到结果当作最新请求的答案；取消后进入盲目自动重试 |
| 协议字段丢失或终止原因异常         | 归 `C11`／`C12` 的协议合同（`Q04`、`Q10`）；记录事实                          | 用「换个更强模型」的实验合理化已知合同错误           |

协议／结果不足是**可诊断的缺口**，与「外部服务失败」「预期限制」并列，不合并成一句模型能力降级。

## 消费方

| 消费方 | 消费的字段                                     | 用途                                                                                   |
| ------ | ---------------------------------------------- | -------------------------------------------------------------------------------------- |
| `C20`  | 全部输入与输出字段、检索凭据的有无             | 责任组件：构造并管理子请求，向 `K11` 报告该路线的 `attempted`／`succeeded`／`failed`   |
| `C11`  | 目标端点与协议、查询与公共范围、返回事件与引用 | 按协议保真地发出受控子请求，并把服务端搜索事件与引用完整带入处理路径                   |
| `C12`  | 请求身份、调用结果、用量与传输状态             | 把重试与用量挂到同一调用身份，不隐藏额外模型请求；区分空输出、协议错误、服务错误与取消 |

## 验证

本合同需要以下类别证据，判据定义在各 `V*` 对象中，本文件不新增判据：

- `V03`：子请求构造的机械不变量——只包含获准查询与必要公共范围，不包含私有笔记上下文；请求身份字段齐备。
- `V05`：**逐端点**的协议测试加对应端点真实调用，记录模型、端点、协议、工具声明、续轮、返回事件与终止原因；端点不可用或凭据缺失时记录为「未验证」，不写成失败或通过。
- `V04`：跨组件交接——原生路线结果与计费关联到 `C13` 账本，以及与 MCP 路线的合并表达（`K11`）。
- `V07`：协议／结果不足在诊断中可定位，且不被合并成模型能力降级。

`G03` 的阻断门槛为 `at=acceptance`；`V05` 当前状态为「未运行（`Q17`）」（见 [acceptance-matrix.md](../testing/acceptance-matrix.md)）。引用这些证据类别不表示本合同已在任一端点通过。
