# K15 交付结果与用户可见表达

<!-- iris:object K15 kind=rules file=true -->

本文件是 `K15` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**用户最终看到什么**：任务结果、回答正文、候选与澄清、限制说明，以及受控来源区的投影依据。责任组件是 `C25`（最终发布与 UI 投影），消费方是 `C25`、`C23`、`C14`。

本文件只定义交付结果与用户可见表达，不复制相邻对象的正式定义：Run 生命周期与任务结果的分离见 [K02](./K02-run-lifecycle.md)，验证报告与可恢复错误反馈见 [K16](./K16-verification-report.md)，来源身份与支持关系见 [K14](./K14-evidence-and-provenance.md)，额度与停止原因见 [K06](./K06-budget-ledger.md)，输入修订与取消见 [K03](./K03-instruction-revision.md)，授权与候选应用边界见 [K05](./K05-authorization-and-confirmation.md)，诊断与归因见 [K17](./K17-audit-events.md)。

本文件的编译依据是架构定义的 M8 与错误归属一节，以及讨论纪要第十节关于联网开关与兼容的结论（不支持原生搜索是正常配置，路径变化不影响任务完成时不打扰用户，确实导致证据不足时不隐藏限制）。`implementation.state` 只描述源码事实，不代表合同正确或用户任务可用（见 [governance.md](../rules/governance.md) §2.2）。运行中追加或修改指令的交互已关闭（`Q16`）：Host 在 Run 进行中拒绝新指令，用户等待、取消或完成后重发；关闭是「选择已作出」，不是「就地修订已实现」，不得由本文件推定已实现运行中修订。

## 接口

**输入**（设计层逻辑类型，不是已存在的 Rust 类型或 IPC 字段）：

| 输入                   | 含义                                                                          | 权威所有者                   |
| ---------------------- | ----------------------------------------------------------------------------- | ---------------------------- |
| 验证报告               | 逐项 `passed`／`failed`／`unknown`／`not-applicable` 结果、实际分母与缺口清单 | `C23`（`K16`）               |
| 循环结束原因与剩余资源 | 完成、需要澄清、权限受限、服务失败、预算耗尽等停止原因                        | `C14`、`C13`（`K06`）        |
| 执行回执与部分失败     | 已执行动作的结果、部分写入、不可回滚事实                                      | `C06`、`C17`                 |
| 来源事实               | 最终正文实际引用且验证通过的账本记录                                          | `C22`（`K14`）               |
| 能力状态               | `unsupported`／`available`／`temporarily-failed`／`unknown`                   | `C10`（`K04`）               |
| 运行与修订身份         | Run 生命周期状态、当前输入修订号                                              | `C02`、`C03`（`K02`、`K03`） |
| 恢复轨迹               | 首个失败、反馈、修正提议与恢复结果的关联事实                                  | `C14`、`C26`（`K17`）        |

**输出**：

1. **回答**：普通回答以自然正文结束；只有需要结构化结果的严格合同才按需使用 `submit_final_answer`。
2. **候选与澄清**：需要用户确认或补充输入时给出候选或澄清问题；候选生成与实际应用分离（`K05`、`C24`）。
3. **限制说明**：仅当限制仍影响任务交付、需要用户操作或恢复资源耗尽时给出，并说明具体限制与其影响范围。
4. **受控来源区**：只投影上面「来源事实」一项中的记录。
5. **任务结果标记**：`completed`／`partial`／`blocked` 等任务结果，与 Run 生命周期分别保存。

**边界**：`C25` 不拥有执行历史（`C17`、`C26`），不把模型的完成声明直接落为文件回执（`C06`），不改写验证报告（`C23`），不新增来源（`K14`），不决定下一步行动（`C14`）。

## 状态转换

Run 生命周期由 `K02` 拥有；本合同只定义交付表达的转换，不引入新的持久状态机：

| 表达状态        | 进入条件                                     | 允许的去向                                           |
| --------------- | -------------------------------------------- | ---------------------------------------------------- |
| `in_progress`   | 循环仍在行动，尚无最终正文                   | `delivered`、`clarification`、`limited`、`cancelled` |
| `delivered`     | 验证报告满足要求，且来源区可依实际引用投影   | 终态                                                 |
| `clarification` | 需要用户补充材料或确认，且未因此产生副作用   | 终态；下一轮用户消息由 `K01`／`K02` 创建新 Run 承接  |
| `limited`       | 仍影响交付的限制、需要用户操作或恢复资源耗尽 | 终态；必须给出具体限制，不得以概括性降级说明代替     |
| `cancelled`     | 用户取消或明确权限拒绝                       | 终态；如实报告已执行前缀                             |

约束：`delivered` 只能由验证报告与执行回执共同支持，不能由模型的完成声明或流式结束推出；表达状态不得反向改写 Run 生命周期或执行事实。

严格结构化合同的 Run 在当前实现中于绑定校验前封存模型正文，通过后只发布最终正文一次，失败则发布无 citation map、无 source summary 的限制说明；普通回答继续自然结束（[ARCHITECTURE.md](../../ARCHITECTURE.md) 记录的源码事实）。`AnswerReset` 不由新的严格 Run 产生，只保留旧事件回放兼容；旧 Run 的 `AwaitingInput` 与提交入口同样只用于读取或恢复兼容，不是新普通对话的路径。上述是源码事实。运行中追加指令的交互已关闭（`Q16`）：拒绝新指令，不是就地修订已实现。

## 不变量

1. **任务结果与 Run 生命周期分离**：执行结束、进程结束或流式输出结束都不等于用户任务成功；两者不得压成同一个状态字段。
2. **普通回答自然结束**：不得为了让所有任务满足同一套终局格式而给简单对话增加失败点；`conclude_reasoning` 已退出目标工具面，兼容期只识别旧记录、不因此重放动作。
3. **不支持原生搜索不显示降级**：该情形是正常能力配置，正常使用 MCP；只有确实导致证据不足时才如实说明限制。
4. **限制说明有明确门槛**：只有仍影响任务交付、需要用户操作或恢复资源耗尽时才在用户侧说明具体限制；成功恢复并满足要求的任务正常交付。
5. **禁止降级概括**：不得用「模型能力降级」概括未知工具、参数错误或普通工具调用错误；实际路由或能力变化必须有事实依据并独立记录（`K04`、`K17`）。自动切换模型不作为未知工具或普通参数错误的默认纠偏手段。
6. **技术错误不堆进正文**：恢复较久时可在用户侧显示简短进度，但不把内部错误、调用细节或私有推理写入回答正文。
7. **来源区只投影实际引用且验证通过的记录**：有引用不等于结论成立；同 Run 的其他候选或已登记未被引用的 evidence 不进入来源区。
8. **表达不改写执行事实**：失败不能压成成功，不可回滚动作只报告事实，部分写入不得表达为完整成功。
9. **恢复轨迹保留**：首个失败不被后续成功覆盖；用户侧不必展示恢复过程，但诊断侧必须可查看（`K17`）。
10. **本合同的输出不构成质量声明**：发布回答不等于合同正确，也不等于用户任务可用；`implementation.state` 只描述源码事实。

## 异常处理

| 失败分类                         | 用户侧表达与可恢复性                                                                                          | 不得发生的行为                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 严格终局校验失败                 | 发布限制说明（无 citation map、无 source summary），并说明哪些核实条件未满足；可恢复（后续 Run 重新取得证据） | 发布未通过校验的正文；把校验失败改称模型能力降级           |
| 所有可用核实路径失败             | 如实说明无法完成当前核实（讨论纪要第十节）                                                                    | 用流畅文字掩盖证据不足；伪造已核实结论                     |
| 恢复耗尽或该路径停滞阈值触发     | 说明具体限制与影响范围；归因由 `C27` 给出（`K17`）                                                            | 用「模型能力降级」概括；把恢复结果当作根因                 |
| 可恢复错误已被纠正               | 正常交付结果，不弹出降级提示                                                                                  | 因一次已恢复的工具错误提示模型降级；把恢复过程写进回答正文 |
| 需要新增授权或用户确认           | 转为澄清或确认路径，不产生副作用                                                                              | 以「用户此前允许联网」隐含扩大授权                         |
| 用户取消或明确权限拒绝           | 如实报告已执行前缀与未执行部分；不进入盲目重试                                                                | 取消后启动新副作用；把拒绝算作失败并重试                   |
| 写入回执未知的非幂等动作         | 先核实回执（`C06`），如实表达结果未知                                                                         | 假设成功；重复执行造成重复变更                             |
| 交付所需授权或变更回执无法持久化 | 不执行新的持久副作用，并说明限制                                                                              | 以未持久化的确认继续执行                                   |
| 可选诊断写入失败                 | 记录可诊断性缺口，通过独立信号呈现；不抹掉已取得的正确答案                                                    | 要求仅靠同一失效日志通道报告自身失败                       |

## 消费方

| 消费方 | 消费的字段                                                           | 用途                                                                                   |
| ------ | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `C25`  | 全部输入与输出字段                                                   | 责任组件：决定交付形态、投影来源区、给出限制说明、分别保存任务结果与 Run 状态          |
| `C23`  | 验证报告与交付表达的交界：缺口清单、应满足的核实条件、限制说明的依据 | 保证「还缺什么」与「用户看到什么」一致；`C23` 只提供报告，不自行发布                   |
| `C14`  | 交付状态、澄清或限制的判定结果、未解决问题                           | 决定下一步继续、修正、澄清还是结束；结束必须对应真实原因，不得以表达结果反推任务已完成 |

相邻而非消费的关系：`C22` 提供来源事实（`K14`），`C06` 提供执行回执，`C13` 提供剩余资源与停止原因（`K06`），`C10` 提供能力状态（`K04`），`C26`／`C27` 提供诊断与归因（`K17`）。

## 验证

本合同需要的证据类别定义在各 `V*` 对象中，本文件不新增判据：

| 判据  | 适用于本合同的内容                                                                                                          |
| ----- | --------------------------------------------------------------------------------------------------------------------------- |
| `V03` | 局部机械不变量：任务结果与 Run 生命周期分字段、来源区只含实际引用且验证通过的记录、严格 Run 失败时的限制说明形态            |
| `V04` | 跨组件与生产入口：`C23` → `C25` 终局交接、严格合同密封与限制说明、取消与授权拒绝路径、普通回答的自然结束路径                |
| `V06` | 语义质量：限制说明是否准确、可理解且不误导；须真实模型场景、明确判据与人工抽检                                              |
| `V07` | 诊断与界面：错误提示误报、不应出现的降级提示、限制说明与诊断入口的关联；正常限制不被误报为 bug                              |
| `V05` | 不适用：供应商端点与协议兼容不属交付表达的判据；相关证据属 `K04`／`K12`                                                     |
| `V02` | 登记关联：本合同的机械不变量须在 [evidence.md](../testing/evidence.md) 登记合法案例、违例案例、检测位置、恢复行为与对应测试 |

各对象当前证据以 `registry.verify` 为准；本页不宣称 `V03`–`V07` 已通过。引用这些判据不表示本合同已通过验收，也不表示交付路径已可用。`C25` 已绑的 `d05_delivery_outcome_tests.rs` 不在本合同页写成验收。
