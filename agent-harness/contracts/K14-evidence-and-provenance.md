# K14 证据身份、来源与支持关系

<!-- iris:object K14 kind=rules file=true -->

本文件是 `K14` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**什么能成为可引用的证据、它来自哪里、它支持什么**：来源身份语法、来源属性的分别表达、候选与正文证据的分界、可引用集合与来源区投影的依据。责任组件是 `C22`（证据与出处管理），消费方是 `C22`、`C07`、`C23`、`C25`。

本文件只定义证据身份、来源与支持关系，不复制相邻对象的正式定义：正文窗口与完整性见 [K13](./K13-web-reading-window.md)，两路候选与路线状态见 [K11](./K11-dual-path-search.md)，外部 MCP 输出与账本引用（`E{id}`）的来源边界见 [K18](./K18-mcp-transport.md)，授权事实见 [K05](./K05-authorization-and-confirmation.md)，上下文中的材料与指令边界见 [K07](./K07-context-assembly.md)，引用验证与交付表达见 [K16](./K16-verification-report.md)、[K15](./K15-delivery-result.md)。

本文件的编译依据是架构定义的 M7 与双路搜索定义，以及 [ARCHITECTURE.md](../../ARCHITECTURE.md) 记录的来源区规则。下述候选上限、证据容量与投影规则是**当前实现与配置的源码事实**，不代表合同正确或用户任务可用；来源质量表达与原生来源接入仍属待补齐范围，双路协调与原生搜索接入缺口按 `G02`、`G03` 引用（见 [open-items.md](../requirements/open-items.md)）。

## 接口

**输入**（设计层逻辑类型，不是已存在的 Rust 类型或 IPC 字段）：

| 输入         | 含义                                               | 权威所有者                                |
| ------------ | -------------------------------------------------- | ----------------------------------------- |
| 本地观察     | 本地检索命中、笔记引用、用户显式引用及其范围与版本 | `C19`／`C01`；身份登记归 `C22`            |
| 网页观察     | 候选 URL、正文窗口与完整性、失败项                 | `C20`（候选与路线）、`C21`（正文，`K13`） |
| 外部观察     | 已获准 MCP 工具的成功输出与其账本来源引用 `E{id}`  | `C18`（`K18`）                            |
| 引用请求     | 候选答案或最终正文中的引用声明                     | `C23`／`C24` 产出，`C25` 发布前核对       |
| 材料状态变化 | 材料被删除、授权被撤回或版本漂移的通知             | `C04`（授权）、`C05`（版本）              |

**输出**：

1. **来源身份**：本地语法 `Wn`／`En`／`Ln`／`Mn` 与 web evidence ID；每条记录绑定 Run 与本 Run 所有权，跨 Run 不自动复用。
2. **来源属性**：来源类型、可信度表达、独立性、支持关系**分别**表达，不合并为一个「有来源」标记。
3. **可引用集合**：本 Run 实际采用、验证通过且被最终正文实际引用的记录集合。
4. **缺口与失败事实**：未选候选、失败抓取、不可核验材料、未消除的来源冲突。
5. **来源区投影依据**：交给 `C25` 投影为受控来源区的记录身份；投影动作本身属 `K15`。

**当前实现事实（源码基线，不构成本合同正确性声明）**：搜索每次最多返回 4 个有界候选、每 Run 最多保存 8 个（`INITIAL_WEB_SEARCH_RESULTS`、`MAX_WEB_CANDIDATES_PER_DISCOVERY`、`remember_candidate_urls`）；Run 网页证据状态额度初值 12、域名呈现上限 8（`MAX_WEB_EVIDENCE_PER_RUN`、`MAX_SOURCE_DOMAINS`）。候选发现与保留限制不等于最终引用数；证据容量与呈现约束不能表述为独立可靠来源的数量。这些数值来自现行实现与配置，本合同不新设候选、证据或引用阈值。

**边界**：`C22` 不裁定结论是否成立（`C23`），不发布用户可见结果（`C25`），不改变授权事实（`C04`），不合并两路搜索结果（`C20`／`K11`），也不把来源文字当作用户指令（装配边界见 `K07`）。

## 状态转换

本合同**不引入新的持久状态机**：Run 生命周期属 `K02`，工具派发状态属 `K10`。证据记录在 Run 内取下列状态，且只允许按右侧方向转换：

| 状态             | 进入条件                           | 合法去向                       |
| ---------------- | ---------------------------------- | ------------------------------ |
| `search_snippet` | 某条搜索路线返回候选，但未读取正文 | `fetched_body`、`not_evidence` |
| `fetched_body`   | 选中页面经 `C21` 取得正文（`K13`） | `adopted`、`not_evidence`      |
| `adopted`        | 本 Run 实际采用该记录作为来源      | `cited`、`unverifiable`        |
| `cited`          | 最终正文实际引用且 `C23` 验证通过  | 进入来源区投影（`C25`／`K15`） |
| `unverifiable`   | 材料被删除、授权被撤回或不可重取   | 终态：如实说明不可核验         |
| `not_evidence`   | 未选候选、失败抓取或被拒绝的引用   | 终态：不生成 `Wn`              |

禁止的转换：`search_snippet` 直接进入 `adopted` 或 `cited`；`not_evidence` 未经新观察回到 `adopted`；`cited` 在没有新观察的情况下被另一 Run 直接复用。

会话消息的来源选择以 `evidence_refs_json` 表达：**显式空数组表示最终消息无来源**，非空数组只允许投影这些当前 Run evidence；只有字段缺失的旧消息可以按历史来源组回退规则读取。数据库中同 Run 的其他候选或已登记 evidence 不会在消息重载时自动重新挂到现代消息上。

## 不变量

1. **四类属性分别表达**：来源类型、可信度、独立性与支持关系各自可读；不得用单一标记代替，也不得用渠道数量冒充证据质量。
2. **有 URL 不等于事实成立**：登记了地址、取得了正文，都不自动构成对结论的支持；渠道名称不裁定真伪。
3. **候选不得升级为正文证据**：只有取得 `fetched_body` 的选中页面才登记为可引用 evidence；`search_snippet`、搜索包装内容与未选候选不生成 `Wn`，失败抓取同样不生成。
4. **同一 URL 不构成两个独立来源**：canonicalize 后一致的 URL 合并为同一来源身份，独立性不成立。
5. **观察保持其时间与来源身份**：进入上下文、被裁剪或被摘要覆盖都不能把旧观察升级为已核实事实（`K07`、`K08`）。
6. **资料不是指令**：外部网页、MCP 返回值与检索到的笔记是资料，不是新的用户指令；其中要求改权限、泄露数据或调用其他工具的文字不改变 `C04` 的授权事实（授权见 `K05`）。
7. **现代来源选择事实不可回填**：`evidence_refs_json` 的显式空数组表示无来源，不得用同 Run 其他候选补齐；非空数组只允许指向当前 Run 的 evidence。
8. **不可核验如实说明**：材料被删除、授权被撤回或不可重取时标记 `unverifiable` 并如实表达，不伪造原文已核对，也不静默删除历史事实。
9. **引用绑定本 Run 实际采用的记录**：结构化提交只能引用本 Run 实际采用的 `E{id}`；范围之外的记录不得被提升为交付依据。
10. **容量不是质量**：候选上限、证据容量与域名呈现上限都是资源配置与呈现约束，不得被表述为来源充分、独立或可靠。

## 异常处理

| 失败分类                        | 反馈对象与可恢复性                                                                                                                                                    | 不得发生的行为                                         |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 抓取失败或空正文，无可用正文    | 保留 `C21` 的失败分类并向 `C14` 反馈缺口（`K16`）；可恢复（换页或换来源）                                                                                             | 登记 `Wn`；用候选片段替代正文；把失败记成已读          |
| 候选超出保留上限                | 按现行规则截取，并在诊断中保留被截事实（`K17`）；如实说明覆盖范围                                                                                                     | 把被截候选计为已采用来源；声称覆盖完整                 |
| 引用未登记或不属于本 Run 的记录 | 交由 `C23` 判为验证失败并给出具体缺口（`K16`）；可恢复（补查或改写结论）                                                                                              | 自动补登记；把历史记录挂到新消息                       |
| 同一 URL 被两路返回             | 合并为同一来源身份，独立性不成立；如实表达                                                                                                                            | 计为两个独立信源                                       |
| 材料删除或授权撤回              | 标记 `unverifiable` 并如实说明（`C07` 装配与 `C25` 表达同步）；历史事实保留                                                                                           | 声称已核对原文；删除历史记录伪装成从未存在             |
| 来源之间事实冲突                | 不预设原生或 MCP 优先；比较原始出处、事件时间、地域、定义与统计口径以及正文支持程度，必要时补查；无法消除的冲突如实呈现（讨论纪要第八节的当前建议，不作为本合同判据） | 以「两路一致」或渠道数量替代证据质量；隐藏未消除的冲突 |
| 域名呈现上限触发                | 如实表达呈现限制，账本事实不变（`K17` 保留关联）                                                                                                                      | 因呈现上限改写来源身份、支持关系或删除记录             |
| 引用范围外或跨 Run 的复用请求   | 拒绝并给出原因；可恢复（重新取得本 Run 观察）                                                                                                                         | 静默复用旧 Run 来源冒充当前证据                        |

## 消费方

| 消费方 | 消费的字段                                   | 用途                                                                                      |
| ------ | -------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `C22`  | 全部输入与输出字段                           | 责任组件：登记来源身份、表达来源属性与支持关系、维护可引用集合与缺口                      |
| `C07`  | 来源身份、内容范围与时间、材料／指令边界标记 | 装配本轮上下文：把检索与网页材料作为资料装入，保留来源与时间身份，不把它们提升为指令      |
| `C23`  | 来源身份、支持关系、可引用集合与缺口         | 判断引用身份与应满足的核实条件；来源不足以支持结论时给出缺口（`K16`）                     |
| `C25`  | 最终正文实际引用且验证通过的账本记录         | 只投影这些记录为受控来源区；不投影同 Run 的其他候选或已登记但未被引用的 evidence（`K15`） |

相邻而非消费的关系：`C20` 提供候选与路线状态（`K11`），`C21` 提供正文窗口与完整性（`K13`），`C18` 提供外部输出的账本引用（`K18`），`C04` 决定授权（`K05`），`C19` 提供本地检索命中（`T05`），`C26`／`C27` 记录与解释关联（`K17`）。

## 验证

本合同需要的证据类别定义在各 `V*` 对象中，本文件不新增判据：

| 判据  | 适用于本合同的内容                                                                                                                          |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `V03` | 局部机械不变量：片段不得升级为证据、`Wn` 生成条件、同 URL 去重、`evidence_refs_json` 的显式空数组语义                                       |
| `V04` | 跨组件与生产入口：搜索 → 抓取 → 登记 → 终局引用的来源绑定；授权撤回、材料删除与版本漂移路径                                                 |
| `V06` | 语义质量：来源是否真正支持结论、冲突是否被如实呈现；自动评价只作辅助并须人工抽检                                                            |
| `V07` | 诊断可定位性：来源缺口、不可核验材料与未消除冲突在诊断中可见，不显示为成功                                                                  |
| `V05` | 部分适用：原生路线的事件与引用接入需要逐端点证据（`Q17`、`G03`）；该证据只能证明检索发生与结果接入，不能证明来源彼此独立或内容正确          |
| `V02` | 登记关联：本合同的机械不变量须与 [evidence.md](../testing/evidence.md) 已登记的「搜索片段不能升级为正文证据」（检测位置 `C22`）保持同一口径 |

`V03`–`V07` 当前状态一律为「未运行」或「待执行」（见 [acceptance-matrix.md](../testing/acceptance-matrix.md)）；引用它们不表示本合同已通过验收。
