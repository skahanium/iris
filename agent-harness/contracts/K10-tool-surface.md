# K10 工具面版本与派发观察

<!-- iris:object K10 kind=rules file=true -->

本文件是 `K10` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**某一轮模型到底看得见哪些工具、这个可见集合如何形成与更新，以及每次提议最终落到哪个派发状态**。责任组件是 `C16`（工具目录、工具面与技能接入），主要消费方是 `C16`、`C17`、`C14`。

本合同只定义工具面与派发观察；工具卡片自身的行为合同在各 `T*` 卡片（见 [tools/README.md](../tools/README.md)，本轮尚未全部建立），授权判定见 [K05](./K05-authorization-and-confirmation.md)，额度租约与分类计数见 [K06](./K06-budget-ledger.md)，可恢复错误的反馈与验证缺口见 [K16](./K16-verification-report.md)，外部 MCP 传输与外部工具呈现见 [K18](./K18-mcp-transport.md)，搜索语义的单一入口见 [K11](./K11-dual-path-search.md)。本合同不复制上述对象正文。

## 接口

**输入**：

| 输入              | 含义                                         | 来源                                                 |
| ----------------- | -------------------------------------------- | ---------------------------------------------------- |
| 内置／外部 schema | 目录项的名称、参数与说明；外部工具按服务注册 | 目录定义与 `C18` 发现结果                            |
| 能力状态          | 某工具或路线在当前模型／端点上是否可用       | `C10`                                                |
| 授权              | 本次 Run 允许的动作范围                      | `C04`（`K05`）                                       |
| 上下文            | 任务类型、场景与需要的领域能力               | `C01`、`C07`                                         |
| 技能发现结果      | 可用技能与方法材料                           | `C16` 自身                                           |
| 工具面申请        | 模型请求安装的**目标工具名**                 | `capabilities_read` 参数（`G01` 登记的待实现消费项） |
| 派发结果          | 每次提议的执行状态与观察                     | `C17`、`C13` 租约                                    |

**输出**：

1. **工具面（版本化集合）**：由「基础工具 + 获准领域工具 + 显式扩展」构成，带**工具面版本**；同一授权范围内可在下一轮更新并记录新版本。
2. **方法材料引用**：技能方法的引用；`C16` 管技能发现与方法选择，`C07` 决定如何把方法材料装入上下文（装载规则见 [K07](./K07-context-assembly.md)）。
3. **参数处置说明**：所有暴露参数标记为「已消费」或「明确拒绝」；不得存在静默忽略的参数。
4. **单次提议的派发状态与观察**：`rejected`／`deferred`／`started`／`partial`／`failed`／`succeeded`，附拒绝原因或失败分类。

**归属边界**：分类计数（各类别已用与剩余）由 `C13` 依据 [K06](./K06-budget-ledger.md) 维护；`C17` **只申领并回报**，不自行记账。每次模型请求、工具调用和原生搜索子请求携带 Run ID、输入修订号、父调用 ID、尝试 ID；工具调用还记录工具面版本。

## 状态转换

工具面是**版本化集合**，不是每轮重写的自由列表：

| 事件                               | 合法转换                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 新一轮开始                         | 沿用上一轮工具面版本；若场景、授权或能力状态变化，形成**新版本**并记录                                             |
| 同一授权范围内的领域或扩展需求     | 组装新版本（加入获准领域工具或显式扩展）；更新只改变可用描述，**不自动扩大权限**                                   |
| `capabilities_read` 申请目标工具名 | 由 `C16` 与 `C04` 验证；通过则在**下一轮**安装新版本；不执行业务动作、不授予新权限；名称未知或权限不足返回明确原因 |
| 涉及新权限的需求                   | 转入既有确认流程（`K05`）；目录扩展、授权变更与实际执行分别记录，不一步混做                                        |
| 能力状态变为不支持                 | 从可见集合移除或标记不可用；不影响正常文本与 MCP 路线的可用性（`K04`）                                             |
| Planned 项                         | **始终不进入可见集合**；文档里有名字不构成可用声明                                                                 |

单次提议的派发状态合法转换：

```text
提议 → rejected                    （未派发；记录原因，不进入执行路径）
提议 → deferred                    （本轮未派发，需反馈后重提）
提议 → started → succeeded
              → partial            （部分成功；保留成功部分）
              → failed             （执行失败；保留分类与关联身份）
```

不允许的转换：`rejected`／`deferred` → `succeeded`（未派发不得记为已执行）；`failed`／`partial` → `succeeded`（不得用后续成功抹掉原始失败，恢复轨迹保留）；`started` → 无终态（必须收敛到 `succeeded`／`partial`／`failed`，或按中断规则标为结果未知）。

## 不变量

1. **Planned 不暴露**：目录中声明但未实现的项不进入任何工具面版本。
2. **所有暴露参数必须被消费或明确拒绝**：schema 里声明的参数不能静默忽略（`G01` 登记了 `capabilities_read` 的 `request_tools` 与 `spawn_subagent` 的 `context_hint`／`max_rounds` 等待清项）。
3. **技能不增权**：技能只提供方法材料，不带来执行权限；发现技能不等于获得执行能力。
4. **同一搜索服务不以原始别名绕开统一路径**：搜索语义只能经统一入口请求，服务别名（如具体服务商的 `search`／`extract`）作为 `web_search`／`web_fetch` 的后端适配，不作为第二个可任选的旁路工具暴露（`K11`）。
5. **工具名是能力接口，不是权限**：可见性不构成授权；每次执行仍由 `C04` 判定。
6. **工具面更新不扩权**：安装新版本只改变可用描述，权限事实仍由 `C04` 维护。
7. **派发状态不被投影改写**：被拒绝的提议不写入执行路径、不增加「实际工具执行次数」；它已消耗的模型回合、token、时间与纠偏次数照实计入 `C13`。
8. **未派发不计入执行**：分类计数由 `C13` 维护，`C17` 只申领并回报，不产生第二本账。
9. **身份可关联**：每次调用带 Run ID、输入修订号、父调用 ID、尝试 ID 与工具面版本。
10. **能力不足不冒充完整兼容**：没有原生搜索但支持客户端工具调用的模型正常使用 MCP；连客户端工具调用也不支持时，明确其纯文本能力范围。

## 异常处理

按 [agent-architecture.md](../../docs/agent-architecture.md) §3 M5 的「可恢复错误的默认处理」，工具面的异常至少覆盖：

| 失败分类                           | 反馈内容与可恢复性                                                                                       | 不得发生的行为                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 提议不存在的工具（`unknown_tool`） | 返回 `unknown_tool`、本次未派发、当前工具面版本及相关合法工具的准确名称与 schema；可恢复，让模型重新提议 | 一次未知工具即终止 Run；模糊匹配工具名后直接执行；把提议失败记成真实工具执行失败 |
| 参数无效                           | 返回字段级校验问题、允许类型及必要字段；可恢复                                                           | 只返回笼统 error；静默猜测写入目标或补造授权参数                                 |
| 工具面或协议解析错位               | 先修正对应内部交接（`C11`／`C16`／`C17`），再让模型重提                                                  | 把内部错位表达为模型能力不足                                                     |
| 工具面申请名称未知                 | 返回明确原因，模型可在同授权内重新申请                                                                   | 退回「只开放两个工具让模型自由决定」的自由提议路径                               |
| 工具面申请权限不足                 | 转入确认流程或返回拒绝原因；不得静默安装                                                                 | 以安装工具面代替授权变更                                                         |
| 工具面版本不可解释（缺少版本记录） | 关联 `C26`，标为诊断不足                                                                                 | 默认执行成功                                                                     |

无法安全还原工具调用身份时，按协议错误恢复处理，不能拼造一个表面有效但关联错误的工具返回。

## 消费方

| 消费方 | 消费的字段                                       | 用途                                                                                     |
| ------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `C16`  | 全部输入与输出字段、工具面版本、参数处置说明     | 责任组件：组装版本化工具集合、处理 `capabilities_read` 申请、管理技能接入                |
| `C17`  | 工具面版本、单次提议的派发状态与观察、拒绝原因   | 派发与观察；**申领**额度并**回报**状态，不维护分类计数                                   |
| `C14`  | 派发状态、拒绝原因、工具面版本变化、参数修正事实 | 判断是否已提供有效反馈、工具面是否变化、参数或策略是否实质修正，从而决定继续、纠偏或结束 |

`C13` 依据本合同的状态回报维护分类计数（`K06`）；`C15` 为子任务申请受限工具面时同样消费本合同，但不改变工具面定义。

## 验证

本合同需要以下类别证据，判据定义在各 `V*` 对象中，本文件不新增判据：

- `V03`：工具面不暴露 Planned 项、参数被消费或明确拒绝、派发状态取值与转换合法、未派发提议不计入已执行工具数（见 [evidence.md](../testing/evidence.md) 的首批不变量登记）。
- `V04`：跨组件交接与生产入口——未知工具纠正后完成、参数错误后修正、`capabilities_read` 申请在下一轮安装新版本且不执行业务动作。
- `V05`：不同协议下的工具声明与续轮（`unknown_tool` 是否由协议解析错位产生，见 `Q01`／`Q12`）。
- `V07`：派发状态、工具面版本与拒绝原因在诊断中的可定位性（「哪个阶段违反了什么合同」）。

`V03`–`V07` 当前状态一律为「未运行」或「待执行」；引用它们不表示本合同已通过验收。
