## 接口

**输入**：模型配置、任务所需能力、已验证配置。

**输出**：可用路由及能力状态。

**能力状态的四个取值**：

| 取值                 | 含义                                   | 不能据此推出                       |
| -------------------- | -------------------------------------- | ---------------------------------- |
| `unsupported`        | 该端点/协议不支持该能力                | 网络故障、模型质量差、需要切换模型 |
| `available`          | 已按该端点的协议声明与验证状态确认可用 | 本轮一定会成功，或结果一定正确     |
| `temporarily-failed` | 能力存在，本次调用失败或超时           | 能力不存在，或应淘汰该路由         |
| `unknown`            | 尚无足够证据判定                       | 不支持，或可用                     |

**必须分别声明的四项能力**：原生搜索、客户端工具调用、流式输出、续轮（多轮工具调用与必要续轮字段）。四项之间不得互相替代：没有原生搜索但支持客户端工具调用的模型可以正常使用 MCP；连客户端工具调用也不支持时，不能冒充完整 agent 兼容，应明确其纯文本能力范围。

**协议保真要求**：Chat Completions、Responses、Messages 各自保真。文本、工具增量、服务端搜索、引用及必要续轮字段不被静默丢弃；供应商的终止事实必须保留，不得把截断写成正常结束。

**入口与关联**：主对话、摘要、语义验证与受控原生搜索请求都走同一模型网关边界，并各自向 `C13` 申领额度。每次调用的身份字段（Run ID、输入修订号、父调用 ID、尝试 ID）由 [K01](./K01-request-identity.md) 定义并随请求传递；重试与用量挂到同一调用身份，不隐藏额外的模型请求。额度类别与记账维度见 [K06](./K06-budget-ledger.md)。

**原生搜索的接入位置**：原生搜索从主对话协议中隔离为受控子请求，只携带获准查询与必要公共范围，不转发整段私有笔记上下文；它不属于子 agent，也不代替主模型的语义判断。执行证据以供应商定义的实际搜索事件或能证明检索发生的结构化 grounding 元数据为准。

## 状态转换

能力状态挂在**具体模型／端点**上，不挂在产品名、品牌或 `OpenAI-compatible` 标签上。

| 转换                               | 触发条件                           | 说明                                           |
| ---------------------------------- | ---------------------------------- | ---------------------------------------------- |
| `unknown` → `available`            | 该端点的协议测试与真实调用取得证据 | 仅首轮文本成功不足以证明工具调用与续轮合同成立 |
| `unknown` → `unsupported`          | 端点协议明确不支持该能力           | 记为不支持，不记为失败                         |
| `available` → `temporarily-failed` | 本次调用超时、限流或服务错误       | 临时失败不改变“能力存在”这一事实               |
| `temporarily-failed` → `available` | 恢复后再次调用成功                 | 保留原始失败记录，首个失败不被后续成功覆盖     |
| `available` → `unknown`            | 配置或提供方变化使既有证据不再适用 | 证据适用性按 `V08` 标注，不静默沿用            |

**禁止转换**：`unsupported` 不得被投影写成 `temporarily-failed` 或 `available`；`temporarily-failed` 不得写成 `unsupported`；任何状态都不得通过“本次任务成功”反推为端点已验证。

端点的原生搜索能力状态与 MCP 服务的能力状态分别保存，`C20` 合成带配置版本的执行快照。配置往返与状态刷新规则见 [agent-architecture.md](../../docs/agent-architecture.md) §5.1。

## 不变量

1. **能力事实如实上报。** 存在、缺失、临时失败与未知分别表达，不用一个“可用”概括。
2. **不支持原生搜索是正常配置。** 它不能淘汰正常的文本／MCP 路由，也不能作为显示能力降级的理由。
3. **不支持的动作不得标记为成功。** 不为“无感”而把未执行的动作写成成功，也不悄悄归成“模型不支持”。
4. **必要续轮字段与终止事实不被静默丢弃。** 各协议分别保真，字段缺失必须可诊断。
5. **重试与用量挂到同一调用身份**，额外模型请求不被隐藏（记账见 `K06`）。
6. **空正文且无工具调用视为无效响应**，不得当作正常完成。
7. **模型本身不得成为唯一根因结论。** 判断模型行为前需核对当前指令与材料覆盖、实际出站请求结构、工具面版本、必要续轮字段与返回解析；出站结构见证只能证明结构及关联，不能单独证明语义理解。

## 异常处理

| 失败类别             | 表现                               | 是否可恢复                                                                                       | 反馈给谁                             | 不得继续的情形                                   |
| -------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------ | ------------------------------------------------ |
| 无效响应             | 空正文且无工具调用                 | 可恢复：在尚无可见正文、工具调用、续轮或副作用时，先重试同一 Provider 一次，再切换同工具能力候选 | `C12` 执行报告；`C14` 决定后续行动   | 不得把无效响应写成正常完成                       |
| 已有动作后的失败     | 已有可见正文、工具调用或副作用     | 不跨 Provider 隐式续接                                                                           | 诊断入口保留尝试、错误类别与切换决定 | 不得隐式换到另一个 Provider 继续同一调用         |
| 协议错误             | 返回结构不属于该协议约定           | 按协议错误恢复                                                                                   | `C11`、`C12`；`Q10` 记录待证事实     | 不得拼造表面有效但关联错误的工具返回             |
| 服务错误与取消       | 超时、限流、鉴权失败、用户取消     | 区分表达，不混为一类                                                                             | `C26`、`C27`                         | 不得在取消后继续发起调用                         |
| 原生搜索无凭据       | 只有生成文字，没有可核实的检索凭据 | 记录协议／结果不足，在预算内允许有依据的恢复                                                     | 诊断入口；`C20` 路线状态             | 不得伪造“原生已成功”，也不得悄悄归成“模型不支持” |
| 端点不可用或凭据缺失 | 无法完成调用                       | 记录为未验证                                                                                     | 设置与诊断入口                       | 不得写成失败或通过                               |

用户可见表达见 `K15`：不得因一次工具错误向用户提示“模型出错／模型能力降级”。

## 验证

按 [acceptance-matrix.md](../testing/acceptance-matrix.md) 的证据用途分类，本合同需要：

1. **`V05` 协议兼容与真实端点证据**：逐端点记录模型、端点、协议、工具声明、客户端工具续轮、返回事件与终止原因；协议测试必须与对应端点的真实调用配对。不得仅凭厂商名、品牌或 `OpenAI-compatible` 标签判定能力；端点不可用或凭据缺失时记录为“未验证”。
2. **`V03` 局部机械不变量**：能力状态四值的合法与禁止转换、空正文且无工具调用判为无效响应、重试与用量归属同一调用身份。
3. **`V08` 证据记录**：出站结构证据必须与 Run、模型轮次、尝试、工具调用及父子任务建立关联，并遵守最小化与脱敏约束。

相关缺口见 `G03`，待证事项见 `Q10`、`Q17`；本轮没有执行付费实网评测，本合同不声明任何端点已通过。
