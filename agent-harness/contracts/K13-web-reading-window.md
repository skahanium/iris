# K13 网页读取窗口与完整性

<!-- iris:object K13 kind=rules file=true -->

本文件是 `K13` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**一次网页读取实际取得了什么正文**：`urls` 批量读取与 `startChar` 窗口续读、URL 安全校验、部分失败的保留、正文完整性与不足的表达。责任组件是 `C21`（网页读取与提取），消费方是 `C21`、`C22`、`C15`。

本文件只定义读取窗口与完整性，不复制相邻对象的正式定义：授权与外发范围见 [K05](./K05-authorization-and-confirmation.md)、[K09](./K09-web-authorization.md)，额度租约与分类计数见 [K06](./K06-budget-ledger.md)，两路候选、路线状态与合并线索见 [K11](./K11-dual-path-search.md)，来源身份与支持关系见 [K14](./K14-evidence-and-provenance.md)，任务验证与用户可见表达见 [K16](./K16-verification-report.md)、[K15](./K15-delivery-result.md)，MCP 提取传输与输出边界见 [K18](./K18-mcp-transport.md)，派发状态见 [K10](./K10-tool-surface.md)。

本合同不代表读取路径已经正确，也不代表用户任务可用：`implementation.state` 只描述源码事实，不代表合同正确或用户任务可用（见 [governance.md](../rules/governance.md) §2.2）。两路协调尚未接通（`G02`），子任务缺少标准网页正文抓取（`Q07`）；这些差异由对应工作包处理，不在本文件内解决，也不在本文件内宣称任何修复结论。

## 接口

**输入**（设计层逻辑类型，不是已存在的 Rust 类型或 IPC 字段）：

| 输入               | 含义                                                                       | 权威所有者                                     |
| ------------------ | -------------------------------------------------------------------------- | ---------------------------------------------- |
| `urls` 数组        | 本批要读取的 URL 集合，可批量读取；元素来自本 Run 候选或用户显式提供的 URL | 候选身份归 `C20`／`C22`；显式引用由 `C01` 绑定 |
| `startChar`        | 续读窗口的起始位置；省略表示从该 URL 的开头读取                            | `C21`                                          |
| 外发与联网授权     | 本次读取是否被允许、允许哪些数据域                                         | `C04`（`K05`、`K09`）                          |
| 额度租约与取消信号 | 本次动作可用的网络类额度、停止信号                                         | `C13`（`K06`）                                 |
| 提取路径与回退     | 默认使用的已配置 MCP 提取，以及当前获准的安全抓取回退与其冻结顺序          | `C18`（`K18`）；顺序由 Intake 冻结             |
| 尝试身份           | 本次读取所属的 Run、调用与尝试                                             | `C17`（`K10`）；记录字段归 `C26`（`K17`）      |

**输出**：

1. **正文窗口**：每个成功 URL 的正文片段及其窗口位置（起点、覆盖范围、是否仍有后续），可被同一合同再次请求续读。
2. **完整性表达**：该页是完整正文还是窗口片段；正文不足时必须同时返回阅读窗口与完整性，不能只给一个不可续读的片段。
3. **失败项与原因分类**：传输失败、空正文、安全校验拒绝、参数无效分别标注；失败项与成功页在同一批次结果中共存。
4. **批次汇总**：本批成功／失败项身份与实际读取用量归属，供 `C17` 的派发观察、`K11` 的路线状态与 `K17` 的事件引用。

**边界**：本合同不登记证据（属 `K14`）、不合并两路搜索结果（属 `K11`）、不判断页面是否支持结论（属 `C23`／`K16`）、不决定循环是否继续（属 `C14`）、不发布用户可见限制说明（属 `C25`／`K15`）。

## 状态转换

本合同**不引入新的持久状态机**：读取状态是 Run 内的观察事实，持久 Run 生命周期属 `K02`；同一 URL 的多次尝试是不同尝试身份（`K17`），不是对旧状态的就地改写。

每个 URL 在本批次内取下列状态之一，且只允许按右侧方向转换：

| 状态              | 含义                           | 合法去向                                                     |
| ----------------- | ------------------------------ | ------------------------------------------------------------ |
| `pending`         | 已进入本批，尚未发起读取       | `fetching`、`skipped`                                        |
| `fetching`        | 已发起传输（含回退切换）       | `body`、`empty`、`failed`、`rejected`                        |
| `body`            | 已取得正文                     | `window_returned`                                            |
| `window_returned` | 已返回窗口与完整性             | `continued`（按 `startChar` 续读）、`complete`（完整性成立） |
| `empty`           | 传输或提取成功但没有可用正文   | 本批次内终态                                                 |
| `failed`          | 传输、超时或提取失败           | 本批次内终态                                                 |
| `rejected`        | URL 安全校验未通过             | 本批次内终态                                                 |
| `skipped`         | 因授权、额度或取消在本批未发起 | 不进入已执行计数（`K06`）                                    |

约束：`body` 只能由 `fetching` 到达；`complete` 只能由 `window_returned` 且完整性成立时到达；`empty`、`failed`、`rejected` 不得在本批次内被改写为 `body`。重试产生同一 URL 的新尝试，失败事实保留在旧尝试上，不被后续成功覆盖（`K17`）。

## 不变量

1. **片段与正文分离**：`search_snippet`、标题或搜索结果包装不得作为已读正文返回，也不得标记为完整抓取；只有实际取得正文的页面进入 `body`。
2. **部分失败不整体失败**：同一批次中一页失败不导致整个任务失败；失败项单独记录，成功页面保留并可用。
3. **不重复抓取成功页面**：重试与回退只针对失败项；不重新抓取本批已成功的页面。
4. **正文不足必须表达窗口与完整性**：不足时返回阅读窗口、覆盖范围与完整性，允许按 `startChar` 续读；不得把摘要或候选片段包装成完整正文。
5. **URL 安全校验不可绕过**：只允许 HTTPS；逐跳重新校验并拒绝任一私网地址；直连固定到已验证地址，代理路径也只发送固定 IP 目标；TLS SNI、证书校验与 Host 保持原域名。校验失败即 `rejected`，不得降级为明文 HTTP、跳过逐跳校验或直连未验证地址。
6. **发现渠道不限制读取路径**：原生路线、MCP 路线发现的 URL 与用户显式提供的 URL 使用同一读取与校验合同；抓取渠道不必与发现渠道一致。接受哪些 URL 进入本动作由候选与显式引用规则决定（`C20`、`C01`），本合同不放宽该范围。
7. **读取成功不等于事实成立**：取得正文只是可登记为来源的前提（`K14`）；相关性、矛盾与支持关系由 `C22`、`C23` 判断。
8. **完整性表达不被投影改写**：裁剪、压缩与用户可见表达（`K07`、`K08`、`K15`）不得把窗口片段、空正文或失败页面改写为「已完整读取」。
9. **委派不改变读取边界**：子运行复用本合同；子任务抓取能力缺口按 `Q07` 登记，额度从父级显式分配（`C15`、`K06`）。
10. **不新设数值门槛**：单次批量上限、超时与完整性判定来自受控配置与账本（`K06`、`K18`），本合同不新设抓取数量、超时或完整性阈值。

## 异常处理

| 失败分类           | 反馈对象与可恢复性                                                                                                 | 不得发生的行为                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 传输失败或超时     | 保留失败项与原因，反馈给 `C14`、`C17`（`K17`）；按原因重试、使用已获准提取回退，或由模型改选 URL／阅读窗口；可恢复 | 紧密无限重试；重新抓取本批全部成功页面；因一页失败终止整个任务 |
| 空正文             | 标记 `empty` 并保留失败事实，反馈给 `C14` 与 `C22`；可恢复（换页或换窗口）                                         | 把空正文当作已读内容；用搜索片段填充                           |
| 部分页面不可读     | 保留成功页面并明确不可读项；结论可基于其余来源（表达归 `C25`／`K15`）；可恢复                                      | 把不可读伪装为已读；隐藏不可读项                               |
| URL 安全校验拒绝   | 标记 `rejected` 并给出原因；不可恢复，不得绕过                                                                     | 降级为 HTTP、跳过私网复核或固定到未验证地址                    |
| 续读窗口非法或越界 | 作为参数错误反馈给模型（反馈合同见 `K16`）；可恢复                                                                 | 静默截断并声称已读完                                           |
| MCP 提取不可用     | 按冻结顺序切换到已获准回退，并如实记录实际使用的提取路径；可恢复                                                   | 把回退结果冒充 MCP 提取成功；静默失败                          |
| 授权关闭或撤回     | 不发起新的读取，保留已有成功页面，反馈停止原因（`K09`）                                                            | 以「已获准」为由继续读取；把授权拒绝算作抓取失败               |
| 用户取消或修订到来 | 停止本批未发起项，保留已完成前缀；迟到结果按旧修订观察（`K03`）                                                    | 取消后启动新的读取；把迟到结果当作新修订证据                   |

失败分类、恢复轨迹与关联记录分别由 `C17`、`C14`、`C26` 承担；本表只固定反馈对象与「什么情况下不得继续」，具体错误码与事件字段属 `K17`。

## 消费方

| 消费方 | 消费的字段                                       | 用途                                                                                                                                 |
| ------ | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `C21`  | 全部输入与输出字段                               | 责任组件：执行批量读取与窗口续读、URL 安全校验、失败分类与完整性表达                                                                 |
| `C22`  | 正文窗口、窗口位置与完整性、失败项分类、批次汇总 | 决定哪些页面可登记为可引用 evidence：只有取得正文（`fetched_body`）的选中页面才登记；`search_snippet` 与失败抓取不生成 `Wn`（`K14`） |
| `C15`  | 本批读取结果、失败项、用量归属与未解决问题       | 子任务网页核验的输入与报告来源：子报告必须给出实际来源、未解决问题与用量，且不是未经验证的最终事实（`Q07`）                          |

相邻而非消费的关系：`C20` 提供候选与路线状态（`K11`），`C18` 提供提取传输（`K18`），`C04`／`K09` 决定能否读取，`C13`／`K06` 计量，`C26`／`C27` 记录与解释；它们通过各自合同交接，不在此重复定义。

## 验证

本合同需要的证据类别定义在各 `V*` 对象中，本文件不新增判据：

| 判据  | 适用于本合同的内容                                                                                                          |
| ----- | --------------------------------------------------------------------------------------------------------------------------- |
| `V03` | 局部机械不变量：`urls` 与 `startChar` 参数校验、逐跳 HTTPS 与私网地址拒绝、窗口与完整性字段、片段不得升级为正文             |
| `V04` | 跨组件与生产入口：批量读取、一页失败而其余页面仍可交付、窗口续读、取消与授权关闭、提取回退切换的真实入口行为                |
| `V06` | 语义质量：部分来源不可读时结论仍须由其余来源支持，需要真实模型场景、明确判据与人工抽检                                      |
| `V07` | 诊断可定位性：`C18` → `C21` → `C22` 路径上「抓取成功但没有正文」须分离呈现传输成功、正文校验与阅读窗口                      |
| `V05` | 不适用：供应商端点与协议兼容不是本合同的读取窗口判据；MCP 服务的协议证据属 `K18`，原生搜索子请求属 `K12`／`K11`             |
| `V02` | 登记关联：本合同的机械不变量须在 [evidence.md](../testing/evidence.md) 登记合法案例、违例案例、检测位置、恢复行为与对应测试 |

`V03`–`V07` 当前状态一律为「未运行」或「待执行」（见 [acceptance-matrix.md](../testing/acceptance-matrix.md)）；引用它们不表示本合同已通过验收，也不表示读取路径已可用。
