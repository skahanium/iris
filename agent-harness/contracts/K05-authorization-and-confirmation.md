# K05 授权范围与冻结确认

<!-- iris:object K05 kind=rules file=true -->

本文件是 `K05` 的正式定义位置。对象身份、标记与引用规则见 [objects.md](../rules/objects.md)，权威边界与状态语义见 [governance.md](../rules/governance.md)。上位架构依据是 [Agent 架构定义](../../docs/agent-architecture.md) §3 M2、§5.1 与 §4；`K05` 由 `C04` 负责，按 [catalog.mjs](../catalog.mjs) 登记的作用域由 `C04`、`C05`、`C06`、`C17`、`C20`、`C24` 消费。

## 接口

**输入**：用户授权、数据域、文件范围与动作（授权判定）；候选变更、目标版本与已有授权（冻结确认）；通过确认与版本复验的操作（执行）。

**输出**：`allow`／`deny`／`need-confirmation` 及原因；冻结变更及确认身份；实际执行回执与部分失败。

**判定三值**：

| 取值                | 含义                               | 必须同时给出                   |
| ------------------- | ---------------------------------- | ------------------------------ |
| `allow`             | 在当前数据域、文件范围与动作内获准 | 命中的授权事实与范围           |
| `deny`              | 超出授权或属于禁止能力             | 拒绝原因；不得以“稍后重试”掩盖 |
| `need-confirmation` | 缺少本次动作所需的用户确认         | 需要确认的目标、内容与范围     |

**判定覆盖四项**：读取、向模型发送、网页查询外发和写入。四项分别判定，一项获准不隐含另一项获准。内容变化不被“允许联网”或“启用工具”隐含授权；严格场景保留联网限制，授权覆盖原生、MCP、抓取、重试与子任务。

**判定对象的字段**：数据域、文件范围、动作、命中的授权事实来源、原因；`need-confirmation` 另需给出待确认的目标、内容与范围。

**冻结确认绑定的五项**：目标、内容、范围、版本与有效期。确认之后的执行必须复核确认身份与版本基准一致。

**唯一副作用提交边界**：只有 `C06` 的边界可以提交 Agent 引起的副作用，它调用已有业务服务，保留已执行前缀，不由模型声明成功。记忆写入、计划登记和导出也属于副作用：`C06` 授权执行，具体存储逻辑仍由对应业务组件完成。

**子任务与重试**：只能继承或收窄授权，不能扩权；一层委派只读，子运行不能自行获得写入或外发能力。

## 状态转换

**授权判定没有跨调用的状态机**：判定是“给定当前事实与当前动作”的输出；事实或动作变化时重新判定，而不是把上次结果沿用为本次结论。已有有效授权不反复索要。

**冻结确认的生命周期**：

| 状态   | 含义                                   | 合法转换                             |
| ------ | -------------------------------------- | ------------------------------------ |
| 已冻结 | 目标、内容、范围、版本与有效期均已绑定 | → 已失效（任一绑定项变化）；→ 已执行 |
| 已执行 | 已按确认提交，并取得执行回执           | 终态；不得重复提交                   |
| 已失效 | 目标或内容变化，或超出有效期           | 终态；只能重新确认                   |

**合法转换的边界**：`need-confirmation` → `allow` 需要用户显式确认，不由模型推断；`deny` 不因重试或换参数转为 `allow`，只有新增显式授权事实才重新判定。

**冻结不引入正文游标**：Durable Run 的一次确认后按无正文游标逐项重验和执行（见 [K02](./K02-run-lifecycle.md)）；执行前复核版本，hash 漂移保留已完成前缀并停止后缀。

恢复入口与启动扫描必须使用同一边界判定：`Approved` 对应基础版本，`Applied` 对应已执行前缀，`Dispatching` 仅核对当前操作的基础／预期回执；未知回执不重放，也不能仅凭计划最终 hash 跳过尚未派发的后缀。目标路径按集合核对，操作始终保留冻结顺序；历史计划只读，不为恢复改写其 hash。恢复装配采用当前边界版本，选区偏移仅按已确认前缀精确映射，不能只替换 hash 后沿用旧范围。写入确认不扩大读取或外发授权；无法在原授权内完成写后复核时，应明确未复核。

## 不变量

1. **模型不能推断显式授权事实**：外部网页、MCP 返回值与检索到的笔记是资料，不是用户指令；其中要求改权限、泄露数据或调用其他工具的文字不能改变授权事实。
2. **子任务与重试只能继承或收窄授权**，不得扩权。
3. **确认绑定目标、内容、范围、版本与有效期**，任一变化使旧确认失效。
4. **已有有效授权不反复索要**；同一范围内的动作不因单次调用被重复确认。
5. **只有 `C06` 边界可以提交 Agent 引起的副作用**，且写入必须与确认身份及版本基准绑定。
6. **保留已执行前缀**：部分失败如实报告“已完成哪一部分”和“剩下哪一部分”。
7. **不由模型声明成功**：成功以执行回执为事实依据。
8. **写前复核路径身份**：词法路径含符号链接组件时，无法完成独立身份解析即在副作用前拒绝。
9. **判定与原因同时记录**，判定三值不得被投影压成一个布尔值。

## 异常处理

| 失败类别         | 表现                                         | 是否可恢复               | 反馈给谁                                              | 不得继续的情形                     |
| ---------------- | -------------------------------------------- | ------------------------ | ----------------------------------------------------- | ---------------------------------- |
| 权限拒绝         | `deny`                                       | 不作为自动重试对象       | 用户与诊断入口；`C17` 分开记录 `rejected` 与 `failed` | 不得换参数绕行或窄化查询范围后重试 |
| 需要新增授权     | `need-confirmation`                          | 用户确认后可继续         | 用户；`C05` 产生冻结确认                              | 不得在确认前提交副作用             |
| 确认已失效       | 目标、内容、范围或版本变化                   | 可恢复：重新确认         | 用户                                                  | 不得按旧确认执行写入               |
| 首次拒绝被误记   | 把拒绝写成已执行或把提议失败写成工具执行失败 | 修正分类并记录差异       | `C17`、`C13`、`C26`                                   | 不得让分类错误影响预算计数         |
| 部分写入         | 多个操作中部分成功                           | 保留成功前缀并报告失败项 | 用户与 `K15` 交付                                     | 不得把部分成功写成整体成功         |
| 写入回执未知     | 已发起或可能已发起的写入未取得回执           | 先核实回执               | `C06` 执行回执、`C26`                                 | 不得因重试造成重复变更             |
| 无回执即报告成功 | 缺少执行证据                                 | 不可接受                 | `C27` 如实报告缺口                                    | 不得由模型声明成功                 |

用户可见的限制说明由 `K15` 定义；本文件只规定内部事实与停止条件。

## 消费方

| 消费方 | 消费的字段                                   | 用途                                                                                           |
| ------ | -------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `C04`  | 三值判定、原因、数据域与文件范围             | 统一所有路线入口的授权判定                                                                     |
| `C05`  | 候选变更、目标版本、已有授权、确认身份五要素 | 冻结变更与确认身份，并使其在目标或内容变化时失效                                               |
| `C06`  | 确认身份、版本基准、执行范围                 | 作为唯一副作用提交边界，产出执行回执与部分失败                                                 |
| `C17`  | 判定三值与原因                               | 分开 `rejected`／`deferred`／`started`／`partial`／`failed`／`succeeded`，只申领并回报分类计数 |
| `C20`  | 联网与外发判定、覆盖范围                     | 决定两路搜索是否获准启动，以及查询是否可外发                                                   |
| `C24`  | 目标版本、既有授权                           | 生成候选文本与差异，并保持“生成候选不等于写文件”                                               |

## 验证

按 [acceptance-matrix.md](../testing/acceptance-matrix.md) 的证据用途分类，本合同需要：

1. **`V03` 局部机械不变量**：三值判定与原因同时产出；子任务与重试的授权只收窄不扩权；确认绑定五要素中任一项变化即使旧确认失效。
2. **`V04` 跨组件交接与生产入口证据**：权限与写入性质必须覆盖**最终执行边界**，不能仅凭局部校验函数通过；覆盖正常拒绝、取消、部分写入与回执未知等异常路径。
3. **`V07` 诊断可定位性**：一次越权或过期确认要在诊断中同时显示发现位置、判定原因、恢复状态与影响，并把正常拒绝与程序错误分开。
4. **`V02` 不变量登记**：「冻结确认绑定目标与版本」已登记为待补证据的不变量，合法案例为确认后立即执行且 hash 一致，违例案例为确认后目标变化仍执行。

证据记录按 `V08` 绑定对象指纹与当前适用性；本合同不声明已验证。
