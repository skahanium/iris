# K18 MCP 传输与外部工具边界

<!-- iris:object K18 kind=rules file=true -->

本文件是 `K18` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**外部工具经由什么边界被信任、被冻结、被调用和被限制**：连接健康／发现成功／业务结果有效的分离、白名单 binding 的信任确认与冻结、运行中的撤销检查、输出边界，以及不得暴露的能力。责任组件是 `C18`（MCP 连接与传输），消费方是 `C18`、`C16`、`C20`、`C21`。

本文件只定义 MCP 传输与外部工具边界，不复制相邻对象的正式定义：授权与确认见 [K05](./K05-authorization-and-confirmation.md)，工具面版本与派发观察见 [K10](./K10-tool-surface.md)，额度租约见 [K06](./K06-budget-ledger.md)，联网授权与查询外发见 [K09](./K09-web-authorization.md)，两路搜索协调见 [K11](./K11-dual-path-search.md)，正文窗口与完整性见 [K13](./K13-web-reading-window.md)，来源身份与账本引用见 [K14](./K14-evidence-and-provenance.md)，事件与审计见 [K17](./K17-audit-events.md)。

本文件的编译依据是架构定义的 M6 与外部只读边界，以及 [ARCHITECTURE.md](../../ARCHITECTURE.md) 记录的 `external.read` 边界。外部 MCP 工具不分配业务工具 ID，其数量按服务动态计算（见 [objects.md](../rules/objects.md) §1.3）。`implementation.state` 只描述源码事实，不代表合同正确或用户任务可用；设置写入冲突（`Q02`，对应架构 `F01`）与读取路径写库（`Q05`，对应架构 `F04`）是已确认的待修正项，按 [current-baseline.md](../requirements/current-baseline.md) 引用，本文件不宣称它们已处理。

## 接口

**输入**（设计层逻辑类型，不是已存在的 Rust 类型或 IPC 字段）：

| 输入           | 含义                                                                          | 权威所有者                                                 |
| -------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 冻结的服务配置 | 绑定生效时冻结的 transport／config、递归输入 Schema、参数映射与输出策略       | `C18` 持有冻结副本；信任位来自用户确认                     |
| 信任与哈希     | 用户对精确 provider／tool／schema 的显式信任确认、binding hash、provider hash | 用户确认（`C05` 记录确认身份）；`C18` 校验                 |
| 发现或调用请求 | 能力发现请求，或某次具体工具调用请求及其参数                                  | `C16`（工具面）、`C17`（派发）；模型不能直接消费 discovery |
| 运行中撤销信号 | live provider hash 与 enablement 状态                                         | `C18` 读取；配置变更入口负责写入                           |
| 公共边界输入   | 授权决定、额度租约、取消信号、联网开关                                        | `C04`（`K05`、`K09`）、`C13`（`K06`）                      |
| 凭据状态       | 某服务是否已配置凭据（只记状态，不记内容）                                    | 凭据服务；安全边界见 [SECURITY.md](../../SECURITY.md)      |

**输出**：

1. **传输结果**：连接是否成功、传输层错误、耗时与请求身份；不包含参数或原始输出。
2. **发现状态**：本次发现是否成功、发现到的工具与其输入 Schema；runtime discovery 只表示能力发现。
3. **业务结果有效性判断**：调用是否取得可用的业务结果（与传输成功、发现成功分别表达）；成功输出向模型返回正文和账本来源引用 `E{id}`。
4. **服务能力与撤销事实**：当前 binding、信任位与 live provider hash／enablement 的一致或漂移结论。

**当前实现事实（源码基线，不构成本合同正确性声明）**：输出正文只接受最多 8,000 字符的文本或 JSON，证据摘录最多 2,000 字符；事件、审计与检查点不保存参数或原始输出；`web.search` 与 `web.fetch` 的健康状态按 `(provider_id, capability)` 分别记录。这些数值与形状来自现行实现与配置，本合同不新设字符数、超时或候选数量阈值。

**边界**：`C18` 不决定是否授权（`C04`），不组装模型可见工具面（`C16`），不合并两路搜索结果（`C20`），不判断正文完整性（`C21`），不裁定结论是否成立（`C23`）。

## 状态转换

**连接健康、工具发现成功、业务结果有效是三个不同事实**，各自独立表达，不得互相代替：连接成功不等于发现成功，发现成功不等于调用成功，调用成功不等于结果有效。

binding 的生命周期：

| 阶段           | 进入条件                                                                                          | 允许的去向                                                    |
| -------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `discovered`   | 服务可连接并返回工具与递归输入 Schema                                                             | `under-review`、`revoked`                                     |
| `under-review` | 管理中心已审查名称与递归输入 Schema，检查声明的能力范围                                           | `trusted`、`rejected`                                         |
| `trusted`      | 用户对精确 provider／tool／schema 显式确认信任，白名单 binding 创建                               | `active`、`revoked`                                           |
| `active`       | Accept 事务冻结信任位、binding hash、provider hash、transport／config、Schema、参数映射与输出策略 | `revoked`（撤销检查失败）、`active`（同一冻结配置下重复调用） |
| `revoked`      | live provider hash／enablement 与冻结配置不一致，或用户撤回信任                                   | 终态：不执行调用；重新配置后走完整审查与确认                  |
| `rejected`     | 名称或 Schema 暴露被禁止的能力                                                                    | 终态                                                          |

运行中**只执行冻结配置**，并以 live provider hash／enablement 作撤销检查；本合同不建立第二套工具执行状态机（派发状态属 `K10`），也不新建第二套 Run 状态（属 `K02`）。

## 不变量

1. **三个事实分离**：连接健康、工具发现成功与业务结果有效分别记录；runtime discovery 只表示能力发现，不被业务调用结果覆盖或冒充。
2. **声明不是证明**：`readOnlyHint=true` 只是服务端声明，不是 Iris 对第三方实现的证明；Iris 无法独立验证已信任第三方服务端是否忠实实现其声明，该限制必须如实表达。
3. **信任必须是对精确对象的显式确认**：管理中心审查名称与递归输入 Schema，并要求用户对精确 provider／tool／schema 显式确认信任后才创建白名单 binding；模型不能直接消费 discovery，也不能自行增权。
4. **运行中只执行冻结配置**：信任位、binding hash、provider hash、transport／config、Schema、参数映射与输出策略在 Accept 事务中冻结；运行中不得改写，也不得用新哈希自动扩权。
5. **撤销检查不可省**：每次执行前用 live provider hash／enablement 作撤销检查；不一致即拒绝执行，而不是静默重算信任。
6. **外部调用不绕开公共边界**：配置、超时、取消与密钥都不绕过授权（`K05`）、预算与计数（`K06`）、联网开关与查询外发（`K09`）、工具面版本（`K10`）与派发观察（`K17`）。
7. **作用域隔离**：classified、local-only、Skills 与隐式关键词匹配均不能获得 `external.read`；每个 normal-domain Run 必须显式选择 binding（`C16`／`C05`）。
8. **能力拒绝清单**：拒绝声明或 Schema 暴露写入、发送、删除、日历变更、进程与 secret 的工具；该拒绝发生在创建 binding 之前。
9. **输出与记录边界**：输出正文与证据摘录遵守当前实现的字符上限；事件、审计与检查点不保存参数或原始输出；原始 provider JSON 不进入事件、审计、错误或评测报告。
10. **引用绑定本 Run**：成功输出向模型返回正文和账本来源引用 `E{id}`；最终结构化提交只能引用本 Run 实际采用的 `E{id}`（登记规则见 `K14`，交付表达见 `K15`）。
11. **设置往返一致**：MCP 主服务与备用顺序只有一个编辑语义；简略入口可以只展示主服务，但更换主服务不得静默删除备用项；完整设置、简略设置、IPC 与持久配置必须往返一致（`Q02` 是待修正差异）。
12. **查询保持只读**：普通列举与读取路径不得触发隐藏的配置变更；配置升级应发生在明确的保存／升级边界，既有信任与快照不随新哈希自动扩权（`Q05` 是待修正差异）。

## 异常处理

| 失败分类                                  | 反馈对象与可恢复性                                                                          | 不得发生的行为                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 连接失败或断连                            | 保留具体服务与请求身份，按外部服务／传输错误分类（`K17`）；可恢复（重连或按冻结顺序换服务） | 把断连归因成工具执行失败；静默切换到未冻结的服务                                       |
| 鉴权失败或凭据缺失                        | 记录配置排查需求；凭据只记「已配置／未配置」状态；可恢复（用户补充配置）                    | 直接认定供应商故障；在日志、错误或事件中输出密钥内容                                   |
| 发现成功但调用失败                        | 发现状态与调用结果分别表达；可恢复（按失败原因处理）                                        | 用发现成功证明业务可用                                                                 |
| 传输成功但结果无效                        | 标记结果无效并说明判据；可恢复（换等价服务或按合同重试）                                    | 把传输成功当作业务成功；把原始载荷透传进事件或审计                                     |
| 输出超出字符上限                          | 按白名单输出映射缩略并确定性验证；如实表达缩略事实                                          | 静默截断后冒充完整输出；把原始 JSON 写入日志或评测报告                                 |
| 冻结配置漂移（hash 或 enablement 不一致） | 拒绝执行并给出漂移事实；要求重新走审查与显式确认；可恢复                                    | 自动扩权；用新哈希替换冻结信任；在运行中读取路径就地改写配置                           |
| 读取路径触发配置写入（`Q05`）             | 按目标合同将升级移动到明确的保存边界，查询保持只读；在修正前如实记录变更事实                | 让普通列举产生隐藏变更并影响既有绑定或快照                                             |
| 两个设置入口保存语义冲突（`Q02`）         | 统一写入语义并保留备用项；往返不一致按缺口处理                                              | 因单元素写入静默丢弃已有备用候选；由前端局部状态决定实际路线                           |
| 候选搜索服务不可用                        | 保留另一条路线的真实结果（`K11`）；抓取是否可用单独判断（`K13`）                            | 因 MCP 失败丢弃原生结果；宣布整个联网能力不可用                                        |
| 被拒绝的能力或作用域申请                  | 返回明确原因与拒绝位置；不可恢复（该服务不进入白名单）                                      | 以改名或包装 Schema 绕过拒绝清单；对 classified 或 local-only 任务开放 `external.read` |

公共边界不可绕过的含义是：容错不能把失败转换成扩权。重试、回退与换服务只允许在既有授权、冻结配置与额度内发生。

## 消费方

| 消费方 | 消费的字段                                                      | 用途                                                                                               |
| ------ | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `C18`  | 全部输入与输出字段                                              | 责任组件：建立与校验 binding、冻结配置、执行撤销检查、表达三类事实与输出边界                       |
| `C16`  | 发现状态、工具输入 Schema、能力范围与拒绝清单结论、binding 身份 | 组装模型可见工具面：Planned 不暴露、暴露参数必须被消费或明确拒绝、外部工具按授权与上下文进入工具面 |
| `C20`  | 冻结的服务配置与顺序、各服务能力状态、调用结果与不足说明        | 经 `C18` 调用选定搜索服务，形成两路状态与合并线索；不能因一路失败伪造另一侧结果（`K11`）           |
| `C21`  | 提取服务的冻结顺序、可用性状态、输出边界与 `E{id}` 引用         | 默认使用已配置 MCP 提取并保留获准的安全抓取回退；正文不足时返回阅读窗口与完整性（`K13`）           |

相邻而非消费的关系：`C04` 决定授权与外发（`K05`、`K09`），`C13` 计量（`K06`），`C17` 派发并回报观察（`K10`），`C22` 登记来源身份（`K14`），`C25` 表达限制说明（`K15`），`C26`／`C27` 记录与解释（`K17`）。用户自行付费的优质服务与开箱即用工具并存（`N19`）；本合同的信任确认与冻结规则对两类服务同样适用。

## 验证

本合同需要的证据类别定义在各 `V*` 对象中，本文件不新增判据：

| 判据  | 适用于本合同的内容                                                                                                          |
| ----- | --------------------------------------------------------------------------------------------------------------------------- |
| `V03` | 局部机械不变量：冻结字段与哈希比较、能力拒绝清单、输出字符上限、查询路径不写库、设置往返的单语义                            |
| `V04` | 跨组件与生产入口：MCP 主备切换与两个设置入口交替保存、运行中撤销检查、入站绑定与出站调用、搜索与抓取经 MCP 的真实入口行为   |
| `V05` | 端点与服务适配：MCP 服务发现与调用的协议证据、错误分类与能力声明；不得仅凭服务名称或 `readOnlyHint` 判定能力                |
| `V07` | 诊断可定位性：MCP 断连、鉴权失败、发现成功但调用失败、传输成功但结果无效在诊断中分离呈现，且不泄露参数或原始输出            |
| `V06` | 不适用：语义质量不是本合同的判据；输出相关性由 `C23`／`C25` 与相应证据类别处理                                              |
| `V02` | 登记关联：本合同的机械不变量须在 [evidence.md](../testing/evidence.md) 登记合法案例、违例案例、检测位置、恢复行为与对应测试 |

`V03`–`V07` 当前状态一律为「未运行」或「待执行」（见 [acceptance-matrix.md](../testing/acceptance-matrix.md)）；引用它们不表示本合同已通过验收，也不表示外部工具边界已正确实现。
