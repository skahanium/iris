## 接口

**输入**：Run 合同、动作申请、用量。

**输出**：执行阶段、额度租约、剩余资源。

**记账维度**（数值可能偶然相同，但不能互相替代）：

| 维度            | 含义与范围                                          |
| --------------- | --------------------------------------------------- |
| 工具提议        | 模型提出的调用，可能被拒绝或延后，不等于实际执行    |
| 已派发工具调用  | 已进入受控派发路径的调用；Host 保底调用也有计入逻辑 |
| 模型轮次        | 实际发生的模型请求次数，含重试与切换产生的额外请求  |
| token           | 实际消耗的用量事实                                  |
| 时间            | 实际耗时                                            |
| 子任务分配      | 从父级总资源中显式分配给子运行的额度                |
| Broker 内部请求 | 一次工具调用内部可能访问多个 URL、重试或切换服务商  |
| 页面数          | 实际请求、成功读取、获得正文的页面数分别记录        |

**申领与回报**：每个模型请求、工具调用与原生搜索子请求都要携带 Run ID、输入修订号、父调用 ID、尝试 ID（字段身份见 [K01](./K01-request-identity.md)），向 `C13` 申领额度；`C17` 只申领并回报分类计数，分类计数由 `C13` 维护。网关侧的重试与用量挂在同一调用身份上，不隐藏额外模型请求。

**层级**：`C13` 保留父子层级明细，同时控制顶层总消耗。父级给子任务显式分配额度，子运行按子策略运行，不能自行扩大。

**权威唯一**：额度只有一个权威账本，不存在每层各算一套总账。

**执行与恢复边界**：根入口装配 `model_turn_ledger`，主阶段与确认后复核分别沿用冻结策略；child scope 的每次申领同时扣所属阶段与自身额度，父阶段先前消耗不能直接和子上限比较。Direct、循环、摘要、子任务、原生搜索、重试与切换均在真实请求前原子申领，未绑定请求拒绝派发。工具阶段为最终综合保留一次请求及现行输出上限允许的额度，内部调用不可占用该预留。

申领、派发与逐尝试结算以带版本的 JSON 写入现有 `agent_run_steps`，内存结构仅作缓存；结算幂等，恢复不刷新额度。单次响应检查与 Run 已报告用量汇总分开，未知用量保留预留而不补零；已有 `TokenUsage` 无法区别显式全零与缺失报告时保守记为未知。旧 Run 无可信账本时不得获得新模型额度；符合安全条件的已确认写入仍可恢复，可选模型复核跳过并说明原因。

## 状态转换

预算维度本身不引入业务状态机；可观测的状态是**租约**与**类别剩余**。

| 状态         | 含义                           | 合法转换                                     |
| ------------ | ------------------------------ | -------------------------------------------- |
| 已申领未派发 | 提议已到达派发路径但未实际执行 | → 已计入提议与模型轮次；不增加已派发工具调用 |
| 已派发       | 实际进入受控执行               | → 已回报（成功、部分成功或失败）             |
| 已回报       | 本次派发的事实已入账           | 终态；不因后续重试改写历史计数               |
| 类别耗尽     | 该类别额度用尽                 | → 该类别的新动作不再派发；其他类别保持可用   |

**禁止转换**：未派发的无效提议不得转为“已派发工具调用”计数；被拒绝的提议不得增加工具执行次数；单次网络动作不得被拆记成两次派发来绕过类别上限。

**当前受控配置（代码事实，不是新门槛）**：

- Standard／Delegated／DurableApply 的 `max_network_tool_calls` 都是 `6`。这是**主循环 Network 类工具额度**，不是全部服务商请求、页面或父子任务网络活动的统一总数。
- `web_search`、`web_fetch` 属于 Network 类，主循环的搜索与抓取派发共用该类别额度。
- Standard 预算为 8 次模型、24 次总工具，并受 local 12、network 6、external-read 6、runtime 4 的分类上限约束；每个模型回合最多执行 2 个 catalog 标记的发现调用，超出的独立发现动作返回 `deferred_for_feedback`，不消耗额度。
- `web_fetch` 接收 `urls` 数组，一次调用可处理多页；主路径按待抓 URL 数计算**单次**上限，最多 8。

**明确不作为全局上限的数值**：非网页派发上下文中出现的 `max_web_fetches: 5` 不属于网页主链路的全局抓取上限。第一轮附录把它列为“整轮抓五篇”并据以推导引用数量，该推论已撤回，本文件不得据此声称页面数上限或统一总数。

## 不变量

1. **额度只有一个权威账本。** 禁止每层另算总账、重复扣费或漏记。
2. **未派发的无效提议不消耗“实际工具执行次数”**，但它已经消耗的模型回合、token、时间及纠偏次数必须照实计入，不能形成免费无限循环。
3. **类别耗尽不封死无关能力。** 一个类别用尽后仍检查其他获准行动与已有材料能否完成任务。
4. **父子层级明细与顶层总消耗同时保留**，不用其中一层替代另一层。
5. **原生搜索辅助模型请求也纳入同一账本**：主对话、摘要、语义验证与受控原生搜索请求都向 `C13` 申领额度。
6. **区分计数类别**：机械重试、模型重新提议与语义改查分开计数，全部纳入同一个顶层预算。
7. **被拒绝的提议不得写成已执行**，分类计数错误必须修正并记录差异。
8. **预算调整必须兼容旧 Run 存档**，旧确认不扩权。
9. **额度耗尽与模型质量分开表达**：不得把预算结果写成“模型能力降级”。

## 异常处理

| 失败类别                       | 表现                           | 是否可恢复                           | 反馈给谁                                    | 不得继续的情形                                       |
| ------------------------------ | ------------------------------ | ------------------------------------ | ------------------------------------------- | ---------------------------------------------------- |
| 类别耗尽                       | 某一类别额度用尽               | 该类别不可继续；其他类别按授权判断   | `C14` 收到停止理由；`C25` 按 `K15` 表达限制 | 不得以单路结果冒充双路完成，也不得继续派发该类别动作 |
| 预算不足以启动已承诺的两条路线 | 双路搜索资源不足               | 说明本次限制                         | 用户与诊断入口                              | 不得伪造另一侧结果                                   |
| 存档兼容失败                   | 同版本不同数值的旧策略读取失败 | 需要处理旧策略的识别、读取与恢复语义 | `C13`；`Q13` 记录待证事实                   | 不得无说明地给已有 Run 扩权或破坏旧存档读取          |
| 计数不一致                     | 账本与实际派发、成功观察不一致 | 修正计数并记录差异                   | `C26`、`C27`                                | 不得用修正后的数字掩盖原始失败                       |
| 结果未知的副作用               | 非幂等副作用回执未知           | 先核实回执，不进入盲目自动重试       | `C06`、`C26`                                | 不得因重试造成重复变更                               |

预算调整的具体兼容实现不是本文件确定的唯一方案（`Q13`）；「网络额度是否为主要瓶颈、新额度取多少」仍是待验证事项（`Q19`），不作为双路与 LOOP 的无条件前置。

## 消费方

| 消费方 | 消费的字段                         | 用途                                                    |
| ------ | ---------------------------------- | ------------------------------------------------------- |
| `C12`  | 额度租约、调用身份、实际用量       | 执行调用并回报响应、错误、实际用量与传输状态            |
| `C13`  | 全部维度、父子层级、顶层总消耗     | 维护唯一权威账本，输出执行阶段与剩余资源                |
| `C15`  | 子任务分配额度、父级授权与额度     | 从父级总资源中显式分配额度，并回报子运行用量            |
| `C17`  | 派发额度、工具面版本、分类计数规则 | 按每次提议申领并回报派发状态，不自行维护分类计数        |
| `C20`  | 网络额度、双路资源预留             | 从 `C13` 申领资源并冻结路线，记录各路线的用量与不足说明 |
| `C21`  | 页面数相关计数、抓取额度           | 批量抓取时区分实际请求、成功读取与获得正文的页面数      |

`C12`、`C15`、`C20` 与 `C21` 在 [catalog.mjs](../catalog.mjs) 中以 `consumes` 声明对本合同的消费。

## 验证

按 [acceptance-matrix.md](../testing/acceptance-matrix.md) 的证据用途分类，本合同需要：

1. **`V03` 局部机械不变量**：未派发的提议不计入已执行工具数；类别耗尽不封死无关能力；分类计数不被重复扣费或漏记。合法案例与违例案例成对登记在 [evidence.md](../testing/evidence.md) 的登记表里。
2. **`V04` 跨组件交接与生产入口证据**：预算调整要处理旧策略的识别、读取与恢复语义，并覆盖“不足以启动两条路线”“类别耗尽”“父子预算分配”等异常路径；不得无说明地给已有 Run 扩权。
3. **`V07` 诊断可定位性**：停止必须能说明是任务完成、需要澄清、权限受限、服务失败还是具体预算耗尽，并定位到具体维度，而不是统一解释为模型能力降级。

定向离线回归使用 `review_regression_a_`，覆盖父子计数、并发争用、最终预留、Direct 一次额度、分阶段恢复、未知用量与重复结算。它们只支持对应机械与交接结论；`Q13`、`Q19` 的其余待证事项及 V05/V06 不由本轮替代，数值保持不变。
