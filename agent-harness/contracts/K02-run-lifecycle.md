# K02 Run 生命周期与任务结果分离

## 接口

**输入**：接受、执行、暂停、取消、结束事件。

**输出**：持久状态与安全恢复视图。

| 维度         | 取值                                                                                | 归属                             |
| ------------ | ----------------------------------------------------------------------------------- | -------------------------------- |
| Run 生命周期 | `accepted`（已接受并持久化）、执行中、`paused`（暂停）、`cancelled`（取消）、已结束 | `C02` 拥有的持久状态             |
| 任务结果     | `completed`、`partial`、`blocked`                                                   | `C25` 交付时表达的语义结果       |
| 安全恢复视图 | 安全快照与过程展示                                                                  | `C02` 输出的投影，只用于恢复展示 |

两个维度正交：生命周期回答“这次运行还在不在进行”，任务结果回答“用户的任务完成了没有”。同一组取值可以独立组合，例如一次已结束的 Run 可以对应 `partial` 结果。

**唯一持久运行状态写入口**：持久运行状态的写入只由 `C02` 的边界完成。其他模块通过交接请求影响它，不能各自建立第二份权威状态或双写。

**安全恢复视图的边界**：过程回放日志是追加式、安全的过程展示，不含工具参数或原始输出，只保存稳定 capability、调用 ID、受限摘要、状态与安全错误码。它不是可据以重建全部 Run 的执行日志。

## 状态转换

**合法转换**（生命周期）：接受 → 执行中；执行中 → 暂停；执行中或暂停 → 取消；执行中、暂停或取消 → 已结束。接受状态必须先持久化，再进入策略、上下文、路由与 provider 调度。

**任务结果的取值由最终交付决定**，不是生命周期转换的别名：`completed` 表示按当前要求完成，`partial` 表示部分完成并带限制说明，`blocked` 表示受阻且需要用户操作或授权。执行结束本身不产生 `completed`。

**中断与恢复的合法恢复范围**：

| 情形               | 可以恢复什么                                                                                                                                            | 不得恢复什么                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 前端断流           | 用安全快照与过程展示回放                                                                                                                                | 不得据回放重新执行模型或工具                   |
| 进程中断           | 安全会话恢复；已冻结的受限变更检查点按未执行后缀继续                                                                                                    | 不得重放未知副作用，不得从事件重建已执行的动作 |
| Direct 与 ToolLoop | 会话与材料安全读取                                                                                                                                      | 不支持进程级续跑                               |
| Durable Run        | 暂停与检查点语义：新计划冻结至多 6 个有序操作与 6 个目标，一次确认后按无正文游标逐项重验和执行；重启只恢复未执行后缀，hash 漂移保留已完成前缀并停止后缀 | 不得重放写入，不得开放新工具                   |

普通 Run 不因具备会话记录而自动获得进程级续跑；扩大执行恢复能力需要单独明确，不能隐藏在“有记忆”这一名称里。

## 不变量

1. **执行结束不等于用户任务成功。** 生命周期状态不得被投影成任务结果，也不得用“进程结束”替代任务成功。
2. **任务结果与生命周期分字段保存**，任何投影都不得把两者压成一个字段。
3. **唯一持久运行状态写入口。** 不存在并行的第二个权威状态机，也不做双写；模块之间只通过合同交接事实与请求。
4. **不能重放未知副作用。** 结果未知的写入先核实回执，不因恢复或重试造成重复变更。
5. **安全恢复视图不是执行日志。** 它只能恢复安全快照与过程展示，不能被当作重放依据。
6. **只有 Durable Run 具有暂停与检查点语义。** Direct 与 ToolLoop 不支持进程级续跑；该差异必须如实表达，不能合并宣传为通用持久 agent。

## 异常处理

| 失败类别         | 表现                            | 是否可恢复                                      | 反馈给谁                              | 不得继续的情形               |
| ---------------- | ------------------------------- | ----------------------------------------------- | ------------------------------------- | ---------------------------- |
| 状态写入冲突     | 同一 Run 收到并发的状态写入请求 | 按唯一写入口串行化并保留原因                    | `C26`、`C27` 记录；`C02` 拒绝越权写入 | 不得出现两个都生效的权威状态 |
| 进程中断         | 终止事件来不及写入              | 由持久状态与缺口规则标识中断或结果未知          | 诊断入口显示“结果未知”                | 不得自动重试未知副作用       |
| 断流             | 前端事件流中断                  | 用安全恢复视图回放                              | 用户可见恢复过程                      | 不得据回放重新执行动作       |
| 检查点 hash 漂移 | 目标文档在检查点之后变化        | 保留已完成前缀，停止后缀                        | 用户与确认边界                        | 不得按旧 hash 继续执行后缀   |
| 取消             | 用户取消 Run                    | 取消信号进入 provider、工具调度与写盘前提交检查 | 用户看到取消结果                      | 取消后不启动新副作用         |

任务结果一侧的限制说明由 `K15` 定义；本文件不规定用户可见措辞。

## 消费方

| 消费方 | 消费的字段                                 | 用途                                                                 |
| ------ | ------------------------------------------ | -------------------------------------------------------------------- |
| `C02`  | 生命周期状态全集、唯一写入口、安全恢复视图 | 接受、执行、暂停、取消、结束事件的持久化与恢复投影                   |
| `C25`  | 生命周期状态、任务结果取值                 | 把两者分开表达，`completed`／`partial`／`blocked` 不写成生命周期别名 |
| `C27`  | 中断标识、结果未知标识、写入冲突记录       | 诊断时区分“发现位置”与“已证实的故障来源”，缺事件必须报告缺口         |

## 验证

按 [acceptance-matrix.md](../testing/acceptance-matrix.md) 的证据用途分类，本合同需要：

1. **`V03` 局部机械不变量**：生命周期与任务结果不被投影合并；同一 Run 的并发状态写入只产生一个权威状态；检查点 hash 漂移时已完成前缀保留、后缀停止。
2. **`V04` 跨组件交接与生产入口证据**：以生产入口验证取消信号进入 provider、工具调度与写盘前提交检查，并覆盖中断、断流与结果未知的异常路径。验收对象是实际组件组合，不是两个替身都被调用。
3. **`V07` 诊断可定位性**：进程中断后诊断必须显示“中断或结果未知”，不得默认执行成功。

证据记录按 `V08` 绑定对象指纹与当前适用性；本轮没有执行新实验，本合同不声明任何验证结果。当前实现事实与缺口见 [current-baseline.md](../requirements/current-baseline.md)。
