# K08 压缩覆盖与长期记忆条目

<!-- iris:object K08 kind=rules file=true -->

本文件是 `K08` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**会话压缩与长期记忆这两件事如何被表达和分开**：被裁剪区间必须有可解释的覆盖或缺口，会话摘要与当前工作状态要保留哪些任务事实，长期记忆条目如何与聊天摘要分离、如何在同作用域保留更新关系、什么情况下才允许持久修改。责任组件是 `C08`（会话压缩与工作状态），主要消费方是 `C08`、`C09`。

本合同引用而不复制相邻对象：请求身份与修订见 [K01](./K01-request-identity.md)、[K03](./K03-instruction-revision.md)，授权与确认见 [K05](./K05-authorization-and-confirmation.md)，本轮装配与覆盖表达见 [K07](./K07-context-assembly.md)，来源身份与支持关系见 [K14](./K14-evidence-and-provenance.md)，交付表达见 [K15](./K15-delivery-result.md)。当前实现事实以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 与源码为准；本合同不代表压缩已经忠实、也不代表用户任务可用。

`C08` 的「摘要覆盖与真实裁剪边界不同源」是已登记的待证事项（`Q08`，2026-09-19 关闭：检测与显式缺口已在位，不同源作为**已知限制**保留），对应缺口 `G05`。长期记忆的写入与作用域语义**已于 2026-09-19 确定**（`Q15` 关闭）：写入只能由 `memory_write` 显式发起且需确认、默认不自动把聊天写成事实、作用域 `global`／`vault`、`clear_scope` 不越界；**有效期与冲突呈现明确不实现**。本文件据此区分「本合同已定的部分」与「明确不做的部分」。

## 接口

**输入**：

| 输入         | 含义                                               | 权威所有者                                                 |
| ------------ | -------------------------------------------------- | ---------------------------------------------------------- |
| 历史区间     | 将进入压缩的会话消息范围及其身份                   | `C02`／`C03`；区间由 `C08` 与 `C07` 的实际裁剪边界共同确定 |
| 实际裁剪边界 | 本轮因规模约束真正被排除在上下文之外的区间         | `C07`（通过 `K07` 的覆盖清单）                             |
| 当前任务事实 | 目标、最新纠正、已撤回信息、已执行动作、未解决问题 | `C01`、`C03`、`C06`、`C17`、`C23`                          |
| 证据时效     | 已登记来源的身份与时间                             | `C22`（`K14`）                                             |
| 长期记忆请求 | 读取或修改授权作用域内条目的请求                   | `C09`；读写授权由 `C04` 决定（`K05`）                      |
| 作用域与版本 | 条目所属作用域及其版本                             | `C09`                                                      |

**输出**：

1. **会话摘要覆盖**：被压缩区间的摘要，以及该摘要**覆写区间**的显式表达；未覆盖的裁剪区间必须作为缺口标出。
2. **当前工作状态**：可机器读取的任务事实集合，至少包含目标、最新纠正、已撤回信息、已执行动作、未解决问题、证据时效。
3. **长期记忆条目与变更回执**：条目的作用域、来源、版本与更新关系；写入／修改／删除回执由 `C06` 执行后返回（`K05`）。

**分离要求**：会话摘要与长期记忆条目是两套事实，接口上分开表达、分开读写；摘要不因为「被模型写过」而获得长期记忆身份，长期条目也不因为出现在摘要里而改变来源。

## 状态转换

本合同不引入新的运行时状态机；它固定**覆盖状态**与**条目更新关系**两组表达。

每个被裁剪区间必须落到下列之一：

| 取值      | 含义               | 约束                                                                       |
| --------- | ------------------ | -------------------------------------------------------------------------- |
| `covered` | 该区间已被摘要覆盖 | 摘要必须保留该区间内的最新纠正、重要约束与任务进展；失败区间不得被压成成功 |
| `gap`     | 该区间未被覆盖     | 必须可解释（说明为何未覆盖、影响什么），并作为缺口关联 `C26`／`C27`        |

合法转换：区间从「未处理」进入 `covered` 或 `gap`；摘要重算后，`covered` 区间可以被新的 `covered` 替换，但替换必须提升或保持覆盖范围，且**旧纠正不得覆盖新纠正**——较新的用户纠正始终优先于摘要中较旧的表述。不允许把 `gap` 静默改写为 `covered`。

长期记忆条目的同作用域更新关系只有：

| 关系        | 含义                                                                           |
| ----------- | ------------------------------------------------------------------------------ |
| `replaced`  | 新条目在**同一作用域**内取代旧条目；旧条目保留身份与历史，不再作为当前事实读取 |
| `retracted` | 条目被用户撤回；保留身份，明确不再作为事实使用                                 |
| `active`    | 当前有效条目                                                                   |

这三者是条目自身的表达，**不是**登记表的 `supersedes` 边（关系模型见 [governance.md](../rules/governance.md) §3.1）。

跨会话的持久修改（新增、修改、删除长期条目）**沿用户确认合同**（`K05`）执行，由 `C06` 提交副作用；默认不把任意聊天内容自动写成长期事实。自动取用仅限已获准作用域内的已保存偏好。

**已确定（`Q15`，2026-09-19）**：写入时机＝仅由 `memory_write` 显式发起（`requires_confirmation = true`、`default_enabled_without_skill = false`，因此默认不把任意聊天内容自动写成长期事实；`ai_memories` 全仓只有这一条写入路径）；作用域＝入参 `scope` 的 `global`／`vault`，`vault` 需有活动 Vault，否则按 `memory_vault_scope_unavailable` 拒绝，未知作用域按 `memory_scope_invalid` 拒绝，**不静默回退到 global**；更新关系与来源失效表达见上表。

**明确不做（关闭 `Q15` 不等于实现它们）**：条目**有效期**与**冲突呈现**。表结构没有过期列，也没有面向用户的冲突裁决界面；把它们写成已实现是错的。这两项需要单独的功能决定与工作包。

## 不变量

1. **被裁剪区间有可解释的覆盖或缺口**：不存在既不在上下文中、也没有 `covered`／`gap` 表达的区间。
2. **失败不能压成成功**：摘要中的执行结果必须与真实观察一致；被拒绝、部分成功或结果未知的动作不得表述为已完成。
3. **旧纠正不能覆盖新纠正**：任何摘要或状态表达都不得让较早的纠正压过较新的修订。
4. **压缩范围、来源归属与任务恢复一致**：摘要不把旧线索变成新证据；需要时按来源身份重新加载获准内容并检查时效。
5. **会话摘要不复制完整网页证据**：摘要保留来源身份与时效即可，正文按需重新加载。
6. **长期记忆与聊天摘要分离**：两套事实不互相改写，也不互相提升身份。
7. **同作用域保留更新关系**：同一作用域内不并存两个互不相关的当前版本；更新与撤回必须显式表达。
8. **长期事实不自动当作当前网页证据**：长期条目是记忆事实，不构成「网页已核实」的证据。
9. **长期条目的持久修改沿用户确认合同**：未获确认的写入不执行；已保存偏好可在获准作用域内自动取用。

## 异常处理

| 失败分类                           | 反馈对象与可恢复性                                                       | 不得继续的情形                                             |
| ---------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 摘要覆盖边界与实际裁剪边界不一致   | 记录缺口并反馈 `C07`／`C26`；在预算允许时重算覆盖                        | 把未覆盖区间当作已覆盖，使用缺失上下文继续交付             |
| 摘要模型暂不可用或返回空结果       | 保留原始区间为 `gap`，按预算与取消信号有依据地恢复                       | 用空摘要覆盖原有区间；把压缩失败当作任务失败或模型能力降级 |
| 摘要内容与真实动作结果冲突         | 以真实观察与回执为准，修正摘要并记录差异                                 | 以摘要代替 `C06`／`C17` 的事实                             |
| 同作用域条目冲突                   | 由 `C09` 与用户确认解决；冲突未解决时不得静默选取一条作为当前事实        | 自动删除或覆盖既有条目                                     |
| 条目来源失效或作用域授权被撤回     | 保留条目标识与回执，明确不再取用；依 `C09`／`C22` 的来源边界说明不可核验 | 继续把失效条目作为当前事实注入上下文                       |
| 记忆写入回执未知                   | 先核实回执，不重复执行非幂等写入                                         | 因重试造成重复变更                                         |
| 确认在写入前失效（目标或内容变化） | 使旧确认失效并要求重新确认（`K05`）                                      | 沿用作废确认执行写入                                       |

## 消费方

| 消费方 | 消费的字段                                                                                | 用途                                                                 |
| ------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `C08`  | 历史区间、实际裁剪边界、当前任务事实；输出摘要覆盖与工作状态                              | 责任组件：使用实际裁剪边界压缩，保持目标、最新纠正、执行回执与未决项 |
| `C09`  | 条目的作用域、来源、更新关系（`replaced`／`retracted`／`active`）与变更回执；确认合同约束 | 长期条目的读取、写入、更新与失效表达；同作用域保留更新关系           |

`C09` 的读写工具（`T13` `memory_read`、`T14` `memory_write`）与长期条目字段的对应关系属于工具卡内容，见 [tools/](../tools/README.md)，本文件不复制工具自身合同。

## 验证

本合同需要以下类别证据，判据定义在各 `V*` 对象中，本文件不新增判据：

- `V03`：覆盖状态取值合法、`covered`／`gap` 与真实裁剪区间一致、更新关系（`replaced`／`retracted`）表达的确定性检查；摘要在失败与部分成功情形下不得压成成功。
- `V04`：跨组件交接——长对话中压缩覆盖与 `C07` 裁剪边界的一致性（`Q08`／`G05`），以及长期记忆读写在确认合同下的生产入口路径。
- `V06`：长对话追问承接、最新纠正保留与任务进展表达的语义质量。
- `V08`：记录绑定与当前适用性。

长期记忆**有效期与冲突呈现**没有验收判据，因为已明确不实现它们：在作出功能决定前**不写判据**，也不得由工作包按已完成设计实现。写入与作用域的机械判据已在位（`memory_scope_precedence_is_vault_then_global`、`confirmed_memory_clear_is_scope_local`、`vault_scope_without_an_active_vault_is_refused_by_name`）。`V03`–`V07` 当前状态一律为「未运行」或「待执行」（见 [evidence.md](../testing/evidence.md)）。
