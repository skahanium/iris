# K16 验证报告与可恢复错误反馈

<!-- iris:object K16 kind=rules file=true -->

本文件是 `K16` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**任务还缺什么、错误如何变成可执行的反馈、什么情况下继续或停止**：逐项验证报告的取值与分母、机械与语义验证的分工、可恢复错误的默认反馈与纠偏载荷、停止条件与盲目重试的禁入情形。责任组件是 `C23`（任务验证），消费方是 `C23`、`C14`、`C17`、`C24`。

本文件只定义验证报告与错误反馈，不复制相邻对象的正式定义：任务结果与交付表达见 [K15](./K15-delivery-result.md)，来源身份与支持关系见 [K14](./K14-evidence-and-provenance.md)，工具面版本与派发状态见 [K10](./K10-tool-surface.md)，额度与分类计数见 [K06](./K06-budget-ledger.md)，协议终止原因与续轮保真见 [K04](./K04-provider-capability.md)，抓取失败分类与阅读窗口见 [K13](./K13-web-reading-window.md)，事件与诊断见 [K17](./K17-audit-events.md)，授权与确认边界见 [K05](./K05-authorization-and-confirmation.md)。

本文件的编译依据是架构定义的 M5 容错小节、M8 与错误归属一节，以及关于容错纠偏能力的需求条目（`N15`、`N16`、`N17`，见 [requirements.md](../requirements/requirements.md)）。`implementation.state` 只描述源码事实，不代表合同正确或用户任务可用；相邻问题以 `Q*` 引用：`Q04` 的 Chat Completions 流式机械覆盖不替代逐端点 `V05`，`Q03`／`Q01`／`Q12` 的关闭口径见其条目，不在此宣称合同已验收。

## 接口

**输入**（设计层逻辑类型，不是已存在的 Rust 类型或 IPC 字段）：

| 输入               | 含义                                                   | 权威所有者                                     |
| ------------------ | ------------------------------------------------------ | ---------------------------------------------- |
| 原要求             | 用户本轮要求、目标文档与版本、允许变化集合             | `C01`（`K01`）                                 |
| 候选答案或候选修改 | 待验证的正文或编辑候选                                 | `C24`／模型产出；生成不等于写入                |
| 来源与支持关系     | 引用身份、内容范围、支持关系                           | `C22`（`K14`）                                 |
| 执行回执           | 已执行动作的结果、部分失败与不可回滚事实               | `C06`、`C17`                                   |
| 终止原因           | 供应商报告的结束原因（正常结束、长度截断、工具结束等） | `C11`／`C12`（`K04`；见 `Q04`）                |
| 观察与失败分类     | 工具派发结果、抓取与搜索的失败分类                     | `C17`（`K10`）、`C21`（`K13`）、`C20`（`K11`） |
| 预算与尝试计数     | 模型回合、工具执行、纠偏次数与剩余额度                 | `C13`（`K06`）                                 |

**输出**：

1. **逐项报告**：每项要求取 `passed`／`failed`／`unknown`／`not-applicable` 之一，并显示该维度的**实际分母**；适用、未覆盖与通过必须分开表达。
2. **缺口清单**：还缺哪些材料、引用或核实条件，供 `C14` 决定继续或结束。
3. **可恢复错误反馈载荷**：错误分类、具体到字段或页面的问题说明、可用的合法取值或合法工具名、以及承载该反馈的协议消息身份。
4. **机械与语义的分列结论**：机械不变量由程序验证；语义支持可借用模型判断，但必须保留判据、来源与不确定性，不输出未经校准的责任概率。
5. **停止原因**：任务完成、需要澄清、权限受限、服务失败或具体资源耗尽，分别表达。

**边界**：验证**不直接开工具**——它不能自行发起新的检索、抓取或写入；需要的补查由 `C14` 交回行动循环。`C23` 也不发布用户可见结果（`K15`）、不登记来源（`K14`）、不改写执行事实（`C17`）。

## 状态转换

报告项状态集合固定为四项，且只允许下列转换；`unknown` 与 `not-applicable` 必须分开，不得互相替代：

| 报告项状态       | 含义                                         | 允许的去向                                           |
| ---------------- | -------------------------------------------- | ---------------------------------------------------- |
| `not-applicable` | 该维度对本任务没有要求（未覆盖，不进入分母） | 由判据变化或新要求进入 `unknown`／`passed`／`failed` |
| `unknown`        | 有要求但证据不足或不可核验                   | `passed`、`failed`（在补足证据后）                   |
| `failed`         | 证据表明要求未满足                           | 新候选生成后重新评估；旧候选的结论不得沿用           |
| `passed`         | 证据表明要求满足                             | 新候选或要求变化后重新评估                           |

报告不是一次性的：**新候选产生新报告**，旧候选的验证结果不得沿用到新候选。恢复流程的状态转换是：失败观察 → 具体反馈送达 → 模型重新提议或修正参数／语义改查 → 新观察 → 新验证报告。本合同的这一转换是 Run 内的执行事实，Run 生命周期属 `K02`，工具派发状态属 `K10`，本合同不建立第三套状态机。

机械重试、模型重新提议与语义改查**分开计数**，全部纳入同一个顶层预算（`K06`）；未派发的无效提议不消耗「实际工具执行次数」，但它已消耗的模型回合、token、时间与纠偏次数必须照实计入。

## 不变量

1. **逐项报告并显示实际分母**：不得把零分母记为满分或通过（`Q03`；同类不变量已登记在 [evidence.md](../testing/evidence.md)）；要求某维度却没有样本时不得作为质量证据放行。
2. **机械与语义分列**：机械不变量由确定性检查给出；语义支持可借用模型，但必须保留证据与不确定性，机械可证的违规与语义判断分开展示。
3. **验证不开工具**：验证边界内不得自行发起新的检索、抓取、模型调用或写入。
4. **反馈必须可被协议承载**：错误观察必须以当前协议支持的有效工具结果或等价续轮消息反馈给模型，并正确关联原调用身份；不能只写日志而不给模型修正信息。无法安全还原工具调用身份时，由 `C11`／`C14` 按协议错误恢复，不拼造表面有效但关联错误的工具返回。
5. **至少一次带具体反馈的纠偏机会**：在授权仍有效、用户未取消且资源允许时，可恢复错误默认获得至少一次带具体反馈的纠偏机会；不足以满足该合同的配置应明确标为受限配置。
6. **计数分离且同账**：机械重试、模型重新提议与语义改查分开计数，全部纳入同一顶层预算，不形成免费无限循环。
7. **停止有原因**：停止必须能说明任务完成、需要澄清、权限受限、服务失败或具体预算耗尽，不得统一解释为模型能力降级。
8. **结果未知的副作用不重试**：已执行或可能已执行的写入必须先核实回执；不得因重试造成重复变更。
9. **旧候选结论不沿用**：候选变化后必须重新验证；校验失败不得立即改称模型能力降级。
10. **终止原因不被静默改写**：长度截断等异常终止必须保留并可到达验证与恢复判断；不得把截断的工具调用当作完整动作执行（Chat Completions 流式机械覆盖见 `Q04`，关闭仍待 `D02`／`V05`；协议保真归 `K04`）。

## 异常处理

下表固定可恢复错误的默认反馈与纠偏动作，以及同一情形下不得发生的行为：

| 情形                             | 反馈与纠偏动作                                                                                                                         | 不得发生的行为                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 提议不存在的工具                 | 返回 `unknown_tool`、本次未派发、工具面版本及相关合法工具的准确名称与 schema；由模型重新提议；工具面或协议解析错位时先修正对应内部交接 | 一次未知工具即终止 Run；模糊匹配工具名后直接执行；把提议失败记成真实工具执行失败 |
| 工具存在但参数无效               | 返回字段级校验问题、允许类型与必要字段；由模型修正后重提                                                                               | 只返回笼统错误；静默猜测写入目标或补造授权参数                                   |
| 超时、限流等暂时服务故障         | 在取消信号、服务退避提示与预算约束下重试；必要时使用已获准的等价服务路线                                                               | 紧密无限重试；因一个工具服务失败就淘汰整个模型路由                               |
| 搜索无结果、范围偏离或证据不足   | 如实保留结果，向模型反馈缺口，由模型修改关键词、时间或地区约束，或改查来源                                                             | 把空结果当传输故障重复同一请求；由 Host 用关键词规则替模型编造查询语义           |
| 抓取失败、空正文或部分页面不可读 | 保留成功页面；对失败项按原因重试、使用获准提取回退，或由模型改选 URL／阅读窗口（`K13`）                                                | 重新抓取全部成功页面；搜索摘要冒充已读正文；批次中一页失败导致整个任务失败       |
| 一条搜索路线失败                 | 保留另一条真实结果，修复失败路线或按证据充足性继续；同一搜索动作恢复时不重复伪造新的双路成功                                           | 因原生失败丢弃 MCP 结果，或因 MCP 失败丢弃原生结果                               |
| 工具结果或交付候选未通过验证     | 返回具体缺口，由模型补查、修改候选或缩小结论；验证报告随新候选更新                                                                     | 校验失败立即改称模型能力降级；把旧候选的验证结果沿用到新候选                     |

**不进入盲目自动重试的情形**：用户取消、明确权限拒绝、需要新增授权、不可恢复的配置问题，以及结果未知的非幂等副作用。容错不能绕过网络开关、授权范围、费用与时间上限（`K05`、`K06`、`K09`）。

**相同错误反复出现时**：由 `C14` 检查是否已提供有效反馈、工具面是否变化、参数或策略是否发生实质修正；每次重复都按不变量 6 计入预算。具体次数与时限由受控恢复策略配置和评测校准，不得把「一次重复」直接等同于整个任务不可恢复。达到该路径的停滞阈值后停止该路径，并仍检查其他获准行动与已有材料能否完成任务。

## 验证

本合同需要的证据类别定义在各 `V*` 对象中，本文件不新增判据：

| 判据  | 适用于本合同的内容                                                                                                                                                                     |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `V03` | 局部机械不变量：报告项取值合法、实际分母与 `not-applicable` 表达、计数分类分离、零分母不得记为通过                                                                                     |
| `V04` | 跨组件与生产入口：先提议未知工具再按反馈正确调用、参数修正、搜索暂时失败后成功、单页抓取失败而其余页面仍可交付、有界纠偏后停止该路径、取消或拒绝后不继续重试、写入回执未知时不重复执行 |
| `V06` | 语义质量：结论是否受材料支持、改查是否针对真实缺口；判据须在执行前固定并由人工抽检                                                                                                     |
| `V07` | 诊断可定位性：错误分类、恢复与影响、归因状态及「本组件失败」与「受上游影响未执行」的分开展示                                                                                           |
| `V05` | 部分适用：终止原因与错误分类的协议保真需要逐端点证据（`Q04`、`Q17`）；该证据证明字段与事件被保真处理，不证明语义理解                                                                   |
| `V02` | 登记关联：本合同的机械不变量须在 [evidence.md](../testing/evidence.md) 登记合法案例、违例案例、检测位置、恢复行为与对应测试                                                            |

`V03`–`V07` 当前状态一律为「未运行」或「待执行」（见 [acceptance-matrix.md](../testing/acceptance-matrix.md)）；引用它们不表示本合同已通过验收，也不表示容错纠偏能力已经可用。字段级 Host 反馈的机械负例见 `agent_tool_loop_schema_feedback_tests.rs` 与 `malformed_arguments_never_reach_dispatch`；`registry.json.verify` 绑 `C14`／`K16`。本合同 `verification.state` 仍为 none，该覆盖不等于 `D02` 可验收，也不关闭 `G06`。
