# K09 联网授权与查询外发

<!-- iris:object K09 kind=rules file=true -->

本文件是 `K09` 的正式定义位置，也是该合同唯一的正式定义位置。它约束**联网这件事谁说了算、关闭时什么不可达、开启时还剩哪些外发限制**。责任组件是 `C04`（授权与外发策略），主要消费方是 `C04`、`C19`、`C20`、`C21`、`C15`。

本合同只定义授权事实与外发边界，不定义搜索如何执行：双路协调结果见 [K11](./K11-dual-path-search.md)，原生受控子请求见 [K12](./K12-native-search-subrequest.md)，正文读取窗口见 [K13](./K13-web-reading-window.md)，来源身份见 [K14](./K14-evidence-and-provenance.md)，交付限制说明见 [K15](./K15-delivery-result.md)。确认流程、冻结与副作用执行属于 [K05](./K05-authorization-and-confirmation.md)；额度和费用上限属于 [K06](./K06-budget-ledger.md)。本文件不新设数值门槛。

## 接口

**输入**：

| 输入             | 含义                                                                         | 来源                                                             |
| ---------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 用户授权         | 总联网开关状态；严格场景下的额外限制                                         | 用户设置（`web.search` 的唯一授权源）                            |
| 数据域与文件范围 | 允许读取、允许外发的材料范围                                                 | `C01` 的显式引用与 `C04` 的既有授权事实                          |
| 动作             | 本次要做的联网动作：原生搜索、MCP 搜索、网页抓取、其重试、子任务内的同类动作 | `C16`／`C17` 的提议，`C20`／`C21` 的执行意图，`C15` 的子任务请求 |
| 外发去向         | 请求将要到达的服务：模型供应商、原生搜索服务、MCP 搜索或提取服务             | `C10` 路由、`C18` 传输、`C20` 协调                               |
| 外发内容         | 实际要发送的查询、URL 与材料范围                                             | `C20`、`C21`                                                     |

**输出**：

1. **允许／拒绝／需要确认，附原因**：与 `K05` 的状态集合一致；原因必须可读且不含敏感正文。
2. **外发范围**：本次允许外发的最小材料集合与去向；每次外发都是一次独立判定，不因先前「允许联网」而自动成立。
3. **不可达说明**：联网关闭时，哪些能力因此不可达。

**关闭时的不可达清单**（全部来自开关事实，不是执行失败）：原生搜索、MCP 搜索、网页抓取、上述动作的重试、Skills、ChildRun 与提示词都不能增权或另开路径。此清单**不包含**云端模型请求本身——那是另一个边界。

## 状态转换

本合同不引入新的状态集合，沿用 `C04` 的授权决定 `allow`／`deny`／`need-confirmation`（[K05](./K05-authorization-and-confirmation.md)），并固定以下转换约束：

| 事件                             | 合法结果                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------------- |
| 联网开关从开启变为关闭           | 后续新的网页搜索与抓取判定为 `deny`；在途调用的迟到结果保留为旧修订观察，不自动成为新答案 |
| 联网开关从关闭变为开启           | 允许在**既有外发权限内**执行搜索与抓取动作；不等于外发限制全部解除                        |
| 动作进入子任务（`C15`）          | 子任务的授权是父级授权的交集；子任务不能自行增权                                          |
| 动作发生重试                     | 重试沿用原动作的授权判定；授权失效后不得重试                                              |
| 会话历史中出现「允许联网」的文本 | **不构成**授权转换；授权事实只来自用户设置与既有授权                                      |

## 不变量

1. **联网开关是唯一授权源**：`web.search` 与抓取的可达性只由该开关决定；联网关闭时，既有授权、提示词、会话文本、Skills 或模型提议都不能使其可达。
2. **关闭时全路径不可达**：原生搜索、MCP 搜索、抓取、其重试、Skills、ChildRun 与提示词都不能绕过关闭状态。
3. **开启不等于外发限制全部解除**：开启只表示允许使用外部网页信息；材料与数据外发范围仍受既有授权约束。
4. **查询外发受控**：严格场景（禁止笔记内容进入搜索引擎）需要能控制外发查询的路径，或把允许公开的信息单独送入搜索请求；这不能仅靠一句提示词完成。
5. **授权覆盖重试与子任务**：重试和子任务只能继承或收窄授权，不能扩权。
6. **网页开关关闭与完全离线不同**：云端模型请求仍然涉及数据外发；诊断与用户表达不得把两者混为一谈。
7. **数据边界优先于双路要求**：外发资料边界与双路实际执行冲突时，先满足已授权的数据边界；该例外不是普通场景退回单路择优的理由。

## 异常处理

| 失败分类                     | 反馈对象与可恢复性                                                                             | 不得继续的情形                                        |
| ---------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 联网关闭导致动作不可达       | **预期限制与控制结果**，不是程序错误：如实告知用户并让模型在既有材料内继续；不重试、不降级提示 | 以任何替代路径执行搜索或抓取                          |
| 外发范围不足或材料未获准外发 | 反馈给 `C14`／`C20`：改查可公开的信息、缩小查询或改用本地材料                                  | 把未获准材料发往外部服务；用小段提示词代替外发控制    |
| 端点无法在搜索前检查查询     | 记录为严格场景的能力约束：选择能控制外发查询的路径，或限制为允许公开的信息                     | 宣称该端点已满足外发控制（逐端点适配见 `Q17`／`G03`） |
| 模型切换                     | 只影响路由，不改变授权事实；把「换了模型」当作可行路径是错误归因                               | 以更换模型绕过 `deny`                                 |
| 授权在运行中被撤回           | 停止新的外发动作，保留已取得的真实观察，按 `K05` 处理进行中的确认                              | 继续已撤回授权的在途动作重试                          |
| 在途调用被取消，迟到结果返回 | 保留为旧修订观察（`C03`），说明其修订身份                                                      | 把迟到结果当作最新请求的答案或新证据                  |

## 消费方

| 消费方 | 消费的字段                       | 用途                                                                 |
| ------ | -------------------------------- | -------------------------------------------------------------------- |
| `C04`  | 全部输入与输出字段               | 责任组件：控制读取、向模型发送、网页查询外发和写入；维护唯一授权事实 |
| `C19`  | 范围与授权判定                   | 本地检索保持在获准范围内，不因联网状态变化扩大范围                   |
| `C20`  | 允许／拒绝判定、外发范围、去向   | 冻结路线前的门禁；决定本次搜索与重试能否启动                         |
| `C21`  | 抓取授权与外发范围、URL 校验结果 | 决定哪些 URL 可读、哪些必须拒绝并说明                                |
| `C15`  | 授权交集与子任务请求的判定       | 子任务继承或收窄父级授权；子任务不能自行增权                         |

`C16`／`C17` 在派发前调用本合同的判定，但派发状态集合属于 [K10](./K10-tool-surface.md)，本文件不重复。

## 验证

本合同需要以下类别证据，判据定义在各 `V*` 对象中，本文件不新增判据：

- `V03`：`allow`／`deny`／`need-confirmation` 与开关状态、外发范围的一致性；关闭状态下各入口不可达的确定性检查。
- `V04`：跨组件交接与**最终执行边界**——生产入口的「运行中关闭联网」「子任务继承授权」「重试沿用授权」，以及设置往返一致。
- `V05`：端点级的外发控制能力（能否在搜索前检查查询），逐端点记录，不凭厂商名或 `OpenAI-compatible` 标签判定。
- `V07`：联网关闭与授权拒绝在诊断中作为「预期限制」呈现，不被误报为 bug，也不被合并成「模型能力降级」。

`V03`–`V07` 当前状态一律为「未运行」或「待执行」（见 [evidence.md](../testing/evidence.md)）；引用它们不表示本合同已通过验收。
