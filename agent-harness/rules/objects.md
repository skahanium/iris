# 对象、标记与引用规则

<!-- iris:object P02 kind=rules file=true -->

本文件固定 Agent Harness 文档体系的**身份、标记、指纹与引用**规则。它是 `scripts/agent-harness-check.mjs`（`X01`）的实现依据：检查器只能执行本文件写明的规则，不能自行发明语义判断。

规则变更属于治理变更（见 [governance.md](./governance.md)），须按架构变更复核。

## 一、对象身份

### 1.1 ID 是身份，不是位置

- ID 一旦分配给某个对象，**永不复用**。删除的对象保留 ID 墓碑，不得把该 ID 让给新对象。
- 移动同一对象（改文件名、跨目录迁移）不改变 ID，但必须更新登记位置并进入影响检查。
- 重命名身份、拆分或合并对象，须创建新 ID，并在登记表里用 `supersedes` 登记替代关系；旧 ID 与其修订保留。
- 检查器不推断「这大概是同一个对象」。ID 不同就是不同对象。

## 二、正式定义标记

### 2.1 标记语法

对象正文使用成对标记包裹：

```markdown
<!-- iris:object K06 kind=contract owner=C13 -->

正式定义正文。

<!-- iris:end K06 -->
```

字段固定如下，不得新增未列出的字段：

| 字段                  | 必填                           | 取值                                                                                                                               |
| --------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `iris:object` 后的 ID | 是                             | 符合 §1.2 前缀表的 ID                                                                                                              |
| `kind`                | 是                             | `requirement`、`module`、`component`、`eval`、`tool`、`contract`、`flow`、`evidence`、`work`、`decision`、`rules`、`issue`、`test` |
| `owner`               | 工作包（`work`）是，其余否     | 责任对象 ID（模块或组件），不是人名或 AI 名字                                                                                      |
| `file`                | 文件级对象必填                 | 值为 `true`，表示承接所在文件的公共说明与外围正文                                                                                  |
| `name`                | 工具、合同、链路、决定推荐填写 | 稳定英文标识（工具名、合同短名），用于交叉核对                                                                                     |
| `scope`               | 工作包必填                     | 该工作包引用的需求与对象 ID 列表                                                                                                   |
| `title`               | 否                             | 中文标题，用于交叉核对                                                                                                             |

### 2.2 硬性规则

1. 标记必须**独占一行**，前后不得有其他字符（缩进也不允许）。
2. 开始与结束标记必须**成对匹配**：出现第二个开始标记时若上一个尚未结束，按第 3 条判定。
3. **文件级容器允许跨越同级的子对象块**（容器 = 外围正文 + 子对象的有序占位）；其他形式的嵌套（对象块内再开对象块）仍然失败。
4. 同一 ID 在同一文件内出现两个**定义块**，或跨文件重复，均为失败。容器与定义块同 ID 是允许的：单对象文件与多对象文件都用对象 ID 作为容器 ID（权威登记写 `<ID>#file`）。
5. `iris:end` 的 ID 必须与对应 `iris:object` 一致。
6. 未登记 ID、未知前缀、字段缺失、字段值非法，均为失败。
7. 围栏代码块（` ``` ` 或 `~~~`）内的文本不参与标记解析；示例写法不算标记。

### 2.3 文件级对象

每份托管文件必须有且只有一个文件级对象，用来承接**所有子对象块之外**的内容（前言、公共表格、维护说明）。文件级对象带 `file=true`，`kind` 取该文件主题对应的种类或 `rules`。

容器 ID 的取值规则：

- **单对象文件**（绝大多数文件）：容器 ID 与该对象的 ID 相同；
- **多对象文件**（`modules/eval-system.md`、`decisions/README.md`、`implementation/README.md`）：使用登记表 `fileContainers` 中显式指定的容器 ID。

文件级对象的存在保证两条约束：没有正文处于“无人负责”的状态；外围正文变化可以被单独识别。

### 2.4 子对象对文件级公共说明的隐式依赖

子对象隐含依赖所在文件的公共说明（文件级对象正文、标题层级约定、术语表）。因此文件级指纹变化时，该文件内**全部子对象**进入复核，而不是只影响文件级对象本身。

## 三、指纹

### 3.1 对象指纹

对象指纹覆盖：标记行的 ID 与 `kind`、以及范围内全部正文。计算方式：

```text
fingerprint = sha256("iris-object-v1\n" + id + "\n" + kind + "\n" + body).slice(0, 32)
```

`body` 的唯一归一化是**换行编码统一为 LF**，并去除结尾多余空行。空白、标点、全角半角、可能的语义差异一律保留——检查器不猜测哪些空白“不重要”。

### 3.2 文件级指纹

文件级对象的指纹**不包含子对象正文**，只包含外围正文，并按出现顺序插入子对象的占位标识：

```text
fingerprint = sha256("iris-file-v1\n" + path + "\n" + outerWithPlaceholders).slice(0, 32)
```

其中 `outerWithPlaceholders` 是把每个子对象块整体替换为 `[[child:<id>]]` 后的正文（含容器自身的标记行）。由此可以分别识别三件事：

| 事件               | 对象指纹           | 文件级指纹                         |
| ------------------ | ------------------ | ---------------------------------- |
| 前言/公共说明变化  | 该文件全部对象进入复核 | 变化                               |
| 对象内容变化       | 仅该对象变化       | 不变（占位数量与顺序不变）         |
| 对象增删或顺序变化 | 不受影响的对象不变 | 变化                               |

### 3.3 来源对象指纹

尚未采用分块标记的上位材料（讨论纪要、架构定义、仓库既有实现文档）以**文件级来源对象**绑定版本：

- 指纹覆盖整个文件正文（同一归一化规则）；
- 登记在 `registry.json` 的 `sources` 段，键是来源 ID（如 `SRC-DISC-2026-09-14`）；
- 来源指纹变化时，所有通过 `refs` 关联到该来源的对象进入复核；初始接受较保守的影响范围，不悄悄漏检。

### 3.4 指纹不匹配的处理

指纹与登记不符，说明内容在登记之外发生了变化。检查器**只报告**，不静默修改历史：

- 报出对象 ID、旧指纹、新指纹与位置；
- 在解决之前，该对象不能声明 `defined` 以上的有效状态：引用它的对象按“上游内容已变化、复核未完成”处理；
- 接受变化需要一次显式动作（见 `rules/governance.md` §4、§5），并留下 `changes` 记录。

## 四、引用与关系

### 4.1 正文引用

正文用相对路径 Markdown 链接与反引号 ID 引用其他对象：

- 需要落到具体段落时用相对路径链接，如 `[K06](../contracts/K06-budget-ledger.md)`；
- 只表达身份时用反引号，如 `K06`、`C14`、`T21`；
- **禁止**在正文里复制另一对象的正式定义。链路文档只说明交接顺序并引用合同。

### 4.2 登记表关系

关系登记在 `registry.json` 的对象条目内，方向固定（见 `rules/governance.md` §3）。检查器校验：每条边的两端存在；`depends_on` 与 `supersedes` 无环；`blocks` 给出 `at: start|acceptance`；工作包 `scope` 至少引用一条需求；正文声称的正式定义位置必须真的存在该标记。

## 五、登记完整性

以下情况一律阻断检查，不得降级为警告：

1. 托管文件清单（`registry.json.files`）与磁盘不一致；
2. 托管文件里存在未登记对象标记；
3. 同一 ID 跨文件重复，或同一文件内出现两个定义块；
4. 标记损坏、未闭合、嵌套（容器跨越同级子对象除外）；
5. 存在无法归属的正文（文件缺文件级对象）；
6. 登记声明某对象有正式定义，但对应标记不存在或 `kind` 不符。

另有一条方向性规则：**“已登记”不等于“已有正式定义”**。登记条目允许 `definition: null`，此时它是有效登记、是待补齐关系的目标；但任何工作包不得依赖一个只有登记、尚无定义的必要对象（见 `rules/governance.md` §2.5）。

反之，**声明存在正式定义却找不到文件或对象范围是错误**：不能退回“仅登记”绕过检查。

### P02 正式定义

## 规则范围

本对象固定 Agent Harness 文档体系的**身份、标记、指纹与引用**规则，并作为 `X01` 的实现依据：检查器只能执行这里写明的规则，不能自行发明语义判断。

## 身份与标记

- ID 是身份不是位置：永不复用；移动不改 ID；重命名身份须创建新 ID 并登记 `supersedes`。
- 前缀表（`N`／`M`／`C`／`E`／`T`／`K`／`L`／`V`／`D`／`R`／`P`／`X`／`Q`／`G`）是封闭清单。
- 标记独占一行、成对匹配；文件级容器允许跨越同级子对象，其他嵌套禁止；围栏代码块内的写法只是示例。
- 单对象文件与多对象文件都用对象 ID 作为容器 ID（权威登记写 `<ID>#file`），多对象文件由 `fileContainers` 显式指定。
- 每份托管文件必须有且只有一个文件级对象。

## 指纹

- 对象指纹 = `sha256("iris-object-v1"+id+kind+body)` 取前 32 位，唯一归一化是换行编码。
- 文件级指纹 = `sha256("iris-file-v1"+path+outer)`，子对象块整体替换为 `[[child:<id>]]`。
- 文件级指纹变化时，该文件内全部子对象进入复核。
- 来源对象按整文件指纹绑定版本，用 `refs` 声明受影响对象。

## 异常处理

标记损坏、同一文件出现两个定义块、ID 跨文件重复、未登记对象、无法归属的正文、声明定义却找不到对象块，全部阻断，不降级为警告。

## 消费方

`X01` 逐条实现本规则；`X02` 用负例验证每条规则都能被检出；`P03` 引用本文件而不重述规则；`X03` 保存对象指纹与修订。

## 验证

规则自身变更属于治理变更（见 `P03` §4.1），需要独立复核；规则与检查器的一致性由 `X02` 覆盖。
