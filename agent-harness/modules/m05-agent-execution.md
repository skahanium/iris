# M5 Agent 执行控制

<!-- iris:object M05 kind=rules file=true -->

**唯一主要责任**：拥有循环过程和统一预算账本。模型负责语义计划、修正建议，以及观察之后的下一步提议。控制器执行信封（授权、预算、取消）与不变量；不得靠配方启发式当第二规划器（`R11`）。本模块承担架构 §3 M5 的「用户补充要求（2026-09-15）」容错纠偏合同。

**状态权威与禁止行为**：本模块拥有「额度配置、预留与累计」逻辑对象。主要读取者是 `M04`、`M06`、`M07`。禁止行为：每层另算总账、重复扣费或漏记。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表第六行。

本模块由 `C13` 循环状态与预算、`C14` 行动与恢复协调、`C15` 子任务协调三个组件组成。子 agent 是 `C15` 管理的子执行，**复用同样的模块与合同，不复制一套内核**（§1）。

## 输入与输出

**输入**：

- Run 合同、动作申请、用量（`C13`）。
- 模型提议、观察、验证缺口（`C14`）。
- 独立任务、上下文引用、父级授权与额度（`C15`）。
- 来自 `M02` 的授权判定、来自 `M06` 的派发状态与观察、来自 `M08` 的验证报告。

**输出**：

- 执行阶段、额度租约、剩余资源（`C13`）。
- 修复反馈、信封内停止理由，或把模型的下一步提议交给派发（`C14`）。
- 子运行及带来源的报告（`C15`）。

## 决定权

- 控制器执行信封与不变量；观察之后下一步由模型提议（`R11`、`R12`、§3 M5）。Host 不得靠配方启发式强制综合；完成额度预留触达后不注入关面指令。
- 额度只有一个权威账本；派发、内部请求、token、时间和子任务分维度记录；**类别耗尽不封死无关能力**（§3 `C13`）。
- 决定可恢复错误的反馈与纠偏动作；机械重试、模型重新提议和语义改查分开计数（§3 M5）。
- 结束必须对应真实原因（§3 `C14`）。
- 不决定授权范围（`M02`），不决定工具面内容（`M06`），不决定证据身份（`M07`），不决定用户可见表达（`M08`）。
- 命令报错、关键词匹配等由 Host 替模型决定查询语义是不允许的；搜索无结果时反馈缺口由模型修改约束（§3 M5）。

## 状态

| 状态项         | 内容                                               | 边界                                               |
| -------------- | -------------------------------------------------- | -------------------------------------------------- |
| 执行阶段       | 当前循环阶段与结束原因                             | 只由 `C13`／`C14` 维护                             |
| 额度租约与累计 | 派发、内部请求、token、时间、子任务分维度计数      | 只由 `C13`，是全系统唯一预算账本                   |
| 内部执行轨迹   | 失败 → 具体反馈 → 修正提议／重试 → 恢复结果 的关联 | 只由 `C14` 与 `C26` 记录，首个失败不被后续成功覆盖 |
| 子运行         | 子任务上下文、工具面、额度与报告                   | 只由 `C15`                                         |

目标预算口径与当前父、子循环各自限额的做法**不同**：`C13` 保留父子层级明细，同时控制顶层总消耗，原生搜索辅助模型请求也纳入（§3 M5）。数值先沿受控配置，属于信封而非架构真理；调整时必须兼容旧 Run 存档，旧确认不扩权。

## 不变量

1. 额度只有一个权威账本；不得每层另算总账、重复扣费或漏记（§4）。
2. 类别耗尽不封死无关能力（§3 `C13`）。
3. 无效提议不当作执行；不给无信息增益的相同错误无限重试（§3 `C14`）。
4. 未派发的无效提议**不消耗**「实际工具执行次数」，但它已经消耗的模型回合、token、时间及纠偏次数必须照实计入，不能形成免费无限循环（§3 M5）。
5. 容错不能绕过网络开关、授权范围、费用和时间上限（§3 M5）。
6. 用户取消、明确权限拒绝、需要新增授权、不可恢复的配置问题，以及结果未知的非幂等副作用，**不进入盲目自动重试**（§3 M5）。
7. 已执行或可能已执行的写入必须先核实回执，不能因重试造成重复变更。
8. 一层委派、只读、授权交集；预算从父级总资源中显式分配；子报告不是未经验证的最终事实（§3 `C15`）。
9. 容错纠偏由 `C14` 协调、`C13` 管预算、`C17` 交付错误观察、`C26`／`C27` 记录和解释，`C25` 依据恢复后的任务结果发布（§3 M5）。
10. 不依赖读取或保存模型私有思维链；无推理内容返回的模型也必须具备同样的恢复能力（§3 M5）。

## 异常与恢复

### 可恢复错误的默认处理（架构 §3 M5 表）

| 情形                             | 反馈与纠偏动作                                                                               | 不得发生的行为                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 提议不存在的工具                 | 返回 `unknown_tool`、本次未派发、工具面版本及相关合法工具的准确名称与 schema；让模型重新提议 | 一次未知工具即终止 Run；模糊匹配工具名后直接执行；把提议失败记成真实工具执行失败 |
| 工具存在但参数无效               | 返回字段级校验问题、允许类型及必要字段；让模型修正后重提                                     | 只返回笼统 error；静默猜测写入目标或补造授权参数                                 |
| 超时、限流等暂时服务故障         | 在取消信号、服务退避提示与预算约束下重试；必要时使用已获准的等价服务路线                     | 紧密无限重试；因一个工具服务失败就淘汰整个模型路由                               |
| 搜索无结果、范围偏离或证据不足   | 如实保留结果，向模型反馈缺口，由模型修改关键词、时间或地区约束，或改查来源                   | 把空结果当传输故障重复同一请求；让 Host 用关键词规则替模型编造查询语义           |
| 抓取失败、空正文或部分页面不可读 | 保留成功页面；对失败项按原因重试、使用获准提取回退，或让模型选择其他 URL／阅读窗口           | 重新抓取全部成功页面；搜索摘要冒充已读正文；批次中一页失败导致整个任务失败       |
| 一条搜索路线失败                 | 保留另一条真实结果，修复失败路线或按证据充足性继续                                           | 因原生失败丢弃 MCP 结果，或因 MCP 失败丢弃原生结果                               |
| 工具结果或交付候选未通过验证     | 返回具体缺口，让模型补查、修改候选或缩小结论；验证报告随新候选更新                           | 校验失败立即改称模型能力降级；把旧候选的验证结果沿用到新候选                     |

错误观察必须以当前协议支持的有效工具结果或等价续轮消息反馈给模型，并正确关联原调用身份；**不能只写日志而不给模型修正信息**（§3 M5）。

### 容错预算与停止条件

- 对可恢复的提议或调用错误，在授权仍有效、用户未取消且资源允许时，默认**至少提供一次带具体反馈的纠偏机会**（§3 M5）。
- `C13` 在可调用工具的 Run 中为纠偏和最终表达预留资源，不能正常行动耗尽全部模型回合后才发现无法纠正；不足以满足该合同的配置应明确标为**受限配置**（§3 M5）。完成额度预留触达后可不提供业务工具并把 remaining 留给表达（`R12`）；不得与无进展计数共用关面指令。循环已按信封收窄工具面、预留轮不写关面指令；`G06` 仍开，因为 `D02` 验收证据包未齐。
- 相同错误反复出现时，`C14` 检查是否已提供有效反馈、工具面是否变化、参数或策略是否发生实质修正；具体次数与时限由受控恢复策略配置和评测校准，**不能把「一次重复」直接等同于整个任务不可恢复**（§3 M5）。
- 达到该路径的停滞阈值后停止该路径，仍检查其他获准行动与已有材料能否完成任务。
- 当前源码基线中 `rejected_rounds`／`no_progress_rounds`／`failed_service_rounds` 仍是诊断字段，**不再**关面、注入关面指令，或仅因 `rejected_rounds >= 2` 把退出标成 `recovery_exhausted`。两轮未知工具后若模型自己给出答案，退出是正常完成。诊断查询测的是注入的事件 JSON，不依赖循环再产出该 reason。过早收束的可判定关闭仍由 `D02` 承接（`G06`）。

## 审计

- 内部保留「失败 → 具体反馈 → 修正提议／重试 → 恢复结果」的关联轨迹；**首个失败不被后续成功覆盖**（§3 M5）。
- 成功恢复并满足任务要求时正常交付结果，不弹出模型降级提示；用户可在诊断详情查看恢复过程。恢复较久时可显示简短进度，但不将技术错误堆进正文（§3 M5）。
- 循环诊断的界面快照仍是部分计数、首次失败及最近 12 条事件；C26 权威表保留完整循环事件，不再把中间恢复挤掉。查询呈现仍属 `C27`（`Q09`）。
- 诊断按「过早收束」检查 `C17`／`C23` → `C14` → `C13`：被拒绝原因、验证缺口、相同失败是否有新反馈、各类剩余额度（§8.5）。
- 恢复能力需要独立的验收案例，并检查实际资源计数（§8.6）。

§8.6 要求的恢复验收案例包括：先提议未知工具，再根据反馈正确调用并完成；参数错误后修正；搜索暂时失败后成功；单页抓取失败而其余页面仍可交付；重复无效提议在有界纠偏后停止该路径；取消／拒绝后不继续重试；写入回执未知时不重复执行。**每例同时检查内部错误与恢复关联、实际资源计数，以及用户侧是否出现不应有的降级提示。**

评测分别报告首试成功率、可恢复案例的最终完成率、额外耗时与调用成本、错误提示误报，以及越权或重复副作用；**本次不凭空设统一容错百分比**，恢复策略必须在这些约束下校准（§8.6）。本模块 `M05`、`C13`–`C15` 当前 `implementation.state=partial`，全部 `verification.state=none`。

### M05 正式定义

## 模块级合同要点

- **唯一主要责任**：拥有循环过程与统一预算账本；控制器执行信封与不变量，观察之后下一步由模型提议（`R11`）。
- **状态权威**：额度配置、预留与累计由本模块独占；其他模块只能申领并回报。
- **禁止行为**：每层另算总账、重复扣费或漏记；把无效提议记成真实执行；把收束原因写成模型能力不足。
- **容错纠偏**：可恢复错误必须给出具体反馈并继续尝试；一次工具错误不终止任务（`R08`）。
- **依赖**：工具面版本见 `K10`；验证缺口见 `K16`；预算合同见 `K06`。

## 组件边界

`C13` 维护执行阶段与额度租约；`C14` 执行信封内停止并交付修复反馈，下一步由模型提议；`C15` 管理一层只读委派，其预算从父级总资源显式分配。

### C13 循环状态与预算

## 输入与输出

- **输入**：Run 合同、动作申请、用量。
- **输出**：执行阶段、额度租约、剩余资源。
- **逻辑合同名称**：设计层名称，不是已存在的 Rust 类型或 IPC 字段；所属模块 `M05`。

## 决定权与不变量

- **决定权**：额度只有一个权威账本；派发、内部请求、token、时间和子任务分维度记录；类别耗尽不封死无关能力。探索轮输出帽与预留触达后不提供业务工具是信封（`R12`），不是关面配方。
- **不变量**：未派发的提议不消耗实际工具执行次数，但模型回合／token／时间／纠偏次数照实计入。
- **禁止行为**：越权改写其他模块的权威状态；把提议当作执行；把缺失当作成功。

## 状态

本组件持有的状态与其权威范围见上；持久状态只有 `M05` 的权威所有者可写，其余为进程内观察。

## 异常与恢复

预算不足时如实说明限制，不静默降级为单路或跳过验证。失败分类使用稳定错误码，可恢复的错误按 `K16` 反馈后继续。

## 审计

租约、预留、累计与耗尽原因进入 `C26`。不记录密钥、笔记正文、完整模型请求或私有推理。

## 源码落点

### C14 行动与恢复协调

## 输入与输出

- **输入**：模型提议、观察、验证缺口。
- **输出**：修复反馈、信封内停止理由，或把模型的下一步提议交给派发。
- **逻辑合同名称**：设计层名称，不是已存在的 Rust 类型或 IPC 字段；所属模块 `M05`。

## 决定权与不变量

- **决定权**：无效提议不当作执行；不给无信息增益的相同错误无限重试；结束必须对应真实原因；下一步由模型提议（`R11`）。Host 不得靠配方启发式强制综合；`rejected_rounds`／`no_progress_rounds`／`failed_service_rounds` 不得关面或注入关面指令。完成额度预留触达后可不提供业务工具，必须把 remaining 留给表达轮，不得注入关面指令（`R12`）。

- **禁止行为**：越权改写其他模块的权威状态；把提议当作执行；把缺失当作成功。

## 状态

## 审计

失败、反馈、重试与恢复结果关联到同一调用身份，首个失败不被后续成功覆盖。不记录密钥、笔记正文、完整模型请求或私有推理。
