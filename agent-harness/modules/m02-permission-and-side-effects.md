# M2 权限与受控副作用

<!-- iris:object M02 kind=rules file=true -->

**唯一主要责任**：拥有授权真相。模型提出动作，`M06` 请求执行，`M02` 判定授权并管理必要确认。内容变化不被「允许联网」或「启用工具」隐含授权。

**状态权威与禁止行为**：本模块拥有「授权与冻结确认」逻辑对象。主要读取者是 `M06`、`M07`、`M04`、`M05`。禁止行为：其他模块自行增权。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表第三行。

本模块由 `C04` 授权与外发策略、`C05` 变更冻结与确认、`C06` 确定性副作用执行三个组件组成。职责划分的依据是「权限与实际副作用放在同一模块下，但审批决定和执行回执是不同组件的输出」（§2）。

## 输入与输出

**输入**：

- 用户授权、数据域、文件范围、动作（`C04`）。
- 候选变更、目标版本、已有授权（`C05`）。
- 通过确认与版本复验的操作（`C06`）。
- 来自 `M06`、`M07`、`M04`、`M05` 的执行请求与调用身份。

**输出**：

- allow／deny／need-confirmation 与原因（`C04`）。
- 冻结变更及确认身份（`C05`）。
- 实际执行回执与部分失败（`C06`）。
- 供 `M08` 呈现的写入回执与供 `M09` 关联的安全事件。

## 决定权

- 授权判定与冻结确认的唯一权威。其他模块不得自行增权（§4 禁止行为）。
- 控制读取、向模型发送、网页查询外发和写入；子任务和重试只能继承或收窄（§3 `C04`）。
- 只有 `C06` 这条边界可以提交 Agent 引起的副作用（§3 `C06`）。
- 不决定模型如何理解任务（`M04`／`M05`），不决定工具面暴露哪些名称（`M06`），不决定证据身份（`M07`）。
- 内容变化不被「允许联网」或「启用工具」隐含授权：联网开关是 `web.search` 的唯一授权源，关闭时 Native 与 MCP Web 调度均不可达，freshness、Skills、ChildRun 和提示词均不能增权（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
- 严格的数据外发限制与双路要求冲突时，先满足已授权的数据边界（`N13`、§5）。

## 状态

| 状态项       | 内容                                     | 边界                                 |
| ------------ | ---------------------------------------- | ------------------------------------ |
| 授权事实     | 用户授权、数据域、文件范围、动作范围     | 只由 `C04` 判定                      |
| 冻结确认     | 目标、内容、范围、版本、有效期、确认身份 | 只由 `C05` 冻结                      |
| 执行回执     | 实际执行结果与已执行前缀                 | 只由 `C06` 产生                      |
| 确认失效条件 | 目标或内容在确认前发生变化               | `C05` 判定，事实由 `M01`／`M08` 提供 |

显式授权事实不由模型推断（§3 `C01`）。权限决定必须能被 `M09` 关联到具体请求身份。

## 不变量

1. 其他模块不得自行增权（§4）。
2. 子任务和重试只能继承或收窄授权（§3 `C04`）。
3. 确认绑定目标、内容、范围、版本和有效期（`K05`）；已有有效授权不反复索要。
4. 只有 `C06` 可提交 Agent 引起的副作用，且不由模型声明成功（§3 `C06`）。
5. 保留已执行前缀：部分成功后不因后续失败而抹去已执行事实。
6. 记忆、计划登记和导出也有副作用：`C06` 授权执行，具体存储逻辑仍由对应业务组件完成（§3 M2 说明）。
7. 结果未知的非幂等副作用不进入盲目自动重试；已执行或可能已执行的写入必须先核实回执（§3 M5）。
8. 容错不能绕过网络开关、授权范围、费用和时间上限（§3 M5）。

## 异常与恢复

- 需要新增授权时，转入既有确认流程；不由模型补造授权参数（§3 M5 可恢复错误默认处理）。
- 确认前目标或内容变化：使旧确认失效并要求重新确认（§3 M1 本次选择）。
- 对于不能撤销的已执行动作，只报告事实，不假装回滚（§3 M1）。
- 必要授权或变更回执无法持久化时，**不执行新的持久副作用**；审计失败与任务失败分别表达（§3 M9）。
- 权限拒绝是预期控制结果，不进入盲目自动重试，也不一律算程序错误（§8.2）。
- 只写日志而不给模型修正信息是不允许的；无法安全还原工具调用身份时由 `C11`／`C14` 按协议错误恢复，不能拼造表面有效但关联错误的工具返回（§3 M5）。

## 审计

- 授权决定、确认身份与执行回执分别记录，不能一步混做：工具目录扩展、授权变更和实际工具执行分别记录（§6.5）。
- 按「文件发生意外修改」这一现象直接检查 `C24` → `C05` → `C06`：候选、冻结范围、确认身份、版本与实际写入回执（§8.5）。
- 不记录密钥、笔记正文或私有推理（§3 `C26`、§8.4）。

## 兼容

- 旧确认不扩权：调整预算或策略时必须兼容旧 Run 存档，旧确认不扩权（§3 M5、`Q13`）。
- 切换或回退不能重放未知副作用，不能通过回退重新开放已拒绝的权限（§10.3）。
- 既有信任与快照不能随配置哈希重算自动扩权（§10.2 `F04`、`Q05`）。
- 读边界兼容策略见 [ARCHITECTURE.md](../../ARCHITECTURE.md) Compatibility boundaries。

## 测试

| 需求／判据                                                           | 覆盖方式                                               |
| -------------------------------------------------------------------- | ------------------------------------------------------ |
| 严格场景保留联网限制，授权覆盖原生、MCP、抓取、重试与子任务（`N12`） | 生产入口验证含「运行中关闭联网」（§5.1、`V04`）        |

`V02` 已登记的相关不变量「冻结确认绑定目标与版本」的测试仍标注「待补充（`D05`）」。本模块 `M02`、`C04`–`C06` 当前 `verification.state=none`；`implementation.state=present` 只描述静态源码事实。

## 依赖与缺口

### M02 正式定义

## 模块级合同要点

- **唯一主要责任**：拥有授权真相；模型提出动作，`M06` 请求执行，本模块判定授权并管理必要确认。
- **状态权威**：授权与冻结确认由本模块独占，其他模块不得自行增权。
- **禁止行为**：把「允许联网」或「启用工具」当作内容变更授权；由模型声明写入成功。
- **决定与执行分离**：`C04` 判定、`C05` 冻结、`C06` 执行，回执只由 `C06` 产生。
- **依赖**：请求身份来自 `C01`；副作用范围受 `K05` 约束。

## 组件边界

`C04` 输出 allow／deny／need-confirmation 与原因；`C05` 产出带目标、内容、范围、版本与有效期的冻结确认；`C06` 是唯一可提交 Agent 副作用的边界。

### C04 授权与外发策略

## 输入与输出

- **输入**：用户授权、数据域、文件范围、动作。
- **输出**：allow／deny／need-confirmation 与原因。
- **逻辑合同名称**：设计层名称，不是已存在的 Rust 类型或 IPC 字段；所属模块 `M02`。

## 决定权与不变量

- **决定权**：控制读取、向模型发送、网页查询外发和写入；子任务与重试只能继承或收窄。
- **不变量**：授权事实不由模型推断；联网开关是 `web.search` 的唯一授权源。
- **禁止行为**：越权改写其他模块的权威状态；把提议当作执行；把缺失当作成功。

## 状态

本组件持有的状态与其权威范围见上；持久状态只有 `M02` 的权威所有者可写，其余为进程内观察。

## 异常与恢复

判定失败时默认拒绝并说明所需授权；不得因超时或解析失败放行。失败分类使用稳定错误码，可恢复的错误按 `K16` 反馈后继续。

## 审计

判定结果、原因与范围进入 `C26`；不记录被拒正文。不记录密钥、笔记正文、完整模型请求或私有推理。

## 源码落点

现有基础与处置：permission_decision.rs、policy_decision_engine.rs；复用，统一所有路线入口。authorization-and-egress 的目标合同不要求按组件新建文件；映射到多个责任组件的现有大文件应在迁移时删除被替代的重复判断。

## 兼容

旧授权记录按兼容读取；不因新能力上线自动扩权。读边界单向兼容，不双写、不保留第二套权威状态。

## 测试

关键不变量与所需证据类别见 `V01`–`V07`；本组件当前 `verification.state=none`，没有绑定指纹的证据记录。
