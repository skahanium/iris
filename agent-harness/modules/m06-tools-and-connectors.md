# M6 工具与连接器

<!-- iris:object M06 kind=rules file=true -->

**唯一主要责任**：拥有工具合同和派发入口。工具名称是能力接口，不是权限。`MCP` 是这里的一种连接方式，不成为第二套独立执行系统。

**状态权威与禁止行为**：本模块拥有「工具面与派发观察」逻辑对象。主要读取者是 `M05`、`M03`、`M09`。禁止行为：被拒绝的提议写成已执行。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表第七行。

本模块由 `C16` 工具目录、工具面与技能接入、`C17` 调用派发与观察、`C18` MCP 连接与传输三个组件组成。协议适配归 `M4`，`MCP` 传输归本模块，搜索语义与结果组织归 `M7`（§2）。

## 输入与输出

**输入**：

- 内置／外部 schema、能力状态、授权、上下文（`C16`）。
- 工具提议、`C04` 决策、`C13` 租约（`C17`）。
- 冻结的服务配置、发现或调用请求（`C18`）。
- 来自 `M02` 的授权判定、来自 `M05` 的额度租约、来自 `M07` 的检索契约。

**输出**：

- 版本化工具集合和方法材料引用（`C16`）。
- 每次提议的派发状态及工具观察（`C17`）。
- transport 结果与服务能力（`C18`）。

## 决定权

- 决定工具面的组成与版本：Planned 不暴露；所有暴露参数必须消费或明确拒绝；技能不能增权；同一搜索服务不以原始别名绕开统一路径（§3 `C16`）。
- 决定每次提议的派发状态分类：分开 rejected／deferred／started／partial／failed／succeeded；**分类计数由 `C13` 维护，`C17` 只申领并回报**（§3 `C17`）。
- 决定 MCP 连接与发现事实如何表达：连接健康、工具发现成功和业务结果有效是不同事实（§3 `C18`）。
- 不决定授权（`M02`），不决定预算总额（`M05`），不裁定证据真伪（`M07`），不决定最终表达（`M08`）。
- 工具名称是能力接口，不是权限；授权变更与实际工具执行分别记录，不能一步混做（§6.5）。

## 状态

| 状态项       | 内容                                                                    | 边界                      |
| ------------ | ----------------------------------------------------------------------- | ------------------------- |
| 工具面       | 版本化的模型可见工具集合与方法材料引用                                  | 只由 `C16` 组装并记录版本 |
| 派发观察     | 每次提议的派发状态与工具观察结果                                        | 只由 `C17` 产生           |
| 外部服务能力 | transport 健康、发现结果、服务能力状态                                  | 只由 `C18`                |
| 外部工具信任 | 用户对精确 provider／tool／schema 的显式确认、白名单 binding 与冻结哈希 | 只由 `C18` 与 `M02` 判定  |

工具面可以在同一授权范围内于下一轮更新，并记录新版本；**更新只改变可用描述，不自动扩大权限**（§3 M6）。

## 不变量

1. 被拒绝的提议不能写成已执行（§4 禁止行为）。
2. Planned 项不暴露给模型；不因文档有名字就声明可用（§6.4）。
3. 所有暴露参数必须被消费或明确拒绝——`capabilities_read` 的目标合同 `request_tools` 参数需实现消费（`G01`）。
4. 技能不能增权：Skills 是 prompt-only `SKILL.md`，不能安装外部包或执行代码（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
5. 同一搜索服务不以原始别名绕开统一路径（§3 `C16`）。AnySearch／Tavily 的 search／extract 只作为 `web_search`／`web_fetch` 的后端适配，不在同一次搜索任务中重复作为旁路工具暴露（§6.4）。
6. MCP 不成为第二套独立执行系统；外部工具的注册、验证与授权各自独立，默认不接管受控写入（§6.4）。
7. Iris 拒绝声明或 Schema 暴露写入、发送、删除、日历变更、进程和 secret 的工具；但**无法独立验证**已信任第三方服务端是否忠实实现其声明（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
8. `secret_read_plaintext` 是明确禁止实现与暴露的能力，不是等待开发的计划（§6.4）。
9. 工具真实副作用分类必须与处理器的实际效果一致；`doc_normalize_markdown` 当前目录权限分类与真实效果不符（§6.3、`G01`）。

## 异常与恢复

- 提议不存在的工具：返回 `unknown_tool`、本次未派发、工具面版本及相关合法工具的准确名称与 schema；让模型重新提议。若工具面或协议解析错位，先修正对应内部交接（§3 M5）。
- 工具存在但参数无效：返回字段级校验问题、允许类型及必要字段；不静默猜测写入目标或补造授权参数。
- 超时、限流等暂时服务故障：在取消信号、服务退避提示与预算约束下重试；不因一个工具服务失败淘汰整个模型路由。
- 抓取失败、空正文或部分页面不可读：保留成功页面；不重新抓取全部成功页面，不让批次中一页失败导致整个任务失败（该行为由 `C17` 观察、`C21` 执行）。
- 连接健康、工具发现成功与业务结果有效是不同事实；配置、超时、取消和密钥不绕开公共边界（§3 `C18`）。
- 模型不能直接消费 discovery，也不能自行增权（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。

## 审计

- 每次提议的派发状态、工具面版本与拒绝原因进入事件与审计；事件、审计和 checkpoint **不保存参数或原始输出**（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
- 原始工具名不未经脱敏写日志；诊断映射「未知工具」检查 `C11` → `C16` → `C17`（§8.5）。
- `unknown` 工具记录能指出拒绝位置，却不能解释名称从何处产生；这是 `Q01`／`Q12` 与 `G04` 的范围（讨论十四）。

## 兼容

- **设置写入语义必须统一**（§10.2 `F01`、`Q02`）：`McpProfilesPanel` 保存完整有序候选数组，`useAiSidecarBridge` 的 `setWebSearchProviderId` 写单元素数组；缺陷是两个设置入口的写入语义不一致，会丢失已有备用项。目标：MCP 主服务和备用顺序只有一个编辑语义；完整设置、简略设置、IPC 和持久配置必须往返一致（§5.1）。
- **读取路径不得隐藏写库**（§10.2 `F04`、`Q05`）：`list_web_evidence_providers` 已只读列举，不再在读取路径 UPDATE 映射、哈希与时间（落点见 `Q05`，`058366ea`）。兼容补字段发生在显式 `upsert`／`normalize_provider_input`；调用侧 overlay 不写库。既有信任与快照不能随新哈希自动扩权。`Q05` 仍 open，关闭等 `D04` 验收。
- `resolve_web_search_provider_route` 只返回启用的 MCP 搜索候选，最多 3 个（§5.1）。
- MCP 列表内部的主备转移仍是同一路线的服务选择，不默认向全部 MCP 服务并发请求（§5.1）。
- 读边界兼容策略见 [ARCHITECTURE.md](../../ARCHITECTURE.md) Compatibility boundaries。

### M06 正式定义

## 模块级合同要点

- **唯一主要责任**：拥有工具合同与派发入口；工具名是能力接口，不是权限。
- **状态权威**：工具面与派发观察由本模块独占；被拒绝的提议不得写成已执行。
