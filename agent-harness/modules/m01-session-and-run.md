# M1 会话与 Run 管理

<!-- iris:object M01 kind=rules file=true -->

**唯一主要责任**：决定请求身份及运行生命周期，不按关键词替模型决定电影、法规等领域策略。执行状态与任务结果分开保存。

**状态权威与禁止行为**：本模块拥有「请求身份、指令修订」与「Run 生命周期」两个逻辑对象。主要读取者是全部模块、`M05`、`M08`、`M09`。禁止行为：迟到结果冒充最新请求；用「进程结束」代替任务成功。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表前两行。

本模块由 `C01` 请求与引用绑定、`C02` 会话与运行状态、`C03` 指令修订与取消协调三个组件组成，与 [架构定义](../../docs/agent-architecture.md) §3 的 M1 表逐行对应。模块合同是设计层逻辑合同，不是已经存在的 Rust 类型或 IPC 字段；下列源码落点是**复用落点**，不表示文件内全部行为都已经符合目标。

## 输入与输出

**输入**：

- 用户消息、选区、目标文档与明确操作（`C01`）。
- 接受、执行、暂停、取消、结束事件（`C02`）。
- 后续用户指令、取消与确认反馈（`C03`）。
- 上游授权事实与数据范围判定结果，由 `C04` 提供，不由本模块推断。

**输出**：

- 请求身份与材料引用（`C01`）。
- 持久运行状态与安全恢复视图（`C02`）。
- 带修订号的待处理输入或停止信号（`C03`）。
- 供 `M03`、`M05`、`M08`、`M09` 读取的会话、修订号与 Run 生命周期事实。

## 决定权

- 决定一次请求的身份：绑定会话、Vault、文档版本与选区；显式授权事实不由模型推断；语义意图保持可修订（`K01`）。
- 决定运行生命周期的状态投影与其恢复视图；执行结束不等于用户任务成功（`K02`）。
- 决定输入修订号如何递增、旧修订的迟到结果如何保留为旧观察（`K03`）。
- 不决定用户任务是否成功（`M08`），不决定授权（`M02`），不决定本轮到模型看到什么材料（`M03`）。
- 用户补充要求（2026-09-15）的容错纠偏合同**不由本模块承担**，由 `M05` 承担；本模块只负责让修订在安全点被吸收。

## 状态

| 状态项       | 内容                                                 | 写入边界                                        |
| ------------ | ---------------------------------------------------- | ----------------------------------------------- |
| 请求身份     | 会话、Vault、文档版本、选区、显式操作的绑定结果      | 只由 `C01` 建立                                 |
| Run 生命周期 | accepted／执行中／暂停／取消／结束，以及安全恢复视图 | 只由 `C02` 写入，是全系统唯一持久运行状态写入口 |
| 任务结果     | completed／partial／blocked 等用户可见结果           | 由 `M08` 拥有，本模块只引用                     |
| 输入修订     | 修订号、待处理输入、停止信号                         | 只由 `C03` 协调                                 |

执行状态与任务结果分开保存是本模块的主要责任之一；两者不能被压成同一字段。

## 不变量

1. 迟到结果不能冒充最新请求（§4 禁止行为）。
2. 执行结束不能写成用户任务成功（§4 禁止行为）。
3. 不能重放未知副作用：`C02` 不因状态恢复而重新执行写入。
4. 旧修订产生的未发布答案不能覆盖新要求（§3 M1 本次选择）。
5. 取消后不启动新副作用（§3 M1 本次选择）。
6. 确认前目标或内容发生变化时，使旧确认失效——该判定的执行边界在 `C05`，本模块提供变化事实。
7. 对于不能撤销的已执行动作，只报告事实，不假装回滚。

## 异常与恢复

- 进程中断后，`Direct` 与 `ToolLoop` **不支持进程级续跑**；只有 Durable Run 具有暂停与检查点语义（见 [ARCHITECTURE.md](../../ARCHITECTURE.md) Agent Run 节）。本模块不承诺普通研究 Run 在进程重启后从任意中间点续跑（§7.4）。
- 恢复视图只恢复安全快照与过程展示；`assistant_run_get` 回放不重新执行模型或工具。
- 取消是正常控制结果，不进入盲目自动重试（§3 M5 容错预算与停止条件）。取消后不启动新副作用。
- 输入修订的到达时机可能与模型／工具交接重叠；协调失败时保留旧修订观察并如实报告，不能把旧修订结果当作新要求的结果。
- 当前实现的取消有基础，**运行中指令修订需补齐**（§10.2、`G05`、`Q16`）。

## 审计

- 每个模型请求、工具调用和原生搜索子请求携带 Run ID、输入修订号、父调用 ID、尝试 ID（§4）。
- `M09` 的 `C26` 记录结构见证；原文仍留在受控会话或瞬时上下文中，不进入日志。
- 本模块提供可关联的运行与修订身份，不自行保存第二套审计事实；审计写入失败与任务失败分别表达（§3 M9、§8.4）。

## 兼容

- 契约描述的目标合同与现有实现的关系是「修正接口而非新增概念」，本模块不使用整体替换路线（§10.1、§17）。
- 迁移时必须保留可读取的历史会话与明确的配置版本；不得同时运行两套权威状态或镜像执行真实写入（§10.3）。
- 旧 Run 的预算策略读取存在兼容要求，见 `Q13`；本模块不因状态投影整理而给已有 Run 扩权。
- 结构化的 `AwaitingInput` 与 `submit_input` 只保留旧 Run 读取／恢复兼容，不是新普通对话的路径（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
- 普通 Run 不自动获得进程级续跑；扩大执行恢复能力需单独明确，不能隐藏在「有记忆」这一名称里（§7.4）。

### M01 正式定义

## 模块级合同要点

- **唯一主要责任**：决定请求身份及运行生命周期，不按关键词替模型决定领域策略。
- **状态权威**：请求身份与指令修订、Run 生命周期由本模块独占；其他模块不得自行改写。
- **禁止行为**：用「进程结束」代替任务成功；迟到结果冒充最新请求。
- **执行状态与任务结果分开保存**，二者的组合见 `K02`。
- **依赖**：不自行决定语义意图（`C01` 只绑定、不解释），不绕开 `K05` 授权。

## 组件边界

`C01` 绑定身份与材料引用；`C02` 是唯一持久运行状态写入口；`C03` 协调输入修订与取消。三者共享本文件前言中的会话身份与事件流说明。

### C01 请求与引用绑定

## 输入与输出

- **输入**：用户消息、选区、目标文档、明确操作。
- **输出**：请求身份与材料引用。
- **逻辑合同名称**：设计层名称，不是已存在的 Rust 类型或 IPC 字段；所属模块 `M01`。

## 决定权与不变量

- **决定权**：绑定会话、Vault、文档版本与选区；显式授权事实不由模型推断；语义意图保持可修订。
- **不变量**：请求身份随输入修订号传递；引用携带路径、内容哈希与 UTF-8 范围。
- **禁止行为**：越权改写其他模块的权威状态；把提议当作执行；把缺失当作成功。

## 状态

本组件持有的状态与其权威范围见上；持久状态只有 `M01` 的权威所有者可写，其余为进程内观察。

## 异常与恢复

绑定失败或引用过期时拒绝该引用并要求重新选择，不静默降级为目标文档。失败分类使用稳定错误码，可恢复的错误按 `K16` 反馈后继续。

## 审计

身份分配、修订号与引用绑定结果进入 `C26` 事件；不出站原始正文。不记录密钥、笔记正文、完整模型请求或私有推理。

## 源码落点

现有基础与处置：run_intake.rs、run_contract.rs；复用身份合同，收窄领域预判。request-and-reference-binding 的目标合同不要求按组件新建文件；映射到多个责任组件的现有大文件应在迁移时删除被替代的重复判断。

## 兼容

会话与 Vault 身份变化时不复用旧绑定；`legacy:` 前缀只用于恢复夹具，正常路径不使用。读边界单向兼容，不双写、不保留第二套权威状态。

## 测试

关键不变量与所需证据类别见 `V01`–`V07`；本组件当前 `verification.state=none`，没有绑定指纹的证据记录。
