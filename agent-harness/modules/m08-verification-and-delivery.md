# M8 验证与交付

<!-- iris:object M08 kind=rules file=true -->

**唯一主要责任**：拥有任务验证报告和用户可见结果，不拥有执行历史，也不能把模型的完成声明直接落为文件回执。

**状态权威与禁止行为**：本模块拥有「验证报告与交付结果」逻辑对象。主要读取者是 `M05`、`M01`、UI。禁止行为：有引用就认定结论成立。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表第九行。

本模块由 `C23` 任务验证、`C24` 编辑候选与差异、`C25` 最终发布与 UI 投影三个组件组成。验证与交付独立于循环控制：验证报告说明还缺什么，循环决定继续还是结束，发布依据两者呈现实际结果（§2）。

## 输入与输出

**输入**：

- 原要求、候选答案／修改、来源与回执（`C23`）。
- 原始文本、目标版本、模型生成（`C24`）。
- 验证报告、循环结束原因、执行回执（`C25`）。
- 来自 `M01` 的修订号与生命周期、来自 `M02` 的写入回执、来自 `M05` 的结束原因、来自 `M07` 的来源身份。

**输出**：

- passed／failed／unknown／not-applicable 的逐项报告（`C23`）。
- 候选文本、差异与适用范围（`C24`）。
- 回答、候选、澄清或限制说明（`C25`）。

## 决定权

- 决定验证报告内容：机械不变量程序验证；语义支持可借模型但保留证据与不确定性；**验证不直接开工具**（§3 `C23`）。
- 决定候选与差异的适用范围；生成候选不等于写文件（§3 `C24`）。
- 决定用户可见表达与任务结果：completed／partial／blocked 等任务结果与 Run 生命周期分离；不支持原生搜索不显示降级（§3 `C25`）。
- 不拥有执行历史（由 `M01`／`M09` 承载），不决定授权（`M02`），不决定循环是否继续（`M05`），不裁定来源真伪（`M07`）。
- **不能把模型的完成声明直接落为文件回执**：模型说「已经整理好了」或「没有改变内容」，不能代替实际检查（讨论十三）。

## 状态

| 状态项   | 内容                                                    | 边界            |
| -------- | ------------------------------------------------------- | --------------- |
| 验证报告 | 逐项 passed／failed／unknown／not-applicable 与缺口说明 | 只由 `C23` 产生 |
| 编辑候选 | 候选文本、差异、适用范围与目标版本绑定                  | 只由 `C24` 产生 |
| 交付结果 | 回答、候选、澄清或限制说明，以及任务结果分类            | 只由 `C25` 发布 |

`C23` 的逐项报告随新候选更新；**旧候选的验证结果不能沿用到新候选**（§3 M5）。验证报告不拥有执行历史：执行历史由 `M01` 的生命周期与 `M09` 的关联记录承担。

## 不变量

1. 有引用就认定结论成立属禁止行为（§4）。引用身份与正文支持关系必须分别核对。
2. 生成候选不等于写文件；候选与实际应用分离（§3 `C24`）。
3. 格式整理必须保持正文信息及顺序，**仅允许明确的编号变化**（§3 `C24`）。
4. 无法证明内容保持时提供差异或说明，**不能自动标记「未改内容」**；纯正则空白整理器不等于这个合同已经实现（§3 M8）。
5. 校验失败不立即改称模型能力降级；不把旧候选的验证结果沿用到新候选。
6. 任务结果与 Run 生命周期分离；**不支持原生搜索不显示降级**。
7. 用户取消、明确权限拒绝、能力不支持、额度耗尽属预期限制与控制结果，独立展示，不一律算程序错误（§8.2）。
8. 文本润色与风格满意度**不能由确定性检查保证**；这类质量仍需用户判断（§3 M8）。
9. 恢复较久时可显示简短进度，但不将技术错误堆进正文；成功恢复并满足任务要求时不弹出模型降级提示（§3 M5）。
10. 只有仍影响任务交付、需要用户操作或恢复资源耗尽时，才在用户侧说明具体限制。

## 异常与恢复

- 验证缺口：返回具体缺口，让模型补查、修改候选或缩小结论；验证报告随新候选更新。
- 内容保持无法证明：交付差异与不确定项，不自动写入，也不声称「内容完全未改」（§7.3）。
- 输入修订到来后不发布已失效版本的最终答案（§7.4、`K03`）。
- 发布失败：如实表达限制说明，不用流畅文字代替未满足的要求。
- 已恢复的问题仍可查看，成功答案不因一次已恢复超时而被整体标红（§8.3）。
- 审计写入失败不自动抹掉已经取得的正确答案（§3 M9）。

## 审计

- 诊断视图必须能直接从对应回答或失败提示进入，自动关联本次 Run，无需用户先复制 ID 或检索日志（§8.3）。
- 首屏摘要用一句话指出主要失败点、实际影响和恢复状态，同时显示归因是否确定及诊断是否完整（§8.3）。
- 诊断映射：过早收束检查 `C17`／`C23` → `C14` → `C13`；只剩「能力降级」检查 `C12`／`C18`／`C23` → `C25`（§8.5）。
- 对于「答偏了但调用都成功」的情况，首屏可显示「答案相关性未通过，执行链无已知机械故障；模型行为疑似，语义归因待复核」，**不能仅因为所有请求成功就展示为全绿质量通过**（§8.3）。

## 兼容

- 普通回答自然结束，严格结构化合同按需使用提交入口；`submit_final_answer` 保留 1 个条件式协议入口，普通聊天、`WebRequired` 本身不强制用它（§6.4、§11）。该入口是协议入口，不计业务工具，也不分配工具 ID（[对象与标记规则](../rules/objects.md) §1.3）。
- 普通时效事实取得一份与核心结论相关的当前 Run 网页正文并精确引用即可完成；高风险当前事实、`CitationCheck`、显式交叉核实、`CurrentRunExternal` 以及含非空历史 `FreshFactPolicy` 的兼容 Run 才要求官方来源或两个独立域名（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
- `AnswerReset` 不由新的严格 Run 产生，只保留旧事件回放兼容。
- 旧 v1／v2／v3 live 报告仅供诊断，**不得进入 `product-gate.json`**（[ARCHITECTURE.md](../../ARCHITECTURE.md)、[评测系统](./eval-system.md)）。
- 文本润色、文风满意度的验收判据不由本文件设定；发布判据与数值门槛未确定（[缺口与未决项](../requirements/open-items.md) §三）。

### M08 正式定义

## 模块级合同要点

- **唯一主要责任**：拥有任务验证报告与用户可见结果；不拥有执行历史。
- **状态权威**：验证报告与交付结果由本模块独占；模型的完成声明不能直接落为文件回执。
- **禁止行为**：把校验失败改称模型能力降级；把旧候选的验证结果沿用到新候选；用零分母记为满分。
- **结果与生命周期分离**：completed／partial／blocked 是任务结果，不是 Run 生命周期（`K02`、`K15`）。
- **依赖**：来源支持关系见 `K14`；可恢复错误反馈见 `K16`。

## 组件边界

`C23` 输出逐项验证报告；`C24` 产出编辑候选与差异；`C25` 依据前两者发布结果与限制说明。

### C23 任务验证

## 输入与输出

- **输入**：原要求、候选答案／修改、来源与回执。
- **输出**：passed／failed／unknown／not-applicable 的逐项报告。
- **逻辑合同名称**：设计层名称，不是已存在的 Rust 类型或 IPC 字段；所属模块 `M08`。

## 决定权与不变量

- **决定权**：机械不变量程序验证；语义支持可借模型但保留证据与不确定性；验证不直接开工具。
- **不变量**：显示实际分母，零分母维度标为「未覆盖」而不是通过（`Q03`）；格式整理必须核对正文信息与顺序。
- **禁止行为**：越权改写其他模块的权威状态；把提议当作执行；把缺失当作成功。

## 状态

本组件持有的状态与其权威范围见上；持久状态只有 `M08` 的权威所有者可写，其余为进程内观察。

## 异常与恢复

无法证明保持时交付差异与不确定项，不自动标记「未改内容」。失败分类使用稳定错误码，可恢复的错误按 `K16` 反馈后继续。

## 审计

验证项、分母、判据版本与不确定项进入 `C26` 与证据记录。不记录密钥、笔记正文、完整模型请求或私有推理。

## 源码落点

现有基础与处置：final_answer_integrity.rs、final_answer_submission.rs、provenance 与变更校验；整合已有并补内容保持验证。task-verification 的目标合同不要求按组件新建文件；映射到多个责任组件的现有大文件应在迁移时删除被替代的重复判断。

## 兼容

旧候选的验证结果不沿用到新候选；判据变更保留原基线。读边界单向兼容，不双写、不保留第二套权威状态。

## 测试

关键不变量与所需证据类别见 `V01`–`V07`；本组件当前 `verification.state=none`，没有绑定指纹的证据记录。
