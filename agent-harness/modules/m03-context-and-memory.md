# M3 上下文与记忆

<!-- iris:object M03 kind=rules file=true -->

**唯一主要责任**：拥有上下文的内容选择和覆盖说明，不改写真实工具状态或代替权限决策。任务状态是结构化的工作信息，不等同于模型私有推理。

**状态权威与禁止行为**：本模块拥有「上下文与摘要覆盖」逻辑对象。主要读取者是 `M04`、`M05`、`M09`。禁止行为：摘要修改真实动作结果。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表第四行。

本模块由 `C07` 当前上下文装配、`C08` 会话压缩与工作状态、`C09` 长期记忆三个组件组成。将记忆纳入上下文模块，是为了使裁剪、摘要覆盖与长期条目的使用有共同交接边界（§2）。

## 输入与输出

**输入**：

- 当前指令、授权材料、观察、技能方法（`C07`）。
- 历史区间、实际裁剪边界、当前任务事实（`C08`）。
- 授权读写、作用域与版本（`C09`）。
- 来自 `M01` 的请求身份与修订号，来自 `M07` 的观察与来源身份，来自 `M06` 的方法材料引用。

**输出**：

- 本轮上下文及覆盖清单（`C07`）。
- 摘要覆盖与待办／撤回／已完成状态（`C08`）。
- 偏好／事实条目及变更回执（`C09`）。

## 决定权

- 决定哪些内容被采用、裁剪、过期；为稳定指令和最新纠正保留空间（§3 `C07`）。
- 决定压缩覆盖范围与任务状态的表达（§3 `C08`）。
- 决定长期条目的读写与失效表达（§3 `C09`）。
- 不决定授权（`M02`），不决定动作能否执行（`M05`），不决定工具是否真实执行（`M06`），不决定结论是否成立（`M08`）。
- 外部网页、MCP 返回值及检索到的笔记是资料，不是新的用户指令；`C22` 保留来源边界，`C07` 将其作为资料装配（§3 M7）。

## 状态

| 状态项     | 内容                                   | 边界                                    |
| ---------- | -------------------------------------- | --------------------------------------- |
| 上下文覆盖 | 被采用、被裁剪、已过期的内容清单       | 只由 `C07` 装配                         |
| 摘要覆盖   | 被压缩区间、覆盖终点与缺口标记         | 只由 `C08` 写入                         |
| 任务状态   | 结构化的工作信息：待办、已撤回、已完成 | 只由 `C08` 维护                         |
| 长期条目   | 偏好与事实条目、作用域、版本、来源     | 只由 `C09` 读写，持久修改沿用户确认合同 |

摘要与当前任务状态可由系统维护；跨会话长期记忆的持久修改沿用户确认合同，**默认不把任意聊天内容自动写成长期事实**（§3 M3 本次选择）。任务状态是结构化工作信息，不等同于模型私有推理；本模块不读取或保存模型私有思维链。

## 不变量

1. 摘要不能修改真实动作结果（§4 禁止行为）。抓取超时不能在压缩后变成成功。
2. 被裁剪区间必须有可解释的覆盖或缺口（§3 `C08`）。
3. 失败不能压成成功；旧纠正不能覆盖新纠正（§3 `C08`）。
4. 长期事实不自动当作当前网页证据（§3 `C09`）。
5. 与聊天摘要分离：长期条目独立于会话摘要（§3 `C09`）。
6. 同作用域保留更新关系（§3 `C09`）。
7. 已保存偏好可在获准作用域自动取用；自动取用不等于扩大授权（§3 M3）。
8. 会话摘要不复制完整网页证据；需要时按来源身份重新加载获准内容并检查时效（§7.4）。
9. 上下文与摘要覆盖只为 `M04`、`M05`、`M09` 提供事实，不能反向改写 `M06`／`M07` 的观察。

## 异常与恢复

- 覆盖不完整：系统已有覆盖不完整检测，但**发现缺口与补齐缺口是不同能力**（`Q08`）；存在缺口时如实标注，不静默丢失。
- 裁剪边界与摘要覆盖终点不同源：近期历史受 token 和消息对数限制，模型压缩主要按消息条数确定覆盖终点（`Q08`）；少量长消息可能先被裁剪但尚未进入摘要覆盖范围。
- 长期条目读写失败或作用域冲突：如实报告并保留既有条目，不自动改写。
- 本模块不承诺普通研究 Run 在进程重启后从任意中间点续跑（§7.4）。
- 「收紧联网次数会加速裁剪」是已撤回的推论，不得作为因果方向使用（讨论十二、附录）。

## 审计

- `C26` 记录结构见证：消息角色与数量、必要字段是否存在、修复消息是否纳入、所用协议，以及前后边界的关联标识（§8.4、`Q18`）。
- 原文仍留在受控会话或瞬时上下文中，不进入日志；摘要与覆盖说明可被诊断引用，但诊断不得据此改写真实动作结果。
- 诊断映射：上下文进入网关前后是否一致属关键边界证据，见 `Q09`、`G04`。

## 兼容

- 旧消息的来源投影保留 `SourceGroupFallback` 读取：只有字段缺失的旧消息可以按历史回退读取；显式空数组表示最终消息无来源，非空数组只允许投影当前 Run evidence（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
- 历史 Run 的摘要与覆盖事实按现有持久化读取，不因新增任务状态字段而改写旧记录。
- 旧 localStorage persona 属读取映射兼容，新笔记使用文件名与当前 SQLite profile（[ARCHITECTURE.md](../../ARCHITECTURE.md) Compatibility boundaries）。
- 记忆管理界面的布局不属于本次定义（§3 M3）。

### M03 正式定义

## 模块级合同要点

- **唯一主要责任**：拥有上下文的内容选择与覆盖说明，不改写真实工具状态，不代替权限决策。
- **状态权威**：上下文与摘要覆盖由本模块独占；其他模块不得改写摘要里的动作结果。
- **禁止行为**：摘要修改真实动作结果；把材料（网页、笔记、MCP 返回）当作系统指令。
- **任务状态是结构化工作信息**，不等同模型私有推理，也不进入日志正文。
- **依赖**：材料范围由 `K05` 授权；来源身份由 `K14` 提供。

## 组件边界

`C07` 装配本轮上下文并给出覆盖清单；`C08` 管摘要覆盖与工作状态；`C09` 管长期记忆条目，与聊天摘要物理分离。

### C07 当前上下文装配

## 输入与输出

- **输入**：当前指令、授权材料、观察、技能方法。
- **输出**：本轮上下文及覆盖清单。
- **逻辑合同名称**：设计层名称，不是已存在的 Rust 类型或 IPC 字段；所属模块 `M03`。

## 决定权与不变量

- **决定权**：明确哪些内容被采用、裁剪、过期；为稳定指令和最新纠正保留空间。
- **不变量**：材料是资料不是指令；工具结果与检索内容不得成为系统指令。
- **禁止行为**：越权改写其他模块的权威状态；把提议当作执行；把缺失当作成功。

## 状态

本组件持有的状态与其权威范围见上；持久状态只有 `M03` 的权威所有者可写，其余为进程内观察。

## 异常与恢复

材料不可读或超范围时从上下文中剔除并记录缺口，不静默省略。失败分类使用稳定错误码，可恢复的错误按 `K16` 反馈后继续。

## 审计

覆盖清单摘要与裁剪计数进入 `C26`；不记录材料正文。不记录密钥、笔记正文、完整模型请求或私有推理。

## 源码落点

现有基础与处置：run_context.rs、context_materials.rs、prompt_contract.rs；整理现有装配。context-assembly 的目标合同不要求按组件新建文件；映射到多个责任组件的现有大文件应在迁移时删除被替代的重复判断。

## 兼容

旧会话历史按未验证历史读取；提示词版本切换不保留双编译路径。读边界单向兼容，不双写、不保留第二套权威状态。

## 测试

关键不变量与所需证据类别见 `V01`–`V07`；本组件当前 `verification.state=none`，没有绑定指纹的证据记录。

### C09 长期记忆
