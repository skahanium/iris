# M4 模型网关

<!-- iris:object M04 kind=rules file=true -->

**唯一主要责任**：把实际供应商能力如实提供给上层；不因接口名相似丢弃必要续轮信息。主对话、摘要、语义验证和受控原生搜索请求都走这个边界，均向 `C13` 申领额度。

**状态权威与禁止行为**：本模块拥有「Provider 续轮状态与用量事实」逻辑对象。主要读取者是 `M03`、`M05`、`M09`。禁止行为：网关静默丢掉必要字段。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表第五行。

本模块由 `C10` 能力与路由、`C11` 协议与续轮适配、`C12` 调用执行与用量三个组件组成。模型是 `M4` 接入的外部能力，**不另算一个内部模块**（§1）。

## 输入与输出

**输入**：

- 模型配置、任务所需能力、已验证配置（`C10`）。
- 上下文、工具合同、续轮状态（`C11`）。
- 请求、额度租约、取消信号（`C12`）。
- 来自 `M03` 的装配结果、来自 `M06` 的工具合同、来自 `C13` 的额度租约。

**输出**：

- 可用路由及能力状态（`C10`）。
- 供应商请求与标准化事件（`C11`）。
- 响应／错误、实际用量与传输状态（`C12`）。
- 供 `M09` 关联的安全事件与出站结构见证。

## 决定权

- 决定能力状态如何表达：区分 unsupported、available、temporarily-failed、unknown；**不支持原生搜索不能淘汰正常文本／MCP 路由**（§3 `C10`）。
- 决定协议保真：Chat Completions／Responses／Messages 各自保真；文本、工具增量、服务端搜索、引用及必要续轮字段不被静默丢弃（§3 `C11`）。
- 决定调用结果分类：区分空输出、协议错误、服务错误和取消；重试与用量挂到同一调用身份，不隐藏额外模型请求（§3 `C12`）。
- 不决定是否继续行动（`M05`），不决定授权（`M02`），不决定工具面的内容（`M06`），不决定证据是否成立（`M07`／`M08`）。
- 原生搜索作为受控子请求接入：由 `C20` 管理、向 `C13` 申领额度；供应商是否能稳定实现该合同仍需逐个适配测试，架构定义**不宣布** MiniMax、DeepSeek 或 Gemini 任一端点已通过（§5）。

## 状态

| 状态项     | 内容                                                | 边界                               |
| ---------- | --------------------------------------------------- | ---------------------------------- |
| 能力状态   | unsupported／available／temporarily-failed／unknown | 只由 `C10` 表达                    |
| 续轮状态   | 协议所需的续轮字段、终止原因、工具增量              | 只由 `C11` 保留与序列化            |
| 调用与用量 | 调用身份、尝试、错误类别、实际用量、切换决定        | 只由 `C12` 报告，账本由 `C13` 拥有 |

网关**不声称**首轮文本成功即代表适配完成；完整适配还涉及工具调用、流式解析、续轮、取消、错误分类、能力边界和来源信息（讨论六）。

## 不变量

1. 网关不静默丢掉必要字段（§4 禁止行为）。
2. 语义分离：原生搜索、客户端工具调用、流式输出及续轮能力分别声明。没有原生搜索但支持客户端工具调用的模型可正常使用 `MCP`；连客户端工具调用也不支持时，不能冒充完整 agent 兼容，应明确其纯文本能力范围（§3 M4）。
3. 不会为了「无感」而将不支持的动作标记为成功（§3 M4）。
4. 不支持原生搜索是正常能力配置，不是运行故障；二者的诊断含义不同（讨论十）。
5. 重试与用量挂到同一调用身份；额度只有一个权威账本（`K06`，由 `C13` 拥有）。
6. 不能把供应商品牌或文本连通性等同于搜索支持（§5.1）。
7. 机械可证的违规与语义判断分开展示；出站结构见证只能证明结构及关联，不能单独证明语义材料完整或模型理解正确（§8.4）。

## 异常与恢复

- 空正文且无工具调用视为无效响应。在尚无可见正文、工具调用、continuation 或副作用时，瞬态／无效响应先重试同一 Provider 一次，再切换同工具能力候选；**已有动作后不跨 Provider 隐式续接**（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。
- 原生返回只有生成文字、没有可核实检索凭据时，记录协议／结果不足；在预算内允许有依据的恢复，不能伪造「原生已成功」，也不能悄悄归成「模型不支持」（§5）。
- 因一个工具服务失败就淘汰整个模型路由是不允许的（§3 M5）；超时、限流等暂时服务故障在取消信号、服务退避提示与预算约束下重试。
- 无法安全还原工具调用身份时，由 `C11`／`C14` 按协议错误恢复，不能拼造一个表面有效但关联错误的工具返回（§3 M5）。
- 「模型能力降级」不得用于概括工具调用错误；实际路由或能力变化必须有事实依据并独立记录（§3 M5）。自动切换模型不作为未知工具或普通参数错误的默认纠偏手段。

## 审计

- 出站请求是重要交接边界：记录安全的结构证据——消息角色与数量、必要字段是否存在、修复消息是否被纳入、所用协议，以及前后边界的关联标识，并与 Run、模型轮次、尝试、工具调用及父子任务建立联系（§8.4）。
- **只有哈希不足以解释字段缺失**；记录遵守最小化与脱敏约束，模型返回的错误字符串、未知工具名和 URL 也需脱敏（§8.4、`Q18`）。
- 尝试、错误类别和切换决定以有界脱敏对象追加到现有 route summary，**不保存请求、响应或凭证正文**（[ARCHITECTURE.md](../../ARCHITECTURE.md)）。

## 异常与恢复

取消后不再发起新请求；重试计入同一身份并如实计费。失败分类使用稳定错误码，可恢复的错误按 `K16` 反馈后继续。

## 审计

尝试、错误类别、用量与切换决定进入 `C26` 与 route summary。不记录密钥、笔记正文、完整模型请求或私有推理。

## 源码落点
