# 独立评测系统：E01–E03

<!-- iris:object FILE-EVAL-SYSTEM kind=rules file=true -->

独立评测系统在生产执行之外评价合同和真实质量，**不替 agent 在线作决定**，不是第十个运行时模块。它读取 `C26` 的安全事件及经专门授权的测试材料。

| 组件           | 输入 → 输出                                           | 当前基础与目标                                                                                           |
| -------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| E01 案例与判据 | 用户场景、失败案例、任务要求 → 固定输入与独立评分规则 | `contract.rs`、fixtures 与 `baseline_identity.rs`；案例/夹具哈希进入报告；补自然追问、编辑内容保持与负例 |
| E02 执行与重放 | 固定配置、测试输入、替身或真实服务 → 可比轨迹和用量   | `test_support.rs` 与脚本；确定性合同与付费真实调用分开；脏工作树不可比                                   |
| E03 评分与校准 | 输出、来源、预设判据与人工抽检 → 分项结果和已知盲点   | `verdict.rs`；空分母未覆盖；评分 schema 进入身份；机械、组合、语义评价分开，校准自动评分                 |

评测系统必须具备的能力：案例固定且可复现；替身与真实服务严格区分；机械、组合、语义三类评价分开报告；人工评分是事实／语义质量的唯一放行依据；故障注入用于检验机械归属（见 `V07`）。

**本轮不设新的发布分数，也未执行实网产品验收。**完整 lint／类型／代码测试与发布 CI 属于实际实现的验证，不是架构文档的结论。

### E01 案例与判据

## 输入与输出

- **输入**：用户场景、失败案例、任务要求。
- **输出**：固定输入与独立评分规则。
- **当前基础**：`agent_capacity_eval/contract.rs`、fixtures 与 `baseline_identity.rs`；案例集合与夹具哈希进入确定性报告。

## 决定的边界

案例必须固定且可重放；判据独立于被测实现；每个案例声明覆盖的需求与对象。评测系统不接管在线授权或最终答案，不是第十个运行时模块。

## 不变量

- 不能把有问题的请求结构写成正确期望（`Q11`）
- 某个维度没有要求时标为「未覆盖」，不得以零分母记为满分通过（`Q03`）
- 重建话术必须标注为重建案例，不能冒称原始请求重放
- 确定性报告必须带封闭 `baselineIdentity`：场景集合哈希与夹具哈希齐备；哈希或夹具对不上时整次运行无效，不得把个别案例记成失败
- 当前 `verification.state=none`：机械负例不等于语义或组合验收通过，不得据此宣称评测结论成立。

## 异常与恢复

案例无法重放时标记为不可用并说明原因，不按通过计入。夹具缺失、夹具哈希或场景集合哈希不匹配时，整次运行无效，不得把个别案例记成失败。

## 审计

案例身份、配置版本、场景集合哈希、夹具哈希与执行时间进入 `V08` 证据记录；评分判据变更保留原基线以便对照。提示只参与场景哈希，不得写入 JSON。

## 源码落点

`agent_capacity_eval/contract.rs`、`baseline_identity.rs` 及 fixtures；补自然追问、编辑内容保持与负例

## 兼容

旧冻结 fixture 标记为 `historical_frozen`，只作对照；旧 live 报告仅供诊断，不得进入 `product-gate.json`。

## 测试

评测组件自身也需要负例验证：故障注入必须真的触发目标故障，否则该案例判为无效（`V02`、`V07`）。

### E02 执行与重放

## 输入与输出

- **输入**：固定配置、测试输入、替身或真实服务。
- **输出**：可比轨迹和用量。
- **当前基础**：`agent_capacity_eval/test_support.rs` 与评测脚本；区分确定性合同和付费真实调用；测试注入固定身份，官方落盘才捕获 git。

## 决定的边界

确定性合同测试与付费真实调用分开报告与存储。执行身份记录 `sourceCommit`、`workingTree`、`os`／`arch` 与配置版本，不记录主机名、用户名或仓库绝对路径。评测系统不接管在线授权或最终答案，不是第十个运行时模块。

## 不变量

- 同一次执行不能同时作为确定性证据与真实质量证据
- 重放不得产生真实副作用；涉及写入的案例必须使用隔离环境
- 脏工作树可以写出报告，但 `comparable` 必须为 false，不得当作冻结基线或 product-gate 输入
- 当前 `verification.state=none`：机械负例不等于语义或组合验收通过，不得据此宣称评测结论成立。

## 异常与恢复

环境失败或身份字段不合法时标记为无效运行，不计入分子或分母，也不当作同期可比基线。

## 审计

执行身份（提交、工作树、os／arch）与配置进入 `V08`；原始事件仍由 `C26` 负责；评分判据变更保留原基线以便对照。

## 源码落点

agent_capacity_eval/test_support.rs 与评测脚本；区分确定性合同和付费真实调用

## 兼容

旧冻结 fixture 标记为 `historical_frozen`，只作对照；旧 live 报告仅供诊断，不得进入 `product-gate.json`。

## 测试

评测组件自身也需要负例验证：故障注入必须真的触发目标故障，否则该案例判为无效（`V02`、`V07`）。

### E03 评分与校准

## 输入与输出

- **输入**：输出、来源、预设判据与人工抽检。
- **输出**：分项结果和已知盲点。
- **当前基础**：`agent_capacity_eval/verdict.rs`；空分母质量维标为未覆盖且不得过门；评分 schema 进入 `baselineIdentity`；机械、组合、语义评价分开，校准自动评分。

## 决定的边界

机械、组合、语义三类评价分开报告；每个维度显示实际分母；自动评价标注校准状态与已知误判。评测系统不接管在线授权或最终答案，不是第十个运行时模块。

## 不变量

- 历史评分不得改写；口径变化保留原基线与版本标识；新确定性报告使用 `agent-eval-summary-v3`／`agent-capacity-report-v3`，冻结的 v1.2.15 报告仍为旧口径
- 不得通过提高「最终成功率」掩盖无限重试、费用失控或原始失败被隐藏
- 当前 `verification.state=none`：机械负例不等于语义或组合验收通过，不得据此宣称评测结论成立。

## 异常与恢复

评分输入缺失时报告缺口，不默认通过也不默认失败。

## 审计

评分版本、口径（含 `scoringSchema`）与校准记录进入 `V08`；评分判据变更保留原基线以便对照，不得回写历史 v1 JSON。

## 源码落点

agent_capacity_eval/verdict.rs；机械、组合、语义评价分开，校准自动评分

## 兼容

旧冻结 fixture 标记为 `historical_frozen`，只作对照；旧 live 报告仅供诊断，不得进入 `product-gate.json`。

## 测试

评测组件自身也需要负例验证：故障注入必须真的触发目标故障，否则该案例判为无效（`V02`、`V07`）。
