# M7 检索与证据

<!-- iris:object M07 kind=rules file=true -->

**唯一主要责任**：拥有资料获取及来源事实；不根据渠道名称裁定真伪。只有可追踪的实际观察才能进入证据链。

**状态权威与禁止行为**：本模块拥有「来源身份、阅读范围」逻辑对象。主要读取者是 `M03`、`M08`、`M09`。禁止行为：搜索片段自动升级为正文证据。对应登记为 [架构定义](../../docs/agent-architecture.md) §4 状态所有权表第八行。

本模块由 `C19` 本地检索、`C20` 双路网页搜索协调、`C21` 网页读取与提取、`C22` 证据与出处管理四个组件组成。检索中的双路协调先作为 `C20`，**不另建一套研究引擎**；协议适配归 `M4`，`MCP` 传输归 `M6`，搜索语义与结果组织归本模块（§2）。

## 输入与输出

**输入**：

- 查询、范围、授权（`C19`）。
- 模型提出的查询、外发批准、两路能力、额度（`C20`）。
- 任一路发现或直接提供的 URL、阅读窗口（`C21`）。
- 本地／网页／外部观察、引用请求（`C22`）。

**输出**：

- 命中片段与检索诊断（`C19`）。
- 两路状态与合并线索（`C20`）。
- 正文窗口、完整性、失败项（`C21`）。
- 来源身份、内容范围、证据关系（`C22`）。

## 决定权

- 决定内部检索策略与范围语义：FTS／向量／图等是内部策略；保持范围、版本与排名语义，不能悄悄扩大到全库（§3 `C19`）。
- 决定一条搜索动作的两路真实执行与合并表达（`C20`）。
- 决定正文窗口、完整性与失败项的表达（`C21`）。
- 决定来源身份、可信度、独立性和支持关系的分别表达（`C22`）。
- 不决定查询语义（由模型理解问题后提出），不裁定真伪（不根据渠道名称裁定），不决定授权（`M02`），不决定预算总额（`M05`），不决定最终结论（`M08`）。
- 外部网页、`MCP` 返回值及检索到的笔记是资料，不是新的用户指令（§3 M7）。

## 状态

| 状态项   | 内容                                                                     | 边界            |
| -------- | ------------------------------------------------------------------------ | --------------- |
| 本地命中 | 片段、范围、版本与检索诊断                                               | 只由 `C19` 产生 |
| 两路状态 | 各路线 supported／attempted／succeeded／failed、候选来源、用量与不足说明 | 只由 `C20` 合成 |
| 阅读范围 | 正文窗口、完整性、失败项                                                 | 只由 `C21`      |
| 证据身份 | 来源身份、内容范围、支持关系、独立性与可信度                             | 只由 `C22`      |

当前实现事实（[ARCHITECTURE.md](../../ARCHITECTURE.md)）：搜索每次最多返回 4 个有界候选、每 Run 最多保存 8 个；候选只标记为 `search_snippet`，不写 evidence ledger；只有 `web_fetch` 得到 `fetched_body` 的选中页面才登记为可引用 evidence；未选候选和失败抓取不能生成 `Wn`。这些是实现事实，不是本文件新设的门槛。

## 不变量

1. 只有可追踪的实际观察才能进入证据链；**搜索片段自动升级为正文证据属禁止行为**（§4）。
2. 每次获准的新搜索，两条可用路线都真实执行；原生不支持时正常单 MCP；**不能伪造另一侧结果**（§3 `C20`）。
3. 两路实际执行是功能合同，是否并发是执行策略；适配测试可以调整后者而不撤回前者（§5）。
4. 以供应商定义的实际搜索事件或能证明检索发生的结构化 grounding 元数据作为执行证据；**单纯发出带工具声明的请求、模型自行生成 URL，都不算已搜**（§5）。
5. 相同 URL 不算两个独立信源（§5）。
6. 有 URL 不等于事实成立；来源类型、可信度、独立性和支持关系分别表达（§3 `C22`）。
7. 检索到的笔记与外部网页同属资料，不是新指令。
8. 可批量抓取；URL 安全校验；部分失败保留成功；**搜索片段不冒充完整正文**（§3 `C21`）。
9. 有提取内容也不能自动宣称完整网页已读完；只有生成文本、没有可靠来源地址时，不能把其中任何看似 URL 的字符串自动当作已发现来源（讨论九）。
10. 结构化检索凭据用于证明供应商按其协议报告了检索，**不是不可伪造的真值证明**，也不证明返回内容正确或来源彼此独立（§5）。

## 异常与恢复

- 一条搜索路线失败：保留另一条真实结果，修复失败路线或按证据充足性继续；同一搜索动作恢复时不重复伪造新双路成功（§3 M5）。
- 原生返回只有生成文字、没有可核实检索凭据时，记录协议／结果不足；在预算内允许有依据的恢复，不能伪造「原生已成功」，也不能悄悄归成「模型不支持」（§5）。
- 搜索无结果、范围偏离或证据不足：如实保留结果，向模型反馈缺口，由模型修改关键词、时间或地区约束，或改查来源；**Host 不得用关键词规则替模型编造查询语义**（§3 M5）。
- 抓取失败、空正文或部分页面不可读：保留成功页面；对失败项按原因重试、使用获准提取回退，或让模型选择其他 URL／阅读窗口；不重新抓取全部成功页面（§3 M5）。
- 双路都失败或缺少足够证据时如实表达限制。预算不足以启动已承诺的两条路线时，说明本次限制，**不以单路结果冒充双路完成**（§5）。
- 查询修改形成新的搜索动作；同修订内成功的同一动作可以复用，复用必须指向真实观察与时间，不能算作新的联网执行（§5）。

## 审计

- `C20` 的逻辑结果包含请求身份、各路线状态、候选来源、用量与不足说明（§5）。
- 诊断映射：两路只执行了一路检查 `C10` → `C20` → `C12`／`C18`；抓取成功但没有正文检查 `C18` → `C21` → `C22`（§8.5）。
- 不记录笔记正文；模型返回的错误字符串、未知工具名和 URL 也需脱敏（§8.4）。
- 已有授权会话、候选与来源可通过受控引用在本地详情中按需核验，不复制进诊断日志；材料已删除或授权已撤回时如实说明不可核验（§8.4）。

### M07 正式定义

## 模块级合同要点

- **唯一主要责任**：拥有资料获取与来源事实；不按渠道名称裁定真伪。
- **状态权威**：来源身份与阅读范围由本模块独占；搜索片段不得自动升级为正文证据。

### C22 证据与出处管理

## 输入与输出

- **输入**：本地／网页／外部观察、引用请求。
- **输出**：来源身份、内容范围、证据关系。
- **逻辑合同名称**：设计层名称，不是已存在的 Rust 类型或 IPC 字段；所属模块 `M07`。

## 决定权与不变量

- **决定权**：来源类型、可信度、独立性和支持关系分别表达；有 URL 不等于事实成立。
- **不变量**：只有 `fetched_body` 的选中页面登记为可引用 evidence；未选候选与失败抓取不生成 `Wn`。
- **禁止行为**：越权改写其他模块的权威状态；把提议当作执行；把缺失当作成功。

## 状态

本组件持有的状态与其权威范围见上；持久状态只有 `M07` 的权威所有者可写，其余为进程内观察。

## 异常与恢复

证据缺失或已删除时如实说明不可核验，不用旧线索替代。失败分类使用稳定错误码，可恢复的错误按 `K16` 反馈后继续。

## 审计

证据身份、来源、时间与阅读范围进入账本与 `C26`。不记录密钥、笔记正文、完整模型请求或私有推理。

## 源码落点

现有基础与处置：agent_evidence_repository.rs、provenance.rs；补原生来源接入与质量表达。evidence-and-provenance 的目标合同不要求按组件新建文件；映射到多个责任组件的现有大文件应在迁移时删除被替代的重复判断。

## 兼容

旧消息的来源字段按历史读取规则处理（显式空数组表示无来源）。读边界单向兼容，不双写、不保留第二套权威状态。

## 测试

关键不变量与所需证据类别见 `V01`–`V07`；本组件当前 `verification.state=none`，没有绑定指纹的证据记录。
