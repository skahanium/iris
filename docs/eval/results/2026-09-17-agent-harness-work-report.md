## 四、发现的问题

### 4.1 `Q13`：一次被否证的施工（我的判断错误）

**现象**（实测）：同一 `schema_version` 下，把本地上限与网络上限各**收紧一档**的存档会被拒绝为 `Run(InvalidBudgetPolicy)`——**任何**数值差异都不可读。

**原因**：`RunBudgetPolicy::for_profile` 的规范值来自硬编码常量，且物化结果**直接用于执行**（`run_engine`、`normal_run_service`）。因此改任何默认值都会让既有存档不可读。

**我的第一次尝试（错误）**：在同 schema 内逐字段取 `min(存档, 规范)`。探针转绿，但打死了一条既有安全测试：

```
complete_but_noncanonical_budget_policies_fail_closed_for_read_and_retry
  → expanded_main_budget（maxModelTurns 1 → 1000）不再失败关闭，被 min 钳回 1 后读取成功
```

它**不会真的扩权**（钳制保证不超过规范值），但**取消了篡改检测本身**——因为历史默认值上调与篡改放宽在读取时不可区分。

**处理**：回退实现（`src-tauri` 零改动），**没有改写那条测试**。把 `R13` 从"已采用"改写为"待定并记录否证路径"，`Q13` 恢复 `open` 并重新阻断 `D02`。

**结论**：`Q13` 不能靠放宽同 schema 校验解决。R13 记录了两条候选（schema 版本门控，或暂不改默认值 + 将来显式恢复），**尚未形成决定**。倾向路径需要历史默认值常量表，该表目前不存在。

### 4.2 复核级联：一个结构性缺陷（已整改）

**现象**：对象被架构复核覆盖后，只要再被**任何**细化，指纹变化就让所有绑定它的复核判为过期并**阻断整个检查**。我这一轮因此被迫生产形式化复核记录。

**病根**：同一个内容哈希被迫承担三件互相冲突的事——检测"变了"（能）、记录"复核看到哪版"（能）、判断"要不要重新复核"（**不能**，哈希分不出错别字和语义改动）。把第三件压在哈希上，制度就会逼人补一条记录来解封，**这是把复核变成橡皮图章的最短路径**。

**我的越权操作**：我发明了 `rebind`（把旧复核的指纹改到当前版本）并用了三次——而 `rebind` 在 `rules/` 里**根本没有定义**，机制上与篡改绑定不可区分。

- `rules/governance.md` §5.2 新增第 6、7 条：绑定**保留写入当时指纹**并标 `stale`；检查器报告为**缺口**（`gaps`），**不阻断检查**，也**不**改写旧记录来解封；解封必须新增一条**针对当前指纹**的复核；陈旧**只影响被改动的那个对象**。
