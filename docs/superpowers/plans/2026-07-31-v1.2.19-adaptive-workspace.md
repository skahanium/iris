# v1.2.19 自适应工作区实施计划

> **执行要求：** 严格测试先行；每个任务先写失败测试并确认失败，再实现最小行为。不得在本计划之外扩展 Agent 权限、Markdown schema 或文件格式。

**目标：** 在保护 Markdown 正文宽度的前提下，交付可连续浏览的轻量文件导航和可展开到主工作区的 Agent 阅读状态。

**架构：** 使用一个纯布局策略模块把用户意图与有效 presentation 分离；AppShell 保持单一编辑器与单一 Agent 子树稳定挂载。文件导航分为 `peek/pinned` placement，业务层复用现有 vault catalog、文件动作和持久化屏障，完整库管理继续留在管理中心。

**技术栈：** React 19、TypeScript、TailwindCSS、shadcn/ui、Tauri 2、Vitest。无新增依赖、IPC 或数据库迁移。

## 全局约束

- 文档保护宽度读取 `--prose-measure` 的计算值；禁止在多处硬编码 832px。
- 不提高 `tests/app-shell-refactor-contract.test.ts` 的 1100 行 checkpoint；新增协调逻辑放入 hook/lib/layout 组件。
- `UnifiedAssistantPanel` 与 TipTap editor surface 在 presentation 切换中不得 remount。
- 文件动作不得复制现有 IPC 流程；先抽取共享 catalog/action controller，再让管理中心与轻量导航共同消费。
- `Ctrl/Cmd+Shift+E` 继续打开完整库管理；新增 `Ctrl/Cmd+\\` 只切换轻量导航。
- 所有用户可见文案使用中文；所有 icon-only 控件必须有 tooltip 与可访问名称。
- 不修改 `ARCHITECTURE.md`，直到实现与验证全部完成；随后只记录已存在结构。

- 自动化门禁全部通过，或外部不可用项有明确、可复现且不涉及产品代码的记录。
