## 1. 目标、依据与边界

修复四组共同根因：读取与上下文投影改变执行事实；回答正文被用来判断终态身份；检索层的排序与过滤语义不一致；联网工具连通性被当作回答质量。保留唯一 `AgentToolLoop`、冻结权限和预算、现有 Broker、Run-local evidence ledger、Provider 中立与确认后写入边界。

2026-09-14 的审查证据分为两类：

- 生产记录：09:41 搜索成功、抓取超时，随后未知工具提议耗尽恢复；09:52 一次抓取失败、一次成功，仅一个聚合页成为证据，模型提前结束并复述内部预算。没有“只允许一个来源”的限制，也没有证据证明话题触发特殊封锁。
- 代码复现：网页先截断再分页；压缩把失败改成成功并可能删除最新观察；BM25 反向；中文 OR 失去分组；路径 LIKE 通配符导致漏召回；转义载荷收缩后仍损坏 JSON。终态正文前缀误分类由生产分支确认。A 的反例已纳入仓库回归，生产入口与验收边界见 [Harness 附录 A](../../../agent-harness/appendices/A-status-and-test-traceability.md)；其余组继续先补反例再实现。

本轮不添加依赖、数据库表、长期记忆、研究子循环、领域路由、模型名分支或固定来源域名表。工具正文保留现有有界原则；不靠调大上下文、页长和重试次数掩盖问题。每个实施单元必须删除被替代路径，不能以新封装包住仍会执行的旧逻辑。

## 2. 四个实施单元

### A. 读取、投影与压缩共用真实执行结果

**落点**：现有 executor/Broker 与 `agent_tool_loop` 下的 `payload_fit`、`prompt_budget`；读取协议由工具适配层负责，通用循环只负责预算和投影。允许按职责提取私有模块，不建立通用插件式压缩框架。

确定数据流为：`受控抓取 → Run 内正文快照 → 选取阅读窗口 → 按实际 JSON 体积收缩 → 登记同一可见摘录 → 模型观察`。登记、引用和进展都消费最终窗口，不能先登记首段再让模型看到另一段。

1. 保留 `web_fetch { urls, startChar? }` 输入；网页偏移按 Rust Unicode scalar 字符计数，本地 `read_note` 继续使用 UTF-8 字节，分别命名，不强行统一单位。多 URL 的窗口、实际返回长度和 `nextStartChar` 放在各自结果项；单页兼容顶层 `excerptWindow`，多页不得用一个指针代表整批。
2. executor 在本 Run 内保存通过安全检查的有界正文快照，覆盖 MCP 与 native 两种抓取路径。规范 URL、正文 hash 和抓取来源绑定为快照身份；沿用当前最多 12,000 字的 Broker 正文边界、Run 证据容量和网络预算。快照只在内存存活，不新增持久化缓存或第二份证据账本；原 native 缓存仍由原模块管理。
3. `startChar > 0` 只续读同 Run 已有快照；缺快照返回可行动的失效结果，不能偷偷重新抓取后按旧偏移拼接。首读也复用本 Run 快照。到尾返回明确 EOF，越界返回范围错误；两者不登记空证据、不算新进展。
4. 下一页指针按最终实际送入 JSON 的正文长度计算，不能固定加 2,000。区分“快照还有后文”和“上游截断/完整性未知”；读取完 12,000 字快照不能宣称完整网页已读完。Broker 需要携带内部完整性标记；上游不提供完整性时记为未知。
5. 每个实际可见的不同摘录复用现有 ledger 登记，保留现有摘录大小与容量限制；相同摘录重放不增加证据。引用按登记返回的 evidence ID 绑定，删除同 URL 查找第一条引用的做法。来源独立性按规范 URL/域名去重，多页不得虚增独立来源数。
6. 进展使用组合身份 `(resource, revision/hash, start, actualEnd, unit)`；逐页前进是进展，同一页重放不是进展。移除用递归收集零散偏移数字代替阅读身份的路径，保留非阅读工具已有的安全资源身份逻辑。

载荷适配分为两层：工具适配层生成可恢复的有界内容；通用层检查最终 JSON 信封。用实际序列化长度迭代收缩正文，包含转义开销；列表项采用确定性截减并如实记录省略，不能从任意字符串字段猜测分页语义。删除所有序列化后直接切字符串的回退。最小合法信封仍超限时返回内部投影预算错误，由现有预算收束路径处理；不得改写实际工具成功/失败，也不得发送损坏 JSON。

压缩仅改变模型消息投影：

- 保留原始 `success`、稳定错误码、资源身份、观察深度、实际范围、可恢复指针和写操作回执。删除固定 `success: true` 标记。
- 保护最近一批完整 assistant/tool 交互、用户最新纠正和必要约束，先压缩更早的正文。不能压缩到所有观察消失后仍宣称上下文可用。
- 将现有成功 fingerprint 集合收敛为有界执行记录，关联该调用的已生成有界观察与其是否被压缩；不另建状态管理器。被压缩的只读观察允许通过相同工具参数重放既有结果，明确标为旧观察，不声称重新读取最新资源。写入仅重放既有回执，永不重新执行副作用。
- 重放仍计一次逻辑调用及原类别预算；Provider 尝试数为零，不重复登记证据，也不产生新进展。存储上限由现有 Run 调用数量和各工具有界载荷上限导出。达到最小投影仍超限，走已有可见终态路径，不再抹掉最近观察。

**必须删除**：首段打包后分页、重复正文切片、裸字符串 JSON 截断、固定成功压缩标记，以及压缩后只剩不可恢复 fingerprint 的独立逻辑。

### B. 终态类型与用户输出边界

**落点**：`AgentToolLoopOutcome`、Run engine 的校验/来源/提交，以及现有 PromptContract 和模型消息投影。

为内部 outcome 增加明确的终态类型：模型回答与 Host 证据受限终态，后者携带已有安全原因码。Provider `finish_reason` 继续表达 Provider 停止原因，不能兼任 Host 身份。正常回答、修复、强制综合和 Host 兜底的构造点全部显式赋值；验证、引用和提交消费同一类型。

删除当前 Run 全部基于正文前缀的 Host 识别。若旧记录读取确实依赖前缀，只允许留在隔离的旧记录适配器；不得从新回答内容或旧前缀授予跳过验证的资格。新 Run 用既有终态诊断及显式 `evidence_refs_json` 持久化结果，计划不需要数据库迁移或 Tauri IPC 改动。

把循环状态分成两个投影，而不复制两份预算：Host 继续保存精确计数、超时阶段和 Provider 尝试；模型只取得当前能否继续、是否必须综合、失败类型及可采取的下一步。移除模型观察里反复出现的精确剩余额度、毫秒、`webUsage` 等内部计量。预算耗尽仍由既有 Host 调度决定。

用户正文围绕问题组织事件、结论和必要的不确定性；候选摘要、已读摘录、来源绑定与独立印证必须语义区分。更新现有一处回答风格合同，覆盖 Host 自写限制文案；不另加按“可用范围说明”等字符串删除整段答案的后处理器。正常运行中不显示工具名、轮次和预算；用户主动询问运行诊断时可由相应诊断入口说明真实执行状态。

**必须删除**：新 Run 的前缀豁免分支、模型可见的重复预算清单，以及“已读聚合页 = 已核实每条报道”的示例或断言。

### C. 检索语义在现有 FTS 链路内收敛

**落点**：`retrieval_broker::fts` 的查询编译、范围 SQL 和分数转换；沿用现有 RRF/MMR。

- BM25 转换采用 `strength = max(-rank, 0)`、`score = strength / (1 + strength)`，保证更负的 rank 对应更高分数；分数只是层内相关性，不是概率。验证经过现有融合后的排序，不能仅检查公式。保留既有融合权重和来源去重，避免顺手重写排序算法。
- 每个 CJK 扩展词组用括号包住 OR，各用户词组用显式 `AND` 连接；原样词匹配与双字词短语并存。保留现有输入清理和索引兼容，不新增查询 DSL，也不要求重建索引。
- 路径前缀 SQL 与 `RetrievalScope::matches_path` 的字面前缀语义一致。采用参数化、二进制字符串前缀比较（`substr(path, 1, length(?)) = ? COLLATE BINARY`），精确路径仍用参数化 IN；消除 LIKE 通配符及大小写折叠歧义，不改变全连接的 SQLite PRAGMA。复用同一个谓词供 FTS/metadata 使用，保留最终授权过滤，并验证查询成本。

**必须删除**：反向分数断言、未分组 OR 拼接和未转义 LIKE 路径谓词。不要增加“结果不足则全库重搜”的补救分支。

### D. 同一循环内改善联网起步、失败恢复与回答质量

这组涉及行为调整，不能只宣称“属于设计取舍”而免于验证，也不能用固定抓取三家网站代替问题理解。

1. 对需要检索的自然问句，让既有首个模型回合先消费历史和最新纠正，选择合法查询与工具。保留最低实际观察义务：模型未取得观察就尝试提前回答时，在现有终局校验点调用同一 Host bootstrap，并回到同一模型循环；这份草稿不发布。显式 URL 仍可直接起步读取。所有分支继续使用冻结总预算与最终综合预留，不新增规划模型调用或 planner。
2. Host 保底最多一次，只用允许外发的用户公开子句和可信日期，不能把笔记、系统提示或整段历史拼到 Web query。模型产生的搜索参数继续经过同一外发边界。工具已实际失败与“完全未尝试”分开，不能因失败反复触发 bootstrap。
3. 观察提供页面阅读深度、时间元数据及其是否未知、失败 URL、剩余快照范围和来源身份。宽泛新闻任务由模型按事件、时间和重要性选取材料，聚合页标题作为后续线索；必要时搜索对应原报道，不把“读取一页”判为任务完成。来源数量由证据需求决定，不给所有问题硬设最小域名数。
4. 保留 5/18/20 秒默认上限，先把 native/MCP 子请求截止时间统一为当前剩余 deadline 与候选上限的较小值，取消必须贯穿到底层请求。部分成功保留成功结果与逐项错误；整批超时不能清空已经取得的材料。组合回归还须覆盖“同批已有 Run 快照 + 新 URL 抓取全部失败”：当前 executor 的整批失败早退仍可能先于快照投影，不能用成功续读测试替代此边界。不在本轮凭感觉增加超时或重试次数。
5. 非法工具提议继续在派发前拒绝；恢复反馈从当前冻结 catalog/schema 生成，包含对应纠错点。检查真实 Provider 续轮的 catalog、调用 ID、参数和 continuation 是否一致，避免核心按 MiniMax 名称分支。诊断保留阶段、稳定拒绝原因、catalog 指纹和未知名称 hash；未知自由文本不进入普通日志，不能为了排查把任意名称或参数持久化。
6. 降级诊断按失败 capability、当前逻辑调用、Provider 尝试与预算取消分别计数；不能用累计三次尝试暗示三次抓取，也不能把 fetch 故障描述成 search 失败。沿用现有事件载荷与诊断对象；若实现发现必须改变公共 IPC，单独同步类型、封装和契约测试后才接线，不创建平行事件体系。

**必须删除**：自然问句在模型理解前无条件先搜并抓前两个结果的分支，及搜索成功掩盖抓取失败的重复诊断推断。替代分支须随生产入口测试同批落地；不得先移除最低观察保证。

## 3. 回归与质量验收

每个缺陷先写能经过真实生产入口的失败测试，记录基线失败，再实现并确认通过。函数单测保留用于边界定位，不能代替 executor → 模型观察 → 终态/ledger 的组合断言。无需新增测试框架或付费评判模型。

| 组  | 必须覆盖的场景                                                                                              | 可判定的验收结果                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| A1  | 5,000 字网页、答案仅在末段；中文/emoji；两页长度不同；多 URL 部分失败；上游截断                             | 指针精确且不跳字，末段可进入模型；不重抓；登记内容等于可见内容；快照读完不冒充网页完整      |
| A2  | 两个 URL、同 URL 多页、同页重放、Run 结束后续读                                                             | 引用按 evidence ID 正确对应；多页不算多个独立来源；无跨 Run 缓存身份穿透                    |
| A3  | 引号/反斜杠/控制字符/嵌套数组；预算小于元数据                                                               | 每个送入模型的结果都能 JSON 解析且满足实际大小；不可容纳时明确收束；offset 对应实际保留正文 |

| B   | 模型回答以每个旧 Host 前缀开头；真正 Host 兜底；流式/重载                                                   | 模型回答仍受校验，真正兜底只发布一次；正文/证据/诊断一致，无来源重新挂回                    |
| C   | 相关程度不同的同语料文档；劳动合同 + 赔偿；中英混合、引号、单字；`_`、`%`、大小写路径，范围外候选挤满 LIMIT | 融合后最相关结果优先；各查询条件成立；SQL 与字面范围过滤一致，无范围外候选挤掉目标          |

| D2  | 一个聚合页可读，原报道需再次搜索；一个候选超时；近期/旧闻/未来日期混杂                                      | 组合轨迹能调整查询、获取对应报道和正确引用；不把标题当正文印证，不输出内部预算              |

真实质量在现有 HR-7/HR-8 门内验收，不另建“修复专用通过”报告。使用原有双路由、同一预算上限和四维人工评分：意图、事实与来源、相关性与完整性、纠正与连续性；沿用单项至少 4/5、平均至少 4.2 的标准。

本轮真实案例至少包含截图原问法与宽泛重试、一个有明确单一答案的对照问题、一个历史依赖追问、一个部分抓取失败后的换源。多来源案例必须预先冻结可支持不同事件的材料，并检查实际引用；单一答案案例允许一份足够来源，防止为了过门禁机械凑数量。实网新闻没有固定答案字符串 oracle，由审阅者核对当次时间、原文与覆盖范围。

真实 Campaign 是有成本的独立运行，沿用已有预检和成本确认机制；本方案不自动消耗额度。尚未运行或未达标时 HR-7 保持实测未通过。确定性修复不得通过改小题目范围、删失败用例或更新期望文本来消除真实失败。
